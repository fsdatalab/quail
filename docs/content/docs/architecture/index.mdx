title: Overview
---

Quail is structured like a traditional query engine: it parses a
query into a logical plan, optimizes it, lowers it to a physical
plan, and executes the physical graph in dependency order. On one
GPU, compatible operators can run together in a pipeline. The executor
packs their ready documents into forward passes using token and KV
page budgets. The two performance goals
are to keep the GPU busy (minimize idle time between forward passes)
and to minimize KV regret (document state that was evicted from GPU
memory and needs to be recomputed).

## Query lifecycle

1. Quail [parses](https://github.com/fsdatalab/quail/blob/main/quail/frontend/sql.py)
   the user's SQL (or [Python builder](https://github.com/fsdatalab/quail/blob/main/quail/frontend/builder.py)
   query) into a logical plan.
2. The session reads Arrow batches from each registered table and
   tokenizes the document columns.
3. The [planner](https://github.com/fsdatalab/quail/blob/main/quail/planner/decide.py)
   proposes one or more physical plans with cost estimates. The
   cheapest one is selected.
4. The [runner](https://github.com/fsdatalab/quail/blob/main/quail/execution/runner.py)
   executes the physical graph. Model nodes run on the GPU.
   Relational nodes run with Arrow on the CPU.
5. The query returns the matching rows as a `pyarrow.Table` and an
   execution report with timing and token counts.

## Packages

The packages separate query representation, planning, and execution.

| Package | What it does | Source |
| --- | --- | --- |
| `quail.frontend` | SQL compiler and Python builder. | [frontend/](https://github.com/fsdatalab/quail/tree/main/quail/frontend) |
| `quail.logical` | Logical plan nodes and prompt binding. | [logical/](https://github.com/fsdatalab/quail/tree/main/quail/logical) |
| `quail.physical` | Physical plan nodes. | [physical/](https://github.com/fsdatalab/quail/tree/main/quail/physical) |
| `quail.planner` | Logical rules, operator ordering, classification rule selection, and KV retention. | [planner/](https://github.com/fsdatalab/quail/tree/main/quail/planner) |
| `quail.cost` | Work and time estimates from model and device specs, including classification replay. | [cost/](https://github.com/fsdatalab/quail/tree/main/quail/cost) |
| `quail.execution` | Session, runner, token store, results. | [execution/](https://github.com/fsdatalab/quail/tree/main/quail/execution) |
| `quail.backends` | Quail's GPU code (`backends/quail/executor/`) and the vLLM and SGLang baselines. | [backends/](https://github.com/fsdatalab/quail/tree/main/quail/backends) |
| `quail.specs` | Model and device constants. | [specs/](https://github.com/fsdatalab/quail/tree/main/quail/specs) |
