---
title: Logical plans
---

A logical plan describes what a query does. Both front ends (SQL and
the Python builder) produce one through `LogicalPlanBuilder`, so
they always generate the same plan for the same query.

## Node types

| Node | What it represents |
| --- | --- |
| `Scan(provider, alias, column)` | Read one document column from a registered table. |
| `SemanticFilter(input, predicates)` | One or more AI predicates over one table. |
| `SemanticJoin(inputs, predicate, semantics, selectivity, anchor)` | An AI join across two or more tables. `semantics` is `full`, `exists`, or `anti`. |
| `Project(input, columns, limit)` | Column projection and optional limit. Always the root. |

Filters sit directly above their scans. A filter always runs before
any join that uses its table.

## The node protocol

All logical nodes implement this protocol:

```python
class LogicalNode(Protocol):
    type_name: ClassVar[str]

    def children(self) -> tuple[LogicalNode, ...]: ...
    def expressions(self) -> tuple[Any, ...]: ...
    def output_schema(self) -> tuple[ColumnRef, ...]: ...
    def validate(self) -> None: ...
    def with_children(self, children) -> LogicalNode: ...
    def with_expressions(self, expressions) -> LogicalNode: ...
    def explain_fields(self) -> dict[str, Any]: ...
```

Nodes are frozen dataclasses. Rewrites produce new nodes through
`with_children` and `with_expressions`. `LogicalPlan.walk()` visits
children before parents.

## Prompt binding

A `Prompt` is a bound `PROMPT(...)` call split into three parts:

- **preamble**: fixed text before the document (`DOCUMENT:` and a
  newline).
- **frame**: for joins, the anchor label and question written once
  into the anchor's KV.
- **tail**: the question and the answer cue.

`bind_prompt` handles filters. `bind_join_prompt` handles joins.
Both move any user text written before the first placeholder to
after it, so the document tokens are the same regardless of the
question. This is the property that makes KV rewind possible.

When a tokenizer is provided, token counts and ids are stored on the
prompt so the planner and executor do not re-tokenize.

## Logical rules

```python
class LogicalOptimizerRule(Protocol):
    name: str
    def rewrite(self, node, context) -> LogicalNode | None: ...
```

`apply_logical_rules` walks the plan bottom-up and offers every
node to every registered rule. A rule returns a replacement node or
`None` to leave it unchanged. Quail has no built-in logical rules
today. The mechanism exists for extensions.
