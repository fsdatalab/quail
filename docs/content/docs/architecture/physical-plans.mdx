---
title: Physical plans
---

A physical plan is a directed acyclic graph of typed nodes. The
planner produces it from the logical plan, and the runner executes
it.

## Nodes and ports

Each node has typed input and output ports. An `InputPort` reads from
one `OutputPort` of another node. Value types include
`DOCUMENT_IDS`, `FILTER_ANSWERS`, `JOIN_ANSWERS`, and `ROWS`. The
graph validates that connected ports have matching types.

```python
@dataclass(frozen=True)
class PhysicalNode:
    node_id: str
    inputs: tuple[InputPort, ...] = ()

    type_name: ClassVar[str]
    runtime_key: ClassVar[str]
    location: ClassVar[ExecutionLocation]
```

## Node types

**Generic nodes** (used by all backends):

| Node | What it does |
| --- | --- |
| `Scan` | Names one tokenized input by alias. |
| `Barrier` | Materializes survivor ids when the anchor changes between join steps. |
| `Exchange` | With multiple GPUs, routes documents to the GPU holding their KV. |
| `Recombine` | Joins TRUE answer tables on shared alias columns using Arrow. |
| `Project` | Reads the selected columns for surviving rows. |
| `Limit` | Truncates the result. |

**Quail backend nodes**:

| Node | What it does |
| --- | --- |
| `AiFilter` | Runs one table's filter stages on the GPU. |
| `AiJoin` | Runs one join group with a fixed anchor on the GPU. |

**Request backend node** (vLLM, SGLang):

| Node | What it does |
| --- | --- |
| `RequestExecution` | Holds the tokenized prompts for submission to the inference server. |

## Node ids

Node ids are readable names:

| Node | Id pattern | Example |
| --- | --- | --- |
| `Scan` | `scan:<alias>` | `scan:r` |
| `AiFilter` | `ai_filter:<alias>` | `ai_filter:r` |
| `AiJoin` | `ai_join:<anchor>` | `ai_join:r` |
| `Barrier` | `barrier:<next_anchor>` | `barrier:e` |
| `Foreign` | `apply:<name>` | `apply:same_page` |
| `Project` | `project` | |

## Editing a plan

You can edit the physical plan before running it:

```python
plan = query.plan()
plan2 = plan.insert(node, between=("ai_filter:c", "ai_join:e"))
plan3 = plan2.remove("apply:same_page")
result = query.run(plan=plan3)
```

- **`insert(node, between=(producer, consumer))`**: put a node on
  one edge.
- **`remove(node_id)`**: take a node out and rewire. Only `Foreign`,
  `Barrier`, and `Exchange` nodes can be removed.
- **`move(node_id, between=...)`**: remove then insert.

Every edit returns a new plan. An illegal edit raises
`PlanEditError`. After each edit, Quail re-validates the graph and
re-estimates every node.

## Execution

`GenericRunner.run(graph, context)` walks nodes in topological
order. For each node it calls the registered runtime, checks that
the output ports match, records node metrics, and notifies
observers.

Model nodes run on the GPU. Relational nodes (`Recombine`,
`Project`, `Limit`) run with Arrow on the CPU.

## Serialization

Each node type has a `NodeCodec` that encodes and decodes it for the
process boundary. `plan_envelope` wraps the encoded graph with the
backend, model, device, and worker count. The worker refuses the
plan if any registered type is missing.
