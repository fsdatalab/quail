---
title: In-process execution
---

`Query.run()` executes the query in the calling process. The same
code path runs on a local GPU or inside a Modal GPU function.

## What happens during run()

1. The session tokenizes document columns in the background if they
   have not been tokenized yet.
2. The planner produces a physical plan.
3. The backend loads the model on first use and warms GPU kernels.
4. The runner executes the physical graph. Model nodes run on the
   GPU. Relational nodes run with Arrow on the CPU.
5. The query returns a `QueryResult` with the output rows and
   execution report.

## Session lifetime

The backend keeps the loaded model in memory for later queries.
The session keeps tokenized documents for reuse. Collect your
results before closing the session, because the row projection may
still read from the session's temporary files.

`Session.close()` waits for background tokenization and releases
temporary files. It does not unload the model.

## Limits

- Temporary token files must fit on local disk.
- At most 8 GPUs in one host. Multi-host execution is not
  implemented.
