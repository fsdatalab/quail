title: Benchmarks
---

Use [QUAIL-B](https://github.com/fsdatalab/quail-bench) to measure a change
against fixed queries and saved reference answers. Complete
[development setup](/docs/contributing) before running the commands below.

## Run a query

Choose a query that exercises the change. Record the expected effect
before running it. A scale factor sets the input size relative to the
full benchmark tables.

### On a local GPU

E.g., run `IMDB-4` with Qwen3 4B fp8 on one H100 SXM:

```bash
uv run python -m bench.quailb --sf 0.1 --only IMDB-4 \
  --model qwen3-4b-fp8 --device h100-sxm \
  --output-dir results/quailb/imdb-4
```

Use a new output directory for each run.

### On Modal

Configure Modal with `uv run modal setup` before the first run.
E.g., run the same query without baselines and save the log:

```bash
mkdir -p results/benchmark
run_log="results/benchmark/quailb-$(date -u +%Y%m%dT%H%M%SZ).log"
uv run modal run --detach -m bench.quailb_parallel \
  --scale-factor 0.1 --model qwen3-4b-fp8 --query IMDB-4 \
  --no-include-baselines \
  --output-dir /results/benchmarks/quailb \
  2>&1 | tee "$run_log"
```

The log prints the function call ID and run directory. Results are on
the `quail-results` volume under `benchmarks/quailb/<run-id>/`.

E.g., download the files, replacing `<run-id>` with the ID from the log:

```bash
uv run modal volume get quail-results \
  "benchmarks/quailb/<run-id>/" "./results/<run-id>/"
```

The downloaded Quail results are in `results/<run-id>/quail/`.

## Read the results

Read `report.md` for measurements and agreement with reference answers.
`run.json` holds the run metadata and per-query measurements.

E.g., regenerate the local report without running the model:

```bash
uv run quail-b report results/quailb/imdb-4
```

## Compare a change

Record the Quail commit for each run. Keep the query definition and
input tables fixed. Use the same model configuration and reference answers.

| Measurement | Meaning |
| --- | --- |
| Query time | Seconds from submission to answer, including planning and answer preparation but excluding model startup. |
| Input tokens per second | Full prompt tokens divided by query time. Count shared prefixes each time they occur. |
| GPU cost per query | Query time in hours × GPU count × hourly GPU price. |

Include document and pair counts. Identify the reference model when
reporting agreement with its answers. Report startup separately.
Compare measurements with your prediction and report changes in answers.
Link to saved results in the pull request; do not commit generated files.

## Add a benchmark query

Query definitions and reference answers belong in
[quail-bench](https://github.com/fsdatalab/quail-bench). Quail's
[`bench/`](https://github.com/fsdatalab/quail/tree/main/bench) runner reads
the query definitions as [Substrait](https://substrait.io/) plans.

Change the query in quail-bench first. Then update the `quail-b` commit
in `pyproject.toml` and update `uv.lock`.
Check that Quail's runner can load and run the revised query.
