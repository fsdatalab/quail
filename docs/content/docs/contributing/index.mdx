Here we explain how to report a bug or submit a change to Quail.

## Report a bug

If you find a bug, please
[open an issue](https://github.com/fsdatalab/quail/issues).
Include:

- A minimal example that reproduces the bug.
- The expected behavior and what happened.
- The Quail version or commit. For an inference error, include the model,
  device, and backend configuration.

## Prepare the repository

Quail requires Python 3.12. Clone the repository and install the development
dependencies:

```bash
git clone https://github.com/fsdatalab/quail.git
cd quail
uv sync --frozen
```

The development dependencies include
[quail-b](https://github.com/fsdatalab/quail-bench).
You need access to that repository to install them.

## Make a change

For a new feature or a substantial change, open an issue to discuss the
approach before implementation.
Include the tests and documentation needed to check and use your change.

| Path | Contents |
| --- | --- |
| `quail/frontend/` | SQL parsing and the Python query API. |
| `quail/logical/`, `quail/physical/` | Logical and physical plan definitions. |
| `quail/planner/`, `quail/cost/`, `quail/specs/` | Planning rules, cost estimates, and model and device specifications. |
| `quail/execution/`, `quail/backends/` | Query execution and inference engines. |
| `tests/`, `experiments/` | CPU tests and Modal GPU scripts. |
| `docs/`, `demos/` | Documentation and examples. |

See [Architecture](/docs/architecture) for the query execution flow.
See [Extending Quail](/docs/extending) for the extension interfaces.

## Check the change

### Code checks

Run these commands from the repository root:

```bash
uv run ruff check quail tests experiments tools
uv run python tools/check_long_strings.py
uv run vulture
uv run pytest -q
```

All four checks must pass before pushing. These checks do not require a GPU.

For changes to model execution, run the relevant GPU tests.
The script
[`experiments/run_gpu_tests.py`](https://github.com/fsdatalab/quail/blob/main/experiments/run_gpu_tests.py)
runs these tests on Modal.
For performance changes, use the [benchmark guide](/docs/contributing/benchmark).

### Documentation checks

Install the documentation dependencies and start the site:

```bash
pnpm --dir docs install --frozen-lockfile
pnpm --dir docs dev
```

Open [the local site](http://localhost:3000/quail).
Check the changed pages, then run:

```bash
pnpm --dir docs types:check
pnpm --dir docs build
```

## Submit a pull request

Describe the problem, what your change does, and why.
List the checks you ran and their results.
For a performance change, include the configurations, measurements, and
saved result paths. State any remaining limitations.
