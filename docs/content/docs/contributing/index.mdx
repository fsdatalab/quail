## Report a bug

[Open an issue](https://github.com/fsdatalab/quail/issues) and include:

- a minimal example reproducing the bug;
- the behavior you expected and the behavior you saw;
- the Quail version or commit, and the `EngineConfig` for an error in
  an AI call.

## Build Quail

Install [uv](https://docs.astral.sh/uv/). Quail uses Python 3.12.

```bash
git clone https://github.com/fsdatalab/quail.git
cd quail
tools/build.sh
```

`tools/build.sh` installs the Python package from your checkout and the
Rust module `_quail_native`. The script downloads a prebuilt module when
CI has built one for your checkout's Rust sources, so you need no Rust
compiler to work on the Python code. Run your tools with
`uv run --no-sync` after a prebuilt install.

Edit Rust, and you compile the module yourself. Install
[rustup](https://rustup.rs), and clang and lld on Linux x86_64, then
run `tools/build.sh --compile`. The first build compiles DataFusion and
takes about 20 minutes on 4 cores; later builds reuse the compiled
dependencies. Run `tools/build.sh --compile` again after each Rust edit.

## How Quail plans a query

Quail plans a query in two parts. DataFusion plans the SQL, and Quail's
rules decide what each AI call asks the model. Quail then plans each
*model region*: a group of AI calls running together on the GPU.

<Mermaid chart={`flowchart TD
    sql["SQL"]
    bind["DataFusion parses and binds the SQL"]
    lower["lower_ai_calls: each AI call becomes an AiNode"]
    merge["merge_repeated_ai_calls: a call written twice becomes one AiNode"]
    derive["derive: each AiNode gets its filter, fetch, guard, and returned columns"]
    place["place_ai_nodes: each AiNode moves next to the table it reads"]
    claim["claim_model_regions: adjacent AiNodes become one model region"]
    plan["quail-planner: orders the region's operators by cost"]
    run["Executor: runs the region on GPU workers"]
    rest["DataFusion: runs scans, joins, sorts, and limits"]
    sql --> bind --> lower --> merge --> derive --> place --> claim
    claim --> plan --> run
    claim --> rest
`} />

| Step | Code |
| --- | --- |
| `lower_ai_calls` | `crates/quail-datafusion/src/rules/lower.rs` |
| `merge_repeated_ai_calls` | `crates/quail-datafusion/src/rules/repeated.rs` |
| `derive` | `crates/quail-datafusion/src/rules/derive/` |
| `place_ai_nodes` | `crates/quail-datafusion/src/rules/placement.rs` |
| `claim_model_regions` | `crates/quail-datafusion/src/region/` |
| Region planner | `crates/quail-planner/` |
| Executor | `crates/quail/` and `quail/backends/quail/` |

`query.explain()` prints the plan the steps produce.

## Add Quail to your own DataFusion session

A Rust program with its own DataFusion functions and rules can add
Quail's AI functions beside them. Depend on the `quail-datafusion`
crate and on DataFusion 55.2, the version Quail builds against:

```toml
[dependencies]
datafusion = "55.2.0"
quail-datafusion = { git = "https://github.com/fsdatalab/quail" }
```

`QuailExtension::register` adds the AI functions, Quail's optimizer
rules, and Quail's query planner to your `SessionState`:

```rust
let host = SessionStateBuilder::new()
    .with_default_features()
    .with_optimizer_rule(Arc::new(MyRule))
    .build();
let state = QuailExtension::new(runner).register(host)?;
let context = SessionContext::new_with_state(state);
```

- `runner` runs the model. `quail::Executor::open(&config)?` from the
  `quail` crate runs it on your GPUs and needs Quail's Python package
  installed, because each GPU worker is a Python process.
- `register_rules` keeps your own query planner. Your planner then
  calls `quail_datafusion::claim_model_regions` on the optimized plan
  and adds `QuailExtension::extension_planner()` to its extension
  planners.
- `register` returns an error when your session already has a function
  under one of Quail's names.

[`host_session.rs`](https://github.com/fsdatalab/quail/blob/main/crates/quail-datafusion/examples/host_session.rs)
is a complete program: a host function, a host optimizer rule, and
`AI.IF` in one SQL statement. Run it with
`cargo run --example host_session`.

## Check a change

```bash
uv run ruff check quail bench calibrate tests experiments tools
uv run python tools/check_long_strings.py
uv run python tools/check_names.py
uv run vulture
uv run lint-imports
uv run --no-sync pytest -q
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked
cargo fmt --check
```

[`AGENTS.md`](https://github.com/fsdatalab/quail/blob/main/AGENTS.md)
holds the rules for writing, names, tests, and GPU runs.

## Submit a pull request

Explain the problem and how the change fixes it. List the checks you
ran and their results. State what remains unverified.
