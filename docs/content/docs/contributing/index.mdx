## How to contribute

1. Open an [issue](https://github.com/fsdatalab/quail/issues)
   proposing what you want to work on, or comment on an existing
   issue to claim it.
2. We will read and respond. Once there is agreement on the
   approach, go ahead and open a PR.
3. If you are adding new operators or functionality, also add
   queries to [QUAIL-B](https://github.com/fsdatalab/quail-bench)
   to test the new feature.

## Repository layout

| Path | Contents |
| --- | --- |
| [`quail/`](https://github.com/fsdatalab/quail/tree/main/quail) | The engine. |
| [`quail/bench/`](https://github.com/fsdatalab/quail/tree/main/quail/bench) | QUAIL-B runner. |
| [`tests/`](https://github.com/fsdatalab/quail/tree/main/tests) | CPU tests (no GPU needed). |
| [`experiments/`](https://github.com/fsdatalab/quail/tree/main/experiments) | Modal GPU scripts. |
| [`demos/`](https://github.com/fsdatalab/quail/tree/main/demos) | Runnable examples. |
| [`docs/`](https://github.com/fsdatalab/quail/tree/main/docs) | This site (Fumadocs + Next.js). |

## Running tests

```bash
uv run ruff check quail tests experiments tools
uv run python tools/check_long_strings.py
uv run vulture
uv run pytest -q
```

All four must pass before pushing.

## Running the docs site locally

```bash
cd docs
pnpm install
pnpm dev
```
