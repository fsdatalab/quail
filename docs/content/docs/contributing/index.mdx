The developer guide is for people who want to work on Quail. The guide
explains how to set up the repository, how Quail works with DataFusion, and
how Quail plans a query. The guide then lists the checks to run before you
submit a change.

## Set up Quail from source

Install [uv](https://docs.astral.sh/uv/). Quail uses Python 3.12.

```bash
git clone https://github.com/fsdatalab/quail.git
cd quail
tools/build.sh
```

`tools/build.sh` installs three things into `.venv`: the Python package from
your checkout, the Rust module `_quail_native`, and the `quail-server`
program. Run a program or the server from the checkout with
`uv run --no-sync`:

```bash
uv run --no-sync python my_program.py
uv run --no-sync quail-server --model qwen3-4b-fp8 --device h100-sxm
```

The build script downloads prebuilt Rust parts when CI has built them for the
same Rust sources. Python changes do not need a Rust compiler when the
prebuilt parts are available.

Rust changes need a local Rust build. Install [rustup](https://rustup.rs),
clang, and lld, then run:

```bash
tools/build.sh --compile
```

The first build takes about 20 minutes on 4 cores because it compiles
DataFusion. Later builds reuse the compiled dependencies. Run the command
again after each Rust change.

## Understand how Quail works with DataFusion

DataFusion parses the SQL and runs the relational operators, including scans,
plain filters, joins, aggregates, sorts, and limits. Quail adds the AI
functions and runs the model.

Quail extends a DataFusion session in four steps:

1. Quail registers SQL functions such as `AI.IF` and `AI.MAP`.
2. DataFusion turns the SQL into a logical plan. A logical plan lists the
   query operations without choosing how to run them.
3. Quail's optimizer rules represent each AI call as an `AiNode`. An `AiNode`
   is a logical-plan node for one AI call. The rules place each node among the
   DataFusion operators.
4. Quail groups related AI calls into a model region. A model region contains
   the part of the query Quail plans and runs.

DataFusion runs the operators below a model region and sends their rows to
Quail as Arrow batches. Quail runs the model and returns finished rows.
DataFusion then runs the remaining operators.

The DataFusion integration lives in `crates/quail-datafusion`:

| Code | Purpose |
| --- | --- |
| `functions` | Register the AI functions. |
| `ai` | Represent one AI call as an `AiNode`. |
| `rules` | Place and simplify the AI calls. |
| `region` | Create and run model regions. |
| `derive` | Read a model region from its DataFusion plan. |

## Understand Quail's query planner

Quail's query planner chooses how each model region runs on the GPU. The
planner orders the AI operators and chooses the rows each operator evaluates.
The operator order determines which prompts can share prefixes and KV. KV
stores the model's keys and values for prompt tokens already processed. The
planner then orders the model requests and assigns GPU memory to KV.

The planner lives in `crates/quail-planner`. The executor lives in
`crates/quail` and `quail/backends/quail`.

| Code | Purpose |
| --- | --- |
| `operators`, `expressions`, `facts` | Describe the model region. |
| `inputs` | Tokenize the document columns and measure shared prefixes. |
| `cost` | Estimate time and memory for the model and GPU. |
| `search`, `optimize`, `pricing` | Choose the operator and join order. |
| `physical` | Describe the plan the executor runs. |

`query.explain()` prints the planned query. `result.explain()` prints the
plan with measured row counts and times after the query finishes.

## Use Quail from Rust

Add the `quail-engine` crate and DataFusion 55.2, the version Quail builds
against. The crate's library is named `quail`:

```toml
[dependencies]
datafusion = "55.2.0"
quail-engine = { git = "https://github.com/fsdatalab/quail" }
```

Quail starts one Python process per GPU to run the model. Install the Python
package in the environment named by `VIRTUAL_ENV`:

```bash
pip install quail-engine
```

`quail::Session` runs SQL with AI functions:

```rust
let config = quail::EngineConfig::new("qwen3-4b-fp8", "h100-sxm");
let session = quail::Session::new(&config)?;
session.register_table("reviews", reviews)?;
let rows = session.sql(
    "SELECT r.id FROM reviews r \
     WHERE AI.IF(PROMPT('Does the reviewer ask for a refund? {0}', r.body))",
)?;
```

[`quickstart.rs`](https://github.com/fsdatalab/quail/blob/main/crates/quail/examples/quickstart.rs)
is the complete program.

### Add Quail to your own DataFusion session

A Rust program with its own DataFusion functions and rules can add Quail with
`quail::extension::QuailExtension`.

`QuailExtension::register` adds the AI functions, Quail's optimizer rules,
and Quail's query planner to your `SessionState`:

```rust
let host = SessionStateBuilder::new()
    .with_default_features()
    .with_optimizer_rule(Arc::new(MyRule))
    .build();
let state = QuailExtension::new(runner).register(host)?;
let context = SessionContext::new_with_state(state);
```

The `runner` runs the model. Use
`Arc::new(quail::Executor::open(&config)?)` to run it on your GPUs.

Call `register_rules` when you need to keep your own query planner. Your
planner must call `quail::extension::claim_model_regions` on the optimized
plan and add `QuailExtension::extension_planner()` to its extension planners.

[`host_session.rs`](https://github.com/fsdatalab/quail/blob/main/crates/quail-datafusion/examples/host_session.rs)
is a complete program. Run it with:

```bash
cargo run --example host_session
```

## Check a change

Run the Python checks:

```bash
uv run ruff check quail bench calibrate tests experiments tools
uv run python tools/check_long_strings.py
uv run python tools/check_names.py
uv run vulture
uv run lint-imports
uv run --no-sync pytest -q
```

Run the Rust checks after a successful native build:

```bash
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked
cargo fmt --check
```

[`AGENTS.md`](https://github.com/fsdatalab/quail/blob/main/AGENTS.md)
holds the rules for writing, names, tests, and GPU runs.

## Submit a pull request

Explain the problem and how the change fixes it. List the checks you ran and
their results. State any unverified behavior.

## Report a bug

[Open an issue](https://github.com/fsdatalab/quail/issues) and include:

- a minimal example reproducing the bug;
- the behavior you expected and the behavior you saw;
- the Quail version or commit;
- the `EngineConfig` for an error in an AI call.
