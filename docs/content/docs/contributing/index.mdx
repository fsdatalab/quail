## Report a bug

[Open an issue](https://github.com/fsdatalab/quail/issues) with:

- A minimal example that reproduces the bug.
- The expected behavior and what happened.
- The Quail version or commit. For an AI call error, include the
  `EngineConfig`.

## Prepare the repository

Install [uv](https://docs.astral.sh/uv/) and
[rustup](https://rustup.rs). Linux x86_64 also requires clang and lld.
Quail uses Python 3.12.

E.g., clone the repository and build the development installation:

```bash
git clone https://github.com/fsdatalab/quail.git
cd quail
tools/build.sh
```

The script runs `uv sync --frozen` with the repository's pinned Rust
toolchain. Keep the same Cargo home and `target/` directory between
builds so Cargo can reuse compiled dependencies. See
[`AGENTS.md`](https://github.com/fsdatalab/quail/blob/main/AGENTS.md#building)
for build troubleshooting.

## Make a change

Discuss substantial changes in an issue before implementation.
Include tests and documentation with the change.

| Path | Contents |
| --- | --- |
| `quail/api/` | `Session` and `Query` |
| `quail/catalog/` | Table providers |
| `crates/quail-datafusion/` | DataFusion extension: AI functions, optimizer rules, model regions |
| `crates/quail-planner/` | Planner of one model region, with the cost model (`src/cost/`) and physical plan types (`src/physical/`) |
| `crates/quail-python/` | Rust `Session` and `Executor`, and the `_quail_native` Python module (`src/native/`) |
| `quail/physical/` | Python physical plan definitions |
| `quail/backends/quail/` | GPU executor |
| `quail/specs/` | Model and device specifications |
| `quail/remote/`, `crates/quail-server/` | Quail Server's Python client, and the server |
| `tests/`, `experiments/` | CPU tests and GPU experiments |
| `docs/`, `demos/` | Documentation and examples |

Follow the writing and naming rules in
[`AGENTS.md`](https://github.com/fsdatalab/quail/blob/main/AGENTS.md).
See [Architecture](/docs/architecture) for query execution and
[Extending Quail](/docs/extending) for extension interfaces.

## Check the change

### Code checks

E.g., run the CPU checks from the repository root:

```bash
uv run ruff check quail bench calibrate tests experiments tools
uv run python tools/check_long_strings.py
uv run python tools/check_names.py
uv run vulture
uv run lint-imports
uv run --no-sync pytest -q
```

Rebuild with `tools/build.sh` after Rust edits. Also run
`cargo test --workspace --locked`,
`cargo clippy --workspace --all-targets --locked`, and `cargo fmt --check`.

For model execution changes, use
[`experiments/run_gpu_tests.py`](https://github.com/fsdatalab/quail/blob/main/experiments/run_gpu_tests.py)
to run the relevant tests on Modal.
For performance changes, follow the [benchmark guide](/docs/contributing/benchmark).

### Documentation checks

Follow [the writing guide](https://github.com/fsdatalab/quail/blob/main/docs/writing-style.md).
E.g., install dependencies and start the local site:

```bash
pnpm --dir docs install --frozen-lockfile
pnpm --dir docs dev
```

Check the changed pages at [the local site](http://localhost:3000/quail).
Then run `pnpm --dir docs types:check` and `pnpm --dir docs build`.

## Submit a pull request

Explain the problem and how the change fixes it.
List the checks you ran and their results. State what remains unverified.
For performance changes, include configurations and measurements with
links to the saved results.
