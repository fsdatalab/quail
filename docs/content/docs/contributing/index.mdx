Here we explain how to report a bug or submit a change to Quail.

## Report a bug

If you find a bug, please
[open an issue](https://github.com/fsdatalab/quail/issues).
Include:

- A minimal example that reproduces the bug.
- The expected behavior and what happened.
- The Quail version or commit. For an inference error, include the model,
  device, and backend configuration.

## Prepare the repository

Quail requires Python 3.12 and a Rust toolchain ([rustup](https://rustup.rs)):
the planner is a Rust module, `_quail_native`, that `uv sync` builds with
maturin. Clone the repository and install the development dependencies:

```bash
git clone https://github.com/fsdatalab/quail.git
cd quail
uv sync --frozen
```

The development dependencies include
[quail-b](https://github.com/fsdatalab/quail-bench).
You need access to that repository to install them.

## Make a change

For a new feature or a substantial change, open an issue to discuss the
approach before implementation.
Include the tests and documentation needed to check and use your change.

| Path | Contents |
| --- | --- |
| `quail/api/` | `Session`, `Query`, and running a query in this process. |
| `quail/catalog/` | Table providers and the tokenized inputs of a session. |
| `crates/quail-planner/`, `quail/physical/` | A region's operators and physical planning (Rust), and physical plan definitions. |
| `crates/` | SQL parsing and binding on DataFusion, the Rust planner, and the cost model, built into the `_quail_native` module. |
| `quail/specs/` | Model and device specifications. The cost model is in `crates/quail-cost/`. |
| `quail/execution/` | The runner and the CPU operators. |
| `quail/backends/` | The Quail inference engine. |
| `quail/baselines/` | The stock vLLM backends the benchmark compares against. |
| `quail/remote/`, `quail/server/` | The client and server of Quail Server. |
| `quail/deploy/` | The Modal images. |
| `bench/` | The QUAIL-B runner, outside the wheel. |
| `tests/`, `experiments/` | CPU tests and Modal GPU scripts. |
| `docs/`, `demos/` | Documentation and examples. |

Each package imports only the packages below it in the list in
`pyproject.toml` under `[tool.importlinter]`; `uv run lint-imports`
checks that.

The planner runs in Rust: `NativePlanner.plan` reads each region's
operators, as `crates/quail-datafusion/src/derive.rs` derives them from
DataFusion's plan, then rewrites, searches, and prices them, for
Quail's backend and for the request backends. Python reads the plan it returns
(`quail.physical.plan.plan_from_json`) and runs it.
`quail.speed_of_light_estimate` calls the Rust estimate with the
caller's oracles.

`PhysicalPlan` and `Refusal` are in `quail/physical/plan.py`,
`EngineConfig` in `quail/api/config.py`, and the rule names a registry
lists in `quail/extensions.py`.

To add an AI operator, add its planning to `crates/quail-planner` and
its node to `quail/physical`.

For module names, follow the [Google Python naming guidance](https://google.github.io/styleguide/pyguide.html#316-naming).
Use descriptive `snake_case` names and avoid unfamiliar abbreviations.
Keep related classes and functions together. Choose the name from the
module's responsibility, such as `model_loading.py` or `admission.py`.

The Quail backend separates its entry point from lowering and execution:

| Path under `quail/backends/quail/` | Responsibility |
| --- | --- |
| `backend.py` | Implement the backend interface and report supported configurations. |
| `lowering.py` | Lower one candidate and bind its runtime prompts. |
| `executor/runtime.py` | Bind loaded model and query state, then dispatch execution. |
| `executor/model_loading.py` | Resolve model files and load weights. |
| `executor/admission.py` | Admit requests within token and KV budgets. |

See [Architecture](/docs/architecture) for the query execution flow.
See [Extending Quail](/docs/extending) for the extension interfaces.

## Check the change

### Code checks

Run these commands from the repository root:

```bash
uv run ruff check quail bench tests experiments tools
uv run python tools/check_long_strings.py
uv run vulture
uv run lint-imports
uv run pytest -q
```

All four checks must pass before pushing. These checks do not require a GPU.

For changes to model execution, run the relevant GPU tests.
The script
[`experiments/run_gpu_tests.py`](https://github.com/fsdatalab/quail/blob/main/experiments/run_gpu_tests.py)
runs these tests on Modal.
For performance changes, use the [benchmark guide](/docs/contributing/benchmark).

### Documentation checks

Install the documentation dependencies and start the site:

```bash
pnpm --dir docs install --frozen-lockfile
pnpm --dir docs dev
```

Open [the local site](http://localhost:3000/quail).
Check the changed pages, then run:

```bash
pnpm --dir docs types:check
pnpm --dir docs build
```

## Submit a pull request

Describe the problem, what your change does, and why.
List the checks you ran and their results.
For a performance change, include the configurations, measurements, and
saved result paths. State any remaining limitations.
