The Civil Comments demo shows how you can use an AI filter and join to
classify reader comments from English-language news sites.

The demo uses 10,000 rows from [Jigsaw Civil Comments][dataset]. Each row
contains a comment and crowd-sourced scores for toxicity, six toxicity
subtypes, and 24 identity mentions.

The dataset is labeled by human raters. A label is positive when selected by
at least 50% of raters. Subjective labels can be noisy, so model predictions
may not match every majority vote.

## Query

The query is: given a `comments` table and a `fields` table, return each
`(comment_id, field)` pair where the comment is toxic and the field applies
to the comment.

The 30 fields comprise:

- Six toxicity subtypes: severe toxicity, obscene, threat, insult, identity
  attack, and sexual explicit.
- Four gender identities.
- Four sexual orientations.
- Seven religions.
- Five races or ethnicities.
- Four disability categories.

Each field has a definition, one TRUE example, and one FALSE example.
Historical `rejected` moderation metadata is excluded because moderation
status is not a semantic property of the text.

```sql
SELECT
    c.comment_id,
    f.field
FROM comments AS c
JOIN fields AS f
  ON AI_FILTER(
      PROMPT(:FIELD_PROMPT, c.text, f.statement)
  )
WHERE AI_FILTER(
    PROMPT(:TOXICITY_PROMPT, c.text)
);
```

The query has no selectivity hints.

## Comparison

The demo includes [Jev][jev] as a comparison point. Jev evaluates typed
questions against a shared state and returns structured probabilities. One
request can evaluate all 31 questions for a comment.

## Execution

Quail checks toxicity before joining a comment with the 30 fields. The
optimization is called predicate pushdown: a filter runs before a more
expensive operation. For example, Quail skips all 30 field checks when a
comment does not pass the toxicity filter.

The Jev runner supports two strategies. The combined strategy sends all 31
questions for every comment in one request. The toxicity-first strategy sends
one toxicity question for every comment, then sends the 30 field questions
only for comments classified as toxic. For example, 3,016 of the 10,000
comments passed the toxicity check, so only 3,016 comments needed field
questions.

Jev batches questions by comment. The Jev runner never sends one request for
each comment-field pair.

| Jev strategy | Request contents | Requests | Questions per request |
|---|---|---:|---:|
| Combined | Toxicity and all fields | 10,000 | 31 |
| Toxicity first | Toxicity check | 10,000 | 1 |
| Toxicity first | Field checks after toxicity passes | 3,016 | 30 |

## Run

The source lives under
[`demos/civil_comments/`](https://github.com/fsdatalab/quail/tree/main/demos/civil_comments).

Run Quail on a local H100:

```bash
uv run python demos/civil_comments/quail_backend.py \
  --limit 10000 --gpus 1 \
  --output results/civil-comments/quail/local
```

The local runner writes files under `results/civil-comments/quail/` by
default. The local runner contains no Modal setup.

Run the same Quail backend on Modal:

```bash
uv run modal run --detach demos/civil_comments/quail_modal.py \
  --limit 10000 --gpus 1
```

The Modal wrapper mounts the `quail-results` volume and writes files under
`demos/civil-comments/quail/` inside the volume. The wrapper prints the Modal
function call id before waiting for the query.

Run Jev:

```bash
read -s TYPESAFE_API_KEY
export TYPESAFE_API_KEY

uv run python demos/civil_comments/jev_backend.py \
  --limit 10000 --concurrency 256 --strategy combined \
  --output results/civil-comments/jev/combined

uv run python demos/civil_comments/jev_backend.py \
  --limit 10000 --concurrency 256 --strategy pushdown \
  --output results/civil-comments/jev/pushdown
```

The Jev runner writes local checkpoints under
`results/civil-comments/jev/`.
