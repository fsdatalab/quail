This demo shows how you can run a semantic filter and join over public
comments.

The task is to find comments that are likely to be toxic, then identify which
of 30 semantic labels apply to each toxic comment.

The comments come from [Jigsaw Civil Comments][dataset]. Human raters scored
each comment for toxicity, six toxicity subtypes, and 24 identity mentions.
Each score records the fraction of raters who selected that label. We treat a
score of 50% or higher as positive.

The labels are subjective and noisy. You should not expect high agreement
with every label. The query is still useful for showing how planning and KV
reuse affect query time and cost.

## Query

The query is: given 10,000 comments and a table of 30 semantic labels, find
the comments judged toxic, then return every label that applies to each
result.

The 30 fields comprise:

- Six toxicity subtypes: severe toxicity, obscene, threat, insult, identity
  attack, and sexual explicit.
- Four gender identities.
- Four sexual orientations.
- Seven religions.
- Five races or ethnicities.
- Four disability categories.

Each field has a definition, one TRUE example, and one FALSE example.
Historical `rejected` moderation metadata is excluded; it is not a semantic
property of the comment text.

```sql
SELECT
    c.comment_id,
    f.field
FROM comments AS c
JOIN fields AS f
  ON AI_FILTER(
      PROMPT(:FIELD_PROMPT, c.text, f.statement)
  )
WHERE AI_FILTER(
    PROMPT(:TOXICITY_PROMPT, c.text)
);
```

The query has no selectivity hints.

## Execution

Quail pushes the toxicity predicate below the join. Jev batches questions by
comment; it never sends one request per comment-field pair.

| Jev strategy | Requests | Questions per request |
|---|---:|---:|
| Combined, no planning | 10,000 | 31 |
| Pushdown filter | 10,000 | 1 |
| Pushdown fields | 3,016 | 30 |

## Results

Primary query time and cost exclude model startup.

| Backend | Query time | Tokens/s | Cost | Cost vs. Quail | Filter F1 | Join F1 |
|---|---:|---:|---:|---:|---:|---:|
| Quail, 1 H100 | **85.53 s** | 284,022 | **$0.0938** | **1.00×** | 0.413 | **0.287** |
| Jev, num_threads = 256 (no query planning) | 244.87 s | **313,379** | $1.8892 | **20.13×** | 0.425 | 0.260 |
| Jev, num_threads = 256 (push down predicate) | 100.20 s | 253,935 | $0.7705 | **8.21×** | **0.430** | 0.263 |

## Run

The source lives under
[`demos/civil_comments/`](https://github.com/fsdatalab/quail/tree/main/demos/civil_comments).

```bash
uv run modal run --detach demos/civil_comments/quail_backend.py \
  --limit 10000 --gpus 1

read -s TYPESAFE_API_KEY
export TYPESAFE_API_KEY

uv run python demos/civil_comments/jev_backend.py \
  --limit 10000 --concurrency 256 --strategy combined

uv run python demos/civil_comments/jev_backend.py \
  --limit 10000 --concurrency 256 --strategy pushdown
```
