---
title: Quail from Rust
---

Quail adds AI functions to DataFusion through one extension:

- `quail_datafusion::QuailExtension` registers AI functions and optimizer
  rules. It hands each model region to a `RegionRunner`.
- `quail::Executor` implements `RegionRunner`. It plans model regions
  and runs them on Quail's GPU executor through an embedded Python interpreter.
- `quail::Session` is the shortcut: a DataFusion session with that
  extension and executor, plus a blocking `sql()` method.
  Python's `quail.Session` uses it.

DataFusion runs SQL outside model regions. The GPU executor requires
Python even when the application is Rust.

Use `quail::Session` unless you need to extend an existing DataFusion
session. E.g., given a DataFusion table provider containing reviews:

```rust
use std::sync::Arc;
use datafusion::arrow::array::RecordBatch;
use datafusion::catalog::TableProvider;
use datafusion::common::Result;

fn negative_reviews(reviews: Arc<dyn TableProvider>) -> Result<Vec<RecordBatch>> {
    let config = quail::EngineConfig::new("qwen3-4b-fp8", "h100-sxm");
    let session = quail::Session::new(&config)?;
    session.register_table("reviews", reviews)?;
    session.sql(
        "SELECT r.id FROM reviews r \
         WHERE AI.IF(PROMPT('Is this review negative? {0}', r.body))",
    )
}
```

The provider must expose `id` and `body` columns. `Session::sql()` blocks;
call it outside an async runtime or from `spawn_blocking`.

The embedded interpreter must be able to import `quail`. Install the
package in the virtual environment selected by `VIRTUAL_ENV`. Build
with `PYO3_PYTHON` set to its Python executable and make libpython
available through `LD_LIBRARY_PATH` or the binary's rpath.

## Quail in your own DataFusion session

Register the same extension and executor on your `SessionState`.
E.g., this function adds Quail to a supplied state:

```rust
use std::sync::Arc;
use datafusion::common::Result;
use datafusion::execution::context::SessionState;
use quail_datafusion::QuailExtension;

fn add_quail(state: SessionState) -> Result<SessionState> {
    let config = quail::EngineConfig::new("qwen3-4b-fp8", "h100-sxm");
    let executor = Arc::new(quail::Executor::open(&config)?);
    QuailExtension::new(executor).register(state)
}
```

Use the returned state to create a DataFusion `SessionContext`.
Its SQL API plans and runs the query as usual.

A different `RegionRunner` can replace `Executor`, such as a test
implementation. The interface receives a model region and input streams,
plus a fetch and dynamic-filter hints. It returns Arrow batches of
model-region rows.

## What `register` adds

- AI functions under their SQL and internal names.
- The `lower_ai_calls` analyzer rule before the host's analyzer rules.
- Quail's logical optimizer rules among DataFusion's, with
  `claim_model_regions` last.
- A query planner for `ModelRegionExec` and `SharedInputExec`.

`with_logical_rules()` selects a rule list explicitly. If the host has
its own `QueryPlanner`, call `register_rules()` to keep it and add
`extension_planner()` to its `DefaultPhysicalPlanner` extensions.

## SQL

The extension also registers struct field access and regular expression
function rewrites. In the Snowflake dialect, `REGEXP_LIKE` and `RLIKE`
match the whole value.

DataFusion's SQL rules apply: `WHERE` cannot read a `SELECT` alias, and
`UNNEST` goes in `SELECT`. Repeat an identical AI call in `WHERE` to reuse
its answer. See [SQL](/docs/user-guide/sql) for syntax.

## From datafusion-python

Use [quail.Session](/docs/user-guide/sessions) from Python. Quail does
not provide a datafusion-python extension.
