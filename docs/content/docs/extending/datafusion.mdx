---
title: Using Quail from DataFusion
description: Keeping relational work in DataFusion and sending only the model part to Quail.
---

Quail does the model part of a query and nothing else. That is a
deliberate fit for an engine such as Apache DataFusion that already
does scans, ordinary joins, aggregation, and projection well.

## The shape of an integration

<Mermaid chart={`
flowchart LR
    A[DataFusion plan] --> B[Custom operator]
    B --> C[Arrow columns: id + document text]
    C --> D[Quail TableProvider]
    D --> E[Quail logical query]
    E --> F[Compute provider]
    F --> G[Arrow result: ids that passed]
    G --> H[DataFusion continues: joins, group by, order by]
`} />

1. DataFusion plans the query. A custom operator, for example one
   that recognizes an `AI_FILTER` user defined function, takes the
   subtree that Quail should run.
2. The operator wraps the Arrow record batches it would feed that
   subtree in a Quail table provider. `DocumentProvider.from_table`
   is enough for an in memory batch; a provider that returns a
   `remote_source()` avoids moving the rows through the client.
3. It builds the Quail logical query with the SQL front end or the
   builder, and runs it through the session's compute provider.
4. The result is an Arrow table of ids (or id pairs for a join).
   DataFusion joins it back to the original rows and carries on.

## What Quail expects from the caller

- A document id column and a text column per table.
- The prompts and, ideally, selectivities. Quail orders predicates by
  cost only when every predicate has one.
- Nothing else. Grouping, ordering, arithmetic, and non-AI predicates
  stay in DataFusion.

## What is not there yet

- The compute provider is a Python interface. A Rust DataFusion
  operator would need a cross-language boundary, for example a small
  Arrow Flight or HTTP shim in front of `ModalComputeProvider`. That
  shim is not built.
- The SQL front end accepts Snowflake and BigQuery spellings only. A
  DataFusion integration would build logical plans directly rather
  than round-trip through SQL text.
- Quail keeps the whole tokenized corpus for one query in one
  temporary file on the worker. Very large inputs need partitioning
  on the DataFusion side.
