---
title: Quail from Rust
---

`quail::Session` runs SQL with AI functions from a Rust program. It is
the same session Python's `quail.Session` runs queries with.
DataFusion runs every operator outside the model regions. Quail's
executor, the `quail` Python package, plans and runs each region in a
Python interpreter embedded in your process.

```rust
use std::sync::Arc;

let config = quail::EngineConfig::new("qwen3-4b-fp8", "h100-sxm");
let session = quail::Session::new(&config)?;
session.register_table("reviews", Arc::new(reviews))?;
let batches = session.sql(
    "SELECT r.id FROM reviews r \
     WHERE AI.IF(PROMPT('Is this review negative? {0}', r.body))",
)?;
```

- `Session::new` starts Python and imports `quail` from the virtual
  environment `VIRTUAL_ENV` names. Install the package there with
  `uv pip install quail-engine`.
- Your program links libpython. Set `PYO3_PYTHON` to the environment's
  Python when you build, and put its library directory on
  `LD_LIBRARY_PATH` or the binary's rpath.
- `sql` blocks until the query finishes, and each model region runs on
  the calling thread. Call it outside an async runtime, or from
  `spawn_blocking`.
- A model region reads a table you register as rows DataFusion scans.
  Tables registered from Python stay with the Python provider, which
  keeps their token counts between queries.

## Quail in your own DataFusion session

`QuailExtension` adds Quail to a DataFusion `SessionState` you already
have, with a runner of your own for the model regions:

```rust
let state = SessionStateBuilder::new().with_default_features().build();
let state = QuailExtension::new(runner).register(state)?;
let context = SessionContext::new_with_state(state);
```

`runner` implements `RegionRunner`: it takes one model region, the rows
of the region's inputs, and an optional row limit, and returns the
region's rows as a stream of Arrow batches: the id column of each
table the region reads and the answers. The region runs only the
model work and the operators it needs; DataFusion joins the tables'
other columns back on their ids, then runs the sorts, limits,
aggregates, unnests, and the rest of the SELECT list above
`ModelRegionExec`. `quail::Session` uses a
runner that calls Quail's Python executor.

## What `register` adds

- The AI functions, under their internal names (`ai_filter`,
  `ai_classify`, ...) and their SQL names (`AI.IF`, `AI.CLASSIFY`,
  `ai.classify`, ...).
- One analyzer rule, ahead of the session's own: `lower_ai_calls`
  turns each AI call in a part of the query Quail plans into an
  `AiNode`.
- Quail's optimizer rules among the session's own, before
  `replace_distinct_aggregate`, so DataFusion's rules optimize the
  plan around each `AiNode`; and `claim_model_regions` last, which
  gathers the `AiNode`s and the operators around them into
  `ModelRegion` nodes. `with_logical_rules` names the rule list
  instead.
- A query planner that plans each `ModelRegion` as a
  `ModelRegionExec`, and each `SharedInput`, a region input that the
  join above the region reads too, as a `SharedInputExec` that
  computes its rows once.

A session with its own `QueryPlanner` calls `register_rules` instead,
and adds `extension_planner()` to the extension planners its planner
passes to `DefaultPhysicalPlanner`.

## SQL

`context.sql` plans Quail's SQL; there is no separate entry point.
`register` adds, beside the AI functions and rules:

- `StructFieldAccess`, an `ExprPlanner` that plans Snowflake's
  `value['field']` on a struct, such as `AI.EXTRACT(...)['ends']`, as
  `get_field`.
- `SnowflakeRegexpLike`, a `FunctionRewrite` that makes `REGEXP_LIKE`
  and `RLIKE` match the whole value when the session reads Snowflake
  SQL, and `regexp_like` under the names `rlike` and `regexp_contains`.

The SQL is DataFusion's: `WHERE` cannot read a `SELECT` alias, so a
query repeats the AI call, which Quail asks the model once for; and
`UNNEST` goes in `SELECT`, with DataFusion's `Unnest` above the region.

## From datafusion-python

datafusion-python can load UDFs and table providers from another
library, and a query planner through `datafusion-ffi`'s
`FFI_QueryPlanner`. It cannot load analyzer or logical optimizer
rules. A Quail planner for datafusion-python would lower the AI calls
and claim the regions inside its query planner, after the session's own
optimizer has run. That is not built yet.
