---
title: Observers
---

An `ExecutionObserver` reads operator measurements and adds a report to
the query result. Quail calls it after model execution, not for progress
updates during GPU execution.

## Implement the observer

E.g., this observer records the IDs of operators whose outputs Quail returns:

```python
class CompletedOperators:
    name = "completed_operators"

    def __init__(self):
        self.node_ids = []

    def after_node(self, node, result):
        self.node_ids.append(node.node_id)

    def report(self):
        return {"node_ids": self.node_ids}
```

- `name` identifies the report.
- `after_node(node, result)` receives a physical node and its `NodeResult`.
  Read its outputs and metrics without changing them.
- `report()` returns a mapping of report values.

See the [interface](https://github.com/fsdatalab/quail/blob/main/quail/execution/runner.py).

## Register the observer

Register a factory, such as the class above. Quail creates fresh observers
when it prepares each model region's result.

E.g., create a session with this observer:

```python
import quail

registry = quail.ExtensionRegistry.with_built_ins()
registry.register_observer(CompletedOperators)
config = quail.EngineConfig(model="qwen3-4b-fp8", device="h100-sxm")
session = quail.Session(config=config, registry=registry)
```

## Read the report

For a query with one model region, call
`result.observer(CompletedOperators)` after `query.run()`. For queries
with several model regions, each region's report appears under
`result.report["regions"]`. Close the session when you finish.

See [Metrics](/docs/user-guide/metrics) for Quail's standard measurements.
