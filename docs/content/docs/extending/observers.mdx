## Metrics on the executed plan

A finished query carries its executed physical plan and each node's
measured metrics, the way a DataFusion `ExecutionPlan` exposes
`metrics()` after it runs:

```python
result = session.sql("SELECT ...").run()

result.plan                 # the executed PhysicalGraph
result.node_metrics         # node id -> NodeMetrics
print(result.explain())
```

`query.explain()` describes the plan before execution.
`result.explain()` formats the executed plan and measured metrics without
running the query again. It returns one line per node in execution order
with its fields and nonzero metrics:

```
<type_name> <node_id> [<explain fields>]  wall_s=<s> rows=<in>-><out> <nonzero metrics>
```

For a one-filter query that is a `quail.document_input` line, a
`quail.packed_filter` line with `evaluated_documents` and
`fresh_tokens`, and a `quail.project` line with the row counts.

`NodeMetrics` has `wall_s`, `input_rows`, `output_rows`,
`evaluated_documents`, `evaluated_document_pairs`, `fresh_tokens`,
`cached_tokens`, `kv_hits`, `kv_misses`, `kv_removals`,
`kv_recomputations`, `regret_tokens`, `peak_gpu_bytes`, and an
`extension` mapping for anything else. Model nodes carry the numbers
the GPU executor measured. `Recombine`, `Project`, and `Limit` report
row counts.

`quail_ext_examples/cost_ledger.py` is a complete example built on
these: it charges the query's GPU seconds, tokens, and dollars to the
nodes that used them.

```python
from quail_ext_examples import cost_ledger

ledger = cost_ledger.charge(result)
ledger["totals"]["usd"]
ledger["nodes"][1]["fresh_tokens"]
```

## Observers

An observer sees every physical node once, right after it runs, with
the node's outputs and metrics. Use one when something has to happen
during execution, such as streaming progress to a log, rather than to
read metrics afterwards. It cannot change values. Its report is
attached to the query result.

```python
class ExecutionObserver(Protocol):
    name: str
    def after_node(self, node: PhysicalNode, result: NodeResult) -> None: ...
    def report(self) -> Mapping[str, Any]: ...
```

You register the class (a factory); the runner creates a fresh
observer per query:

```python
import logging


class Progress:
    name = "my.progress"

    def __init__(self):
        self.seen = []

    def after_node(self, node, result) -> None:
        self.seen.append(node.node_id)
        logging.info("%s done in %.2fs", node.node_id, result.metrics.wall_s)

    def report(self) -> dict:
        return {"nodes": list(self.seen)}


registry = quail.ExtensionRegistry.with_built_ins().register_observer(Progress)
session = quail.Session(registry=registry)
...
result.observer(Progress)["nodes"]
```

`result.observer(Progress)` looks the report up by the class's `name`,
which is the key it travels under inside `result.report["observers"]`.

Observers see model nodes and the Arrow nodes in one pass because the
worker runs the full graph once with the model outputs supplied.
