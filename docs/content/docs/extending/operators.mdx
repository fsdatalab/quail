---
title: Custom operators
---

Quail currently supports one AI operator: `AI_FILTER` / `AI.IF`,
which returns TRUE or FALSE. Adding a new operator (like
`AI.CLASSIFY`, which returns one of N labels) requires a logical
node, a physical node, and planning logic.

We walk through what building `AI.CLASSIFY` would look like.
`AI.CLASSIFY` differs from `AI_FILTER` in two ways: it returns one
of several labels (not TRUE/FALSE), and it requires decode (the
model generates multiple tokens instead of scoring one).

## Logical node

A new operator needs a logical node type. For `AI.CLASSIFY`, the
node would hold the input, the prompt, and the list of allowed
categories:

```python
@dataclass(frozen=True)
class SemanticClassify:
    input: LogicalNode
    prompt: Prompt
    categories: tuple[str, ...]

    type_name: ClassVar[str] = "quail.semantic_classify"

    def children(self):
        return (self.input,)

    def expressions(self):
        return (self.prompt, self.categories)

    def output_schema(self):
        return self.input.output_schema()

    def validate(self):
        if not self.categories:
            raise CompileError("AI.CLASSIFY needs at least one category")
```

The node implements the
[`LogicalNode` protocol](https://github.com/fsdatalab/quail/blob/main/quail/logical.py).
Nodes are frozen dataclasses. `with_children` and
`with_expressions` return new nodes with replaced fields.

## Physical node

The physical node specifies how the operator runs on the GPU. For
`AI.CLASSIFY`, the physical node would hold the tokenized category
labels and the prompt token IDs:

```python
@dataclass(frozen=True)
class AiClassify(PhysicalNode):
    alias: str = ""
    category_token_ids: tuple = ()

    type_name: ClassVar[str] = "quail.ai_classify"
    runtime_key: ClassVar[str] = type_name
    location: ClassVar[ExecutionLocation] = ExecutionLocation.GPU_EXECUTOR
```

Each physical node needs:
- A **codec** to serialize the node for the process boundary.
  `register_node` provides a standard codec.
- A **runtime** that implements `execute(node, inputs, context)` and
  returns a `NodeResult` with Arrow output tables.

Source:
[quail/physical/nodes.py](https://github.com/fsdatalab/quail/blob/main/quail/physical/nodes.py)
for existing nodes.

## Planning

The planner needs to estimate the cost of the new operator. For
`AI.CLASSIFY`, the cost differs from `AI_FILTER` because decode
generates multiple tokens. The
[roofline model](/docs/architecture/planning#the-roofline-speed-of-light-model)
would need to account for decode steps in addition to prefill.

## Logical and physical rules

**Logical rules** rewrite the logical plan before physical planning.
For example, a rule could rewrite `AI.CLASSIFY` with two categories
into an `AI_FILTER` (since two categories is equivalent to
TRUE/FALSE):

```python
class SimplifyBinaryClassify:
    name = "simplify_binary_classify"

    def rewrite(self, node, context):
        if isinstance(node, SemanticClassify) and len(node.categories) == 2:
            return SemanticFilter(node.input, ...)
        return None
```

**Physical rules** rewrite the physical graph after the planner
picks one. For example, a rule could fuse consecutive classify
operators.

Source:
[quail/logical_optimizer.py](https://github.com/fsdatalab/quail/blob/main/quail/logical_optimizer.py)
(logical rules),
[quail/planning.py](https://github.com/fsdatalab/quail/blob/main/quail/planning.py)
(physical rules).

## Registration

```python
registry = (
    quail.ExtensionRegistry.with_built_ins()
    .register_node(AiClassify, runtime=AiClassifyRuntime())
    .register_physical_planner(ClassifyPlanner())
    .register_logical_rule(SimplifyBinaryClassify())
)
```
