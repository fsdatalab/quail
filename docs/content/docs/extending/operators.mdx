---
title: Custom operators
---

To implement a custom operator, define a physical node class and a runtime
class. The node stores your operation's settings and declares its outputs.
The *runtime* is the code that executes the node.

The example below shows these classes for Quail's existing `Scan` operator.
It explains the methods your operator must implement.
After you implement the classes, register them and add the operator to a plan.

To call a Python function between existing operators, use
[`apply()`](/docs/user-guide/python-api#apply).

## Implement the classes

In the example, `Scan` returns document IDs for a prepared table.
Its node class stores the table alias and source identifier.
For your operator, define the fields needed to perform your operation.

Quail uses these class settings to restore and execute the node:

- `type_name` identifies the node class in a saved plan. Quail uses it
  to restore a node as an instance of the correct class.
- `runtime_key` selects the registered runtime that executes the node.
  `Scan` uses the same identifier for its node class and runtime.
- `location` specifies where the operator runs. `COORDINATOR` runs it in
  the process that manages query execution. `GPU_EXECUTOR` runs it in a
  GPU worker process.

Declare the outputs with `OutputPort`:

```python
from dataclasses import dataclass
from typing import ClassVar

from quail.physical import (
    ExecutionLocation, OutputPort, PhysicalNode, ValueType,
)


@dataclass(frozen=True)
class Scan(PhysicalNode):
    alias: str = ""
    input_id: str = ""

    type_name: ClassVar[str] = "quail.scan"
    runtime_key: ClassVar[str] = type_name
    location: ClassVar[ExecutionLocation] = ExecutionLocation.COORDINATOR

    @property
    def outputs(self):
        return (OutputPort(f"ids:{self.alias}", ValueType.DOCUMENT_IDS,
                           schema=(self.alias,)),)
```

An output *port* declares the name and value type of an output.
Your runtime must return a value under each declared output name.
In the example, `ScanRuntime` reads the prepared document IDs and returns
them under the name declared by `Scan`:

```python
from quail.execution.runner import NodeResult


class ScanRuntime:
    def execute(self, node, inputs, context):
        value = context.sources[node.input_id]
        return NodeResult({f"ids:{node.alias}": value})
```

For your operator:

- Subclass `PhysicalNode`. Define the settings and output ports.
- Use a distinct `type_name` and `runtime_key`. Set `location` to the
  process where the operator will run.
- Implement `attributes()` and `from_attributes()` to save and restore
  the node's settings.
- Implement `execute(node, inputs, context)` in the runtime class.
  Return a `NodeResult` with a value for each output port.

See the complete implementations of
[`Scan`](https://github.com/fsdatalab/quail/blob/main/quail/physical/nodes.py)
and
[`ScanRuntime`](https://github.com/fsdatalab/quail/blob/main/quail/execution/runner.py).

## Register the operator

Create an [extension registry](/docs/extending#registration) with
`ExtensionRegistry.with_built_ins()`. Register your node class and runtime
instance with `registry.register_node(node_class, runtime=runtime_instance)`.
Pass the registry to the session.

Register the node and runtime in each process that executes the plan.

## Add the operator to a plan

Registration does not add the operator to queries.
Implement a [physical rule or planner](/docs/extending/rules) that creates
node instances and connects them to the physical plan.
Register the rule or planner in the same registry.

Use `PortRef` to connect an input to another node's output.
The connected ports must have compatible value types and schemas.
