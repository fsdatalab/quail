title: Custom operators
---

Adding a new operator requires a physical node, a runtime, and planning
logic. If it introduces a new operation in SQL or the Python builder,
it also needs a logical representation.

The example below defines `FirstDocuments`, a custom operator that
keeps the first N document IDs. The
[complete example](https://github.com/fsdatalab/quail/blob/main/tests/test_physical.py)
includes a planner, registration, serialization, and execution without a GPU.

## Logical node

A logical node defines what the operator means in the query plan.
For a new logical node, implement the inputs, expressions, output schema,
validation, and immutable rewrite methods described in the
[node protocol](/docs/architecture/logical-plans#the-node-protocol).
SQL and Python syntax should produce the same logical representation.

See
[`SemanticFilter`](https://github.com/fsdatalab/quail/blob/main/quail/logical/nodes.py)
for how an existing logical node is built.

## Physical node

A physical node declares its input and output ports, where it runs,
and how it is serialized. `FirstDocuments` runs on the CPU and has one
output, `ids:<alias>`. Its runtime reads the document IDs and keeps the
first `count` of them:

```python
from dataclasses import dataclass
from typing import ClassVar

from quail.execution.runner import NodeResult
from quail.physical import (
    ExecutionLocation, OutputPort, PhysicalNode, ValueType,
)

@dataclass(frozen=True)
class FirstDocuments(PhysicalNode):
    alias: str = ""
    count: int = 1

    type_name: ClassVar[str] = "example.first_documents"
    runtime_key: ClassVar[str] = type_name
    location: ClassVar[ExecutionLocation] = ExecutionLocation.COORDINATOR

    @property
    def outputs(self):
        return (OutputPort(f"ids:{self.alias}", ValueType.DOCUMENT_IDS,
                           schema=(self.alias,)),)

    def attributes(self):
        return {"alias": self.alias, "count": self.count}

    @classmethod
    def from_attributes(cls, node_id, inputs, attributes):
        return cls(node_id=node_id, inputs=inputs, alias=attributes["alias"],
                   count=int(attributes["count"]))


class FirstDocumentsRuntime:
    def execute(self, node, inputs, context):
        documents = next(iter(inputs.values()))
        return NodeResult({f"ids:{node.alias}": documents[:node.count]})
```

`attributes()` and `from_attributes()` save and restore the node's
fields. `register_node()` gives a default `NodeCodec`. The runtime
implements `execute(node, inputs, context)` and returns a `NodeResult`
with the node's declared outputs.

## Planning

A planner constructs the physical graph and estimates its execution
time. For an LLM operator:

1. **Work counting.** Add a function that counts fresh tokens,
   attention pairs, KV written, and KV read for the new operator.
   Pass `window=model.sliding_window` to `scan`, `ask`, or `stream`
   so you also count pairs and KV reads for sliding-window layers.
   See
   [`quail/cost/work.py`](https://github.com/fsdatalab/quail/blob/main/quail/cost/work.py).
2. **Cost estimation.** Pass the work counts through the
   [roofline model](/docs/architecture/cost-model#the-roofline-model)
   to get estimated seconds. See
   [`quail/cost/sol.py`](https://github.com/fsdatalab/quail/blob/main/quail/cost/sol.py).
3. **Graph construction.** Include the new physical node in the graph
   the planner builds. The planner in
   [`quail/planner/decide.py`](https://github.com/fsdatalab/quail/blob/main/quail/planner/decide.py)
   constructs the full physical graph (scans, filters, joins,
   barriers, projection) and returns a `PhysicalCandidate` with the
   graph and estimated time. The new node would be placed in the
   graph alongside the existing node types.

## Pipelines

An operator can run alone or in a pipeline with the operators next to
it. A pipeline lets an operator use the document KV of the operator
before it. To run in a pipeline, an operator must state which
neighbors it can run with and which document state it uses again.

[`execution/pipelines.py`](https://github.com/fsdatalab/quail/blob/main/quail/execution/pipelines.py)
groups physical nodes.
[`executor/pipeline.py`](https://github.com/fsdatalab/quail/blob/main/quail/backends/quail/executor/pipeline.py)
executes the groups using `executor/operators/`.

## Optional: rules

A logical or physical rule can place the new node in a plan or set
its fields. See [Rules](/docs/extending/rules).

## Registration

Register the node and runtime on the session's `ExtensionRegistry`:

```python
registry = quail.ExtensionRegistry.with_built_ins()
registry.register_node(FirstDocuments, runtime=FirstDocumentsRuntime())
```

Register a planner with `register_physical_planner()`. See the
[Overview](/docs/extending) for how to create and pass a registry.
