---
title: Physical nodes, planners, and rules
description: Adding a node type with its codec and runtime, offering plans, and rewriting graphs.
---

A physical node needs a node class and a runtime that executes it.
`register_node` supplies the standard `NodeCodec`, which converts the node
into a form that can be sent to the worker. A physical
planner offers graphs that use it. A physical rule rewrites graphs
after the planner has chosen one. All of this is exercised by
`tests/test_physical.py`, which the code below is taken from.

## The node

```python
from dataclasses import dataclass
from typing import ClassVar

from quail.physical import (
    ExecutionLocation, OutputPort, PhysicalNode, ValueType,
)


@dataclass(frozen=True)
class FirstDocuments(PhysicalNode):
    """Return a fixed number of document ids."""

    alias: str = ""
    count: int = 1

    type_name: ClassVar[str] = "test.first_documents"
    runtime_key: ClassVar[str] = type_name
    location: ClassVar[ExecutionLocation] = ExecutionLocation.CLIENT

    @property
    def outputs(self):
        return (OutputPort(f"ids:{self.alias}", ValueType.DOCUMENT_IDS,
                           schema=(self.alias,)),)

    def attributes(self):
        return {"alias": self.alias, "count": self.count}

    @classmethod
    def from_attributes(cls, node_id, inputs, attributes):
        return cls(node_id=node_id, inputs=inputs,
                   alias=attributes["alias"],
                   count=int(attributes["count"]))
```

Rules for a node:

- `type_name` is the codec key. `runtime_key` is the runtime key.
  Both must be unique across the registry.
- `attributes()` must return exactly the dataclass fields other than
  `node_id` and `inputs`. The codec checks the key set on both sides.
- Output port names follow a convention the graph validator reads:
  `ids:<alias>` carries document ids, `filter_answers:<alias>` and
  `join_answers:<n>` carry answer relations, `rows` and `tuples`
  carry result rows.
- Set `backend` when the node can only run under one backend. The
  plan envelope refuses a graph whose backend nodes disagree with the
  selected backend.

## The runtime

```python
from quail.runtime.runner import NodeResult


class FirstDocumentsRuntime:
    def execute(self, node, inputs, context):
        documents = next(iter(inputs.values()))
        return NodeResult({f"ids:{node.alias}": documents[:node.count]})
```

`inputs` is keyed by input port name. The returned `NodeResult` must
name exactly the node's output ports. It can carry `NodeMetrics`. The
`context` is the `ExecutionContext`: the registered runtimes, the
prepared sources, the backend's model execution object, shared state,
and the observers.

## A physical planner

A planner sees the logical region and the planning context and returns
candidates. The cheapest candidate across the backend and all
registered planners wins.

```python
from quail.physical import DocumentInput, InputPort, PortRef, Project
from quail.planner.plan import PhysicalPlan
from quail.planning import PhysicalCandidate


class PreferredPlanner:
    name = "preferred"

    def plan(self, region, context):
        n_docs = len(context.document_tokens["d"])
        scan = DocumentInput(node_id="input:d", alias="d",
                             input_id="d", n_docs=n_docs)
        first = FirstDocuments(
            node_id="filter:d",
            inputs=(InputPort("input:0", ValueType.DOCUMENT_IDS,
                              PortRef("input:d", "ids:d"), schema=("d",)),),
            alias="d", count=2,
        )
        project = Project(
            node_id="project",
            inputs=(InputPort("input:0", ValueType.DOCUMENT_IDS,
                              PortRef("filter:d", "ids:d"), schema=("d",)),),
            columns=("d.id",),
        )
        plan = PhysicalPlan(
            model=context.model.name, device=context.device.name,
            workers=context.gpu_count, backend=context.backend,
            estimated_seconds=0.0, nodes=(scan, first, project),
            settings={"planner_source": "preferred planner"},
        )
        return (PhysicalCandidate(plan.graph, plan, plan.estimated_seconds),)
```

`context` is a `PlanningContext`: the model and device specs, the GPU
count, per alias document token counts, the selected backend name,
the order rule, and the tokenizer. A candidate's `plan.backend` must
equal the selected backend.

## A physical rule

```python
from dataclasses import replace
from quail.physical import PhysicalGraph


class KeepFirstDocument:
    name = "keep_first_document"

    def rewrite(self, graph, context):
        return PhysicalGraph(
            tuple(replace(n, count=1) if isinstance(n, FirstDocuments) else n
                  for n in graph.nodes),
            graph.root,
        )
```

A rule returns a new graph or `None`. Every change is validated and
noted in `plan.remarks`.

## Registering all of it

```python
registry = (
    quail.ExtensionRegistry.with_built_ins()
    .register_node(FirstDocuments, runtime=FirstDocumentsRuntime())
    .register_physical_planner(PreferredPlanner())
    .register_physical_rule(KeepFirstDocument())
)
```

`register_node` checks both names before adding the codec and runtime.
If either name is already registered, the registry stays unchanged. Pass
`codec=...` when the node needs a custom codec. The separate
`register_codec` and `register_runtime` methods remain available.

`query.explain()` prints the node by its `type_name` and its
`explain_fields()`, which default to `attributes()`. Override
`explain_fields` to drop large values from the printed plan.
