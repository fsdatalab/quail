---
title: Table providers
description: Supplying documents from storage in the query process.
---

A table provider gives Quail a schema, an id column, and bounded
Arrow batches. Construct and register the provider in the process that
runs the query.

## A provider over Arrow rows

Implement `scan` to return the requested columns in bounded batches.

```python
import pyarrow as pa
from quail.catalog import ScanRequest, TableStatistics


class RowsProvider:
    id_col = "id"

    def __init__(self, rows: list[dict]):
        self._table = pa.Table.from_pylist(rows)

    @property
    def columns(self):
        return tuple(self._table.column_names)

    def schema(self):
        return self._table.schema

    def content_identity(self):
        return f"rows:{len(self._table)}"

    def statistics(self):
        return TableStatistics(row_count=len(self._table))

    def scan(self, request: ScanRequest):
        table = self._table.select(list(request.columns))
        if request.limit is not None:
            table = table.slice(0, request.limit)
        return table.to_reader(max_chunksize=request.batch_rows)


session.register("docs", RowsProvider(rows))
```

`content_identity` must change when the content changes. The session
keys its tokenized copy of each column by it.

## Other storage systems

Create a provider with a working `scan` method and register it directly:

```python
from my_package import WarehouseProvider

session.register("docs", WarehouseProvider("documents"))
```

The provider handles connections and storage reads. It does not need an
extension registry entry or a description for another process to reopen.

On Modal, create connections and providers inside the GPU function.
Attach credentials through the function's `secrets` argument. If documents
exist only on the caller's machine, pass an Arrow table as a function argument.
See [Running on Modal](/docs/user-guide/compute).

## Reading batches

The session reads batches for the id column, the document column, and
the projected columns only. It tokenizes the document column and
writes tokens, lengths, and the projected columns to a temporary
memory mapped Arrow file. Batches are released as they are written,
so a provider can be much larger than process memory as long as the
token file fits on local disk.
