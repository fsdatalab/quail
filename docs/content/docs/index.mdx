Quail is a query engine for running language-model operations over document
collections. You write the analysis in SQL or Python. Quail plans the
complete query before it starts inference, then schedules the model work so
repeated document prefixes can share KV and each forward pass can use more of
the available token budget.

KV is the attention key and value tensors the model keeps for tokens
it has already processed.

## The problem with one request per row

Suppose an analysis first filters a collection of long documents, then asks
several more questions about every document that passes. A request-at-a-time
system handles each question separately. It processes the same document
prefix again, waits for the complete filter before starting the next stage,
and groups requests by count even when their documents have very different
lengths.

Quail sees the filter, user-provided selectivity estimates, every later
question, the document lengths, and the available GPU memory before execution
begins. This lets one query share work across rows and stages.

## What Quail does differently

1. **Pipelining.** A document starts its next predicate as soon as it passes
   the current one.
2. **Token-based admission.** The scheduler fills each forward pass by token
   count and available KV, rather than by request count.
3. **KV rewind.** A document's KV stays on the GPU for its later predicates,
   so Quail does not compute the document prefix again.
4. **Packed joins.** One anchor document shares its KV across many join
   partners in the same forward pass.

Pipelining and token-based admission reduce waiting and unused batch
capacity. KV rewind and packed joins reduce fresh input-token computation
when the needed KV remains available.

## Current scope

Quail currently runs true-or-false filters over one table, AI joins across
two or more tables, and `EXISTS` or `NOT EXISTS` filters over an AI join. The
same queries can use Snowflake-style `AI_FILTER`, BigQuery-style `AI.IF`, or
the Python builder.

The model answers each predicate with one constrained token, `TRUE` or
`FALSE`. Quail runs Qwen3 4B fp8 or Qwen3 32B fp8, with one model copy per
H100. A query can use 1, 2, 4, or 8 H100s in one Modal container.

## Roadmap

The next operators expand what a model call can return:

- `AI.CLASSIFY` returns one label from a declared set.
- `AI.EXTRACT` returns typed fields from a document.
- `AI.MAP` returns a typed value for each input row.

These operators are planned, not implemented. Open-ended generation,
speculation, and request forking are not part of the current runtime.
