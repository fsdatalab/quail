Quail runs language-model filters and joins over document collections.
Write the query in Snowflake-style SQL, BigQuery-style SQL, or Python.
Quail plans its model calls as one job instead of sending one independent
request for each row.

KV is the attention key and value tensors the model keeps for tokens
it has already processed.

## Supported queries

- Filters over one table with `AI_FILTER(PROMPT(...))`.
- AI joins across two or more tables.
- `EXISTS` and `NOT EXISTS` filters over an AI join.
- The same query shapes with BigQuery's `AI.IF` or the Python builder.

The model answers each question with a single token, TRUE or FALSE.
Quail does not run open-ended generation, classification, extraction,
or summarization.

## How Quail saves work

- **Pipelining.** A document starts its next predicate as soon as it
  passes the current one.
- **Token-based admission.** The scheduler fills each forward pass by
  token count and available KV, rather than by request count.
- **KV rewind.** A document's KV stays on the GPU for its later
  predicates, so Quail does not compute the document prefix again.
- **Packed joins.** One anchor document's KV is shared by every
  join partner in the same forward pass.

## Runtime requirements

- Python 3.12.
- Qwen3 4B fp8 or Qwen3 32B fp8.
- A CUDA GPU in the process that runs the query.
- One model copy per GPU. Quail does not split one model across GPUs.
- A local GPU, or 1, 2, 4, or 8 H100s in one Modal container.
