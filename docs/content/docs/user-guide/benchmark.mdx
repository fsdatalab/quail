---
title: Running QUAIL-B
description: Run queries with Quail and generate reports with QUAIL-B.
---

QUAIL-B defines 33 filter and join queries at scale factors 0.1, 0.5, and 1.0.
It loads inputs and labels from public S3, saves answers, and computes metrics.
Quail executes the queries.

## Run on Modal

State your expected result before starting an experiment.

```bash
mkdir -p results/benchmark
uv run modal run --detach -m quail.bench.quailb_parallel \
  --sf 0.1 --model qwen3-4b-fp8 --query IMDB-4 \
  --output-dir /results/benchmarks/quailb \
  2>&1 | tee results/benchmark/quailb.log
```

Omit `--query` to run all queries. Each query family uses one H100 for
Quail and both vLLM submission strategies. SGLang uses a separate container.
Use `--no-include-baselines` to run Quail alone.

The command prints the run directory and Modal function call IDs.
It saves results under `/results/benchmarks/quailb/<run-id>/` on the
`quail-results` volume. The wrapper owns the volume mounts and caches.

- `manifest.json` records overall status, backend run paths, and function call IDs.
- `quail/run.json` and `quail/report.md` contain combined Quail results.
- `quail/imdb/run.json` and `quail/imdb/report.md` contain the IMDB family run.
- `quail/imdb/IMDB-4/` contains the final IDs and predicate-answer Parquet files.
- Other backends have their own directories beside `quail/`.

One reference-label collection is resolved before starting any query families.
Completed results are committed even when a later query fails.
Existing run directories are not overwritten.

## Use the Python API

Inside the GPU process, use Quail's function with the shared benchmark runner:

```python
from functools import partial

import quail
import quail_b
from quail.bench.quailb import run_query

with quail.Session() as session:
    quail_b.run(
        partial(run_query, session),
        queries=["IMDB-4"],
        scale_factor=0.1,
        output_dir="/results/my-run",
        metadata={"engine": "quail", "model": session.config.model},
    )
```

`run_query` reads the query's Substrait plan into Quail's query builder,
executes it, and returns document IDs, predicate answers keyed by the plan's
operator ids, and measured duration. QUAIL-B saves and scores the results.
No evaluator or saving callback is needed.

The `run_suite()` convenience function in the same module also records Quail's
configuration and GPU price. It requires an `output_dir`.

## Generate a report

Download the printed run directory, replacing `<run-id>` with its ID:

```bash
uv run modal volume get quail-results \
  "benchmarks/quailb/<run-id>/" "./results/<run-id>/"
uv run quail-b report "./results/<run-id>/quail"
```

The command writes `report.md` beside `run.json`. Use another backend's
directory to report that backend, or a family directory to report a partial run.

Reports use the run's saved label collection and do not rerun inference.
Query time and GPU cost exclude model startup and result collection.
Filter throughput is input documents per second. Join throughput is evaluated
document pairs per second, summed across join stages.

Historical plot scripts under `reports/` still read their original saved formats.
