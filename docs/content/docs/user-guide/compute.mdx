---
title: Running on Modal
description: Run an ordinary Quail query inside a Modal GPU function.
---

All model execution requires a CUDA GPU. Modal supplies that GPU, but Quail
does not need a Modal integration. Your script defines the image, GPU,
volumes, cache paths, credentials, and result storage.

The runnable pair is
[`demos/quickstart.py`](https://github.com/fsdatalab/quail-exploration/blob/blogs/demos/quickstart.py)
and
[`demos/quickstart_modal.py`](https://github.com/fsdatalab/quail-exploration/blob/blogs/demos/quickstart_modal.py).
The Modal script calls the ordinary script's `run_query()` function.
Both run QUAIL-B IMDB-1 on 100 published reviews, using the benchmark's
query definition to find reviews that mention a positive aspect of a movie.
The shared script calls `benchmark.load_table("reviews", limit=100)`;
QUAIL-B handles the data download.

```sh
uv run modal run demos/quickstart_modal.py 2>&1 | tee results/quickstart_modal.log
```

## Define the function

The function needs a CUDA image with Quail and its backend dependencies.
For the repository checkout:

```python
import modal
from demos import quickstart

app = modal.App("quail-engine")
IMAGE_REQUIREMENTS = (
    "sqlglot==30.17.0",
    "transformers==5.15.0",
    "huggingface-hub==1.27.0",
    "pyarrow==25.0.1",
    "numpy==2.3.5",
    "bpe-qwen==0.1.5",
    "datasets==5.0.1",
    "vllm==0.26.0",
)
image = (
    modal.Image.from_registry(
        "nvidia/cuda:13.0.1-devel-ubuntu24.04", add_python="3.12")
    .entrypoint([])
    .pip_install(*IMAGE_REQUIREMENTS)
    .add_local_python_source("quail", "quail_b", "demos")
)

@app.function(image=image, gpu="H100!", memory=98304, timeout=1200)
def run_query():
    return quickstart.run_query()
```

The session, data registration, planning, and execution happen inside the
GPU function. For large sources, pass a path and open it there.

## Choose volumes and cache paths

Volumes are optional. Mount your volumes wherever you want and point the
relevant libraries at those paths. For example, a model cache can use:

```python
weights = modal.Volume.from_name("quail-hf-cache", create_if_missing=True)
image = image.env({"HF_HOME": "/model-cache"})

@app.function(
    image=image, gpu="H100!", memory=98304, timeout=1200,
    volumes={"/model-cache": weights},
)
def run_query():
    return quickstart.run_query()
```

Quail does not set Hugging Face, vLLM, Triton, or DeepGEMM cache locations.
Those libraries use their own defaults or environment settings.
`QUAIL_CACHE_DIR` controls Quail's warmup marker files. Its default is
`~/.cache/quail/kernels`; it does not change another library's cache.

The complete demo mounts one volume, `quail-results`, at `/results`.
Models use `/results/models`, compiled kernels use `/results/kernels`, and
reports use `/results/quickstart`. You can change the mount and cache paths
in the script. Keep the existing app names,
`quail-engine` for demos and `quail-milestone1` for this repository's experiments.

## Save results explicitly

Collect rows before closing the session. The function can return the
collected Arrow table and report without saving either. To persist them,
write them to a mounted path and call your volume's `commit()` method.
Quail does not write run reports or commit volumes.

The complete demo writes its report under `/results/quickstart/` and returns
the saved path with the rows and report. Change `RESULTS_DIR` and the mount
in that script to use another location.

## Submit and retrieve

Inside an `@app.local_entrypoint()`:

```python
call = run_query.spawn()
print(f"function call id: {call.object_id}", flush=True)
rows, report = call.get()
```

Keep the function call id in the tee file. After a disconnect, retrieve the
return value with `modal.FunctionCall.from_id("fc-...").get()`.
For long runs, use `modal run --detach`.

## Extensions and lifetime

Use Modal's `image.pip_install(...)` and
`image.add_local_python_source(...)` for extension dependencies and code.
Create the registry and extensions inside the function. Attach credentials
with the function's `secrets` argument.

Several queries can share one session's token files. Backends keep loaded
models in process state, but separate Modal invocations may use different
containers. `Session.close()` releases token files and waits for background
tokenization. It does not unload models or control container lifetime.
