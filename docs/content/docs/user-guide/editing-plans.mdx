---
title: Editing physical plans
---

Edit a physical plan to compare execution schedules without changing
the query. Plan editing requires a local session and a query with one
model region.

## Run the example

E.g., insert a `Barrier` between a filter and a join.
The example plans on the CPU; it downloads a tokenizer if necessary.
Save it as `edit_plan.py` and run `python edit_plan.py`:

```python
import pyarrow as pa
import quail
from quail.physical import Barrier
from quail.physical.plan import Refusal

claims = pa.table({
    "id": ["c1", "c2"],
    "claim": ["Ada Lovelace was a mathematician.", "Paris is in France."],
    "wiki_url": ["e1", "e2"],
})
evidence = pa.table({
    "id": ["e1", "e2"],
    "text": ["Ada Lovelace was an English mathematician.",
             "Paris is the capital of France."],
})
config = quail.EngineConfig(model="qwen3-4b-fp8", device="h100-sxm")
with quail.Session(config=config) as session:
    session.register("claims", quail.DocumentProvider.from_table(claims, id_col="id"))
    session.register("evidence", quail.DocumentProvider.from_table(evidence, id_col="id"))
    query = session.sql("""
        SELECT c.id, e.id
        FROM claims c
        JOIN evidence e ON c.wiki_url = e.id
          AND AI.IF(PROMPT('Does the passage support the claim? {0} {1}',
                           c.claim, e.text), {'anchor': 'c'})
        WHERE AI.IF(PROMPT('Is this claim about a person? {0}', c.claim))
    """, dialect="bq")
    print(query.explain(verbose=True))
    plan = query.plan()
    if isinstance(plan, Refusal):
        raise quail.RefusalError(plan)
    edited = plan.insert(
        Barrier(node_id="barrier:c", next_anchor="c", aliases=("c",)),
        between=("ai_filter:c", "ai_join:c"),
    )
    print("Original estimate:", plan.estimated_seconds)
    print("Edited estimate:", edited.estimated_seconds)
    assert edited.remove("barrier:c") == plan
```

## The query

The filter keeps claims about a person. The join asks whether the
matching passage supports each claim. `c.wiki_url = e.id` restricts
the pairs that the model reads. The `anchor` option selects `c` as the
side whose KV the join reuses.

## Inspect the plan

`query.explain(verbose=True)` shows operator IDs and their connections.
Use these IDs when editing another query; its IDs can differ.

Time estimates assume peak GPU compute rates and memory bandwidth.
They are not measurements. On a GPU, use `query.run(plan=plan)` and
`query.run(plan=edited)` to compare the two plans' reports.

## Insert a barrier

Without the barrier, a claim can enter the join as soon as it passes
the filter. `Barrier` waits until the filter finishes before supplying
passing claims to the join.

The edit enables KV retention on the filter. Available GPU memory
limits how much KV Quail retains. On several GPUs, the join waits for
the filter on every GPU.

`edited.remove("barrier:c")` restores the original plan.
Only `Barrier` nodes can be removed.

## Plan editing API

| Method | Effect |
| --- | --- |
| `plan.insert(node, between=(producer_id, consumer_id))` | Insert a node on an existing connection. Its value type must match. |
| `plan.remove(node_id)` | Remove a barrier and reconnect its consumers. |
| `plan.move(node_id, between=(producer_id, consumer_id))` | Move a barrier to another connection. |
| `query.run(plan=edited)` | Run the edited physical plan. |

Each edit returns a new plan. Quail checks connections and cycles,
then updates estimates when the plan has cost information.
Invalid edits raise `PlanEditError`.
