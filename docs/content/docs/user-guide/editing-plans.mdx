---
title: Editing physical plans
---

You can edit a physical plan to compare two ways of running one query.
Plan editing needs a local session and a query with one model region.

## Run the example

The program below inserts a `Barrier` between a filter and a join. A
`Barrier` makes the join wait until the filter has finished. The program
plans on the CPU and downloads a tokenizer when your machine has none.
Save the program as `edit_plan.py` and run `python edit_plan.py`:

```python
import pyarrow as pa
import quail
from quail.physical import Barrier
from quail.physical.plan import Refusal

claims = pa.table({
    "id": ["c1", "c2"],
    "claim": ["Ada Lovelace was a mathematician.", "Paris is in France."],
    "wiki_url": ["e1", "e2"],
})
evidence = pa.table({
    "id": ["e1", "e2"],
    "text": ["Ada Lovelace was an English mathematician.",
             "Paris is the capital of France."],
})
config = quail.EngineConfig(model="qwen3-4b-fp8", device="h100-sxm")
with quail.Session(config=config) as session:
    session.register("claims", quail.DocumentProvider.from_table(claims, id_col="id"))
    session.register("evidence", quail.DocumentProvider.from_table(evidence, id_col="id"))
    query = session.sql("""
        SELECT c.id, e.id
        FROM claims c
        JOIN evidence e ON c.wiki_url = e.id
          AND AI.IF(PROMPT('Does the passage support the claim? {0} {1}',
                           c.claim, e.text), {'anchor': 'c'})
        WHERE AI.IF(PROMPT('Is this claim about a person? {0}', c.claim))
    """, dialect="bq")
    print(query.explain(verbose=True))
    plan = query.plan()
    if isinstance(plan, Refusal):
        raise quail.RefusalError(plan)
    edited = plan.insert(
        Barrier(node_id="barrier:c", next_anchor="c", aliases=("c",)),
        between=("ai_filter:c", "ai_join:c"),
    )
    print("Original estimate:", plan.estimated_seconds)
    print("Edited estimate:", edited.estimated_seconds)
    assert edited.remove("barrier:c") == plan
```

## The query

The filter keeps the claims about a person. The join asks whether the
matching passage supports each claim. `c.wiki_url = e.id` limits the
pairs the model reads. The `anchor` option names `c` as the table whose
KV the join reuses.

## Inspect the plan

`query.explain(verbose=True)` shows each operator's ID and connections.
Another query has other IDs, so read the IDs from its own plan before
you edit it.

Quail estimates time from the GPU's peak compute rate and memory
bandwidth; an estimate is not a measurement. Run `query.run(plan=plan)`
and `query.run(plan=edited)` on a GPU to compare the reports of the two
plans.

## Insert a barrier

The original plan lets a claim enter the join as soon as the claim
passes the filter. `Barrier` holds the passing claims until the filter
has finished, then gives them to the join.

The edit turns on KV retention for the filter. GPU memory limits how
much KV Quail retains. The join waits for the filter on every GPU when
the session has several GPUs.

`edited.remove("barrier:c")` restores the original plan. `remove()`
accepts `Barrier` nodes only.

## Plan editing API

| Method | Effect |
| --- | --- |
| `plan.insert(node, between=(producer_id, consumer_id))` | `insert` puts a node on an existing connection. The node's value type must match the connection's. |
| `plan.remove(node_id)` | `remove` takes a barrier out and reconnects its consumers. |
| `plan.move(node_id, between=(producer_id, consumer_id))` | `move` puts a barrier on another connection. |
| `query.run(plan=edited)` | `run` runs the edited physical plan. |

Each edit returns a new plan. Quail checks the connections and rejects
a cycle, then updates the estimates when the plan has cost information.
An invalid edit raises `PlanEditError`.
