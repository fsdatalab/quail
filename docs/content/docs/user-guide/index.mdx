---
title: Installation
description: Setting up the Python package, with or without a local GPU.
---

Quail is a Python package managed with `uv`. It needs Python 3.12. A
query runs the model in your Python process by default, so that
process needs a CUDA GPU. Without one, the same query runs on Modal.

```bash
git clone https://github.com/fsdatalab/quail-exploration
cd quail-exploration
uv sync
```

`uv sync` installs the package and its dependencies: `sqlglot` for SQL
parsing, `pyarrow` for tables and results, `transformers` and
`bpe-qwen` for tokenization, `datasets` and `huggingface-hub` for
Hugging Face sources, the `modal` client, and on Linux the `vllm`
runtime that loads the model. vLLM publishes Linux wheels only, so on
macOS and Windows the package installs without it and queries run on
Modal.

## Local GPU

`quail.Session()` uses `InProcessComputeProvider`. The first `run()`
loads the model onto the GPU visible to the process and keeps it
loaded until `Session.close()`. If the process has no CUDA GPU, `run()`
raises a `RuntimeError` that says so and names the Modal provider.

The machine needs an NVIDIA driver that supports CUDA 13 (version 580
or newer) and a C compiler. Triton, which vLLM uses for GPU kernels,
compiles a small C helper at startup with `gcc`. NVIDIA GPU images
include `gcc`; on a plain Ubuntu install, `sudo apt-get install -y
build-essential` adds it. `uv sync` downloads its own Python build,
which carries the C headers that helper needs, so the system Python
and its header packages are not used.

The first run on a machine compiles the Quail backend's kernels, which
takes about three minutes on an H100. The compiled kernels and the
marker that records the compile go under `~/.cache/quail/kernels`, the
same layout the Modal image keeps on its kernel-cache volume, so later
runs skip the compile. Set `DG_CACHE_DIR`, `TRITON_CACHE_DIR`,
`VLLM_CACHE_ROOT`, or `TORCHINDUCTOR_CACHE_DIR` before the first query
to put them elsewhere. Model weights go to the Hugging Face cache,
`~/.cache/huggingface` by default.

`demos/local_gpu_smoke.py` runs one filter query in process and
prints the rows and timing, for checking a new machine.

## Modal

Pass `ModalComputeProvider` to run the compute side as Modal Functions
in the existing `quail-engine` app:

```python
session = quail.Session(compute_provider=quail.ModalComputeProvider())
```

You need a Modal account and a token on the client:

```bash
uv run modal token new
```

The first query in a fresh Modal environment builds the worker image
and downloads the model weights into the `quail-hf-cache` volume.
Later runs reuse both. Three volumes are attached to every worker:

| Volume | Mounted at | Holds |
| --- | --- | --- |
| `quail-hf-cache` | `/root/.cache/huggingface` | Model weights and tokenizers |
| `quail-kernel-cache` | `/root/.cache/kernels` | Compiled kernels and vLLM's model inspection cache |
| `quail-results` | `/results` | Run records, benchmark summaries, and per-item data |

Do not create new Modal app names. Caches and warm containers ride on
the app.

## Check the install

The CPU test suite runs without Modal:

```bash
uv run pytest
```

Everything under `experiments/cells/` is a Modal cell that costs GPU time and
runs only when you invoke it explicitly.
