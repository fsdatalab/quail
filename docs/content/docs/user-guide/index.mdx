---
title: Install
description: Install Quail and choose where its GPU process will run.
---

Quail requires Python 3.12 and currently installs from this repository.

```bash
git clone https://github.com/fsdatalab/quail.git
cd quail
uv sync
```

All model execution requires an H100. A query runs the model in the
process that creates its `Session`.

- On an H100 machine, create the session in your normal Python process.
- On Modal, create the session inside a Modal GPU function.
- On macOS or Windows, install the client dependencies locally and submit
  the query to Modal. vLLM publishes Linux wheels only.

The engine does not depend on Modal. The repository's development
dependencies include the Modal client for the supplied examples.

## Local GPU

`quail.Session()` runs queries in the current process. The first `run()`
loads the model onto the visible GPU. The backend keeps the model in process
state for later queries. `Session.close()` releases token files and background
work. Without a supported GPU, `run()` raises a `RuntimeError`.

The machine needs an NVIDIA driver that supports CUDA 13 (version 580
or newer) and a C compiler. Triton, which vLLM uses for GPU kernels,
compiles a small C helper at startup with `gcc`. NVIDIA GPU images
include `gcc`; on a plain Ubuntu install, `sudo apt-get install -y
build-essential` adds it. `uv sync` downloads its own Python build,
which carries the C headers that helper needs, so the system Python
and its header packages are not used.

The first run compiles the Quail backend's kernels. Each library uses its
own cache defaults. Set `HF_HOME`, `DG_CACHE_DIR`, `TRITON_CACHE_DIR`,
`VLLM_CACHE_ROOT`, or `TORCHINDUCTOR_CACHE_DIR` before the first query to
choose other locations. Quail does not change those settings.

Quail's warmup marker files record completed compilation passes. They go
under `~/.cache/quail/kernels` by default. Set `QUAIL_CACHE_DIR` to put them
elsewhere. On Modal, configure environment settings and mounts in your script.

`demos/quickstart.py` runs one filter query in process and prints the rows
and report. Run it on an H100 host with `uv run python demos/quickstart.py`.

## Modal

Create a normal session inside a Modal GPU function. The supplied example
uses the existing `quail-engine` app:

```bash
uv run modal run demos/quickstart_modal.py 2>&1 | tee results/quickstart_modal.log
```

See [Running on Modal](/docs/user-guide/compute) for the function and submission code.

You need a Modal account and a token on the client:

```bash
uv run modal token new
```

The first query in a fresh Modal environment builds the worker image
and downloads the model weights into the `quail-hf-cache` volume.
Later runs reuse both. Three volumes are attached to every worker:

| Volume | Mounted at | Holds |
| --- | --- | --- |
| `quail-hf-cache` | `/root/.cache/huggingface` | Model weights and tokenizers |
| `quail-kernel-cache` | `/root/.cache/kernels` | Compiled kernels and vLLM's model inspection cache |
| `quail-results` | `/results` | Run records, benchmark summaries, and per-item data |

Do not create new Modal app names. Caches and warm containers ride on
the app.

## Check the install

The CPU test suite runs without Modal:

```bash
uv run pytest
```

Everything under `experiments/cells/` is a Modal cell that costs GPU time and
runs only when you invoke it explicitly.
