---
title: Metrics
---

Use `result.report` to read the time, model work, memory, and GPU cost of
one finished run. Use `result.explain()` to compare measurements for each
query operation.

The examples continue the H100 run from
[Query results and plans](/docs/user-guide/results).

## Print a summary

```python
report = result.report
print(f"AI execution: {report['wall_s']:.2f} s")
print(f"Model startup: {report['boot_s']:.1f} s")
print(f"Fresh tokens: {report['fresh_tokens']}")
print(f"Cached tokens: {report['cached_tokens']}")
print(f"Peak GPU memory: {report['peak_gib']:.2f} GiB")
print(f"GPU cost: ${report['usd_per_query']:.6f}")
```

```text title="Output"
AI execution: 0.02 s
Model startup: 28.5 s
Fresh tokens: 100
Cached tokens: 0
Peak GPU memory: 52.97 GiB
GPU cost: $0.000020
```

The values depend on the query, model, GPU, and warm state. A warm state
means the model and kernels are already prepared.

## Time

| Field | Meaning |
| --- | --- |
| `wall_s` | Time spent running the AI operations. The value excludes model startup. |
| `boot_s` | Time spent loading the model and preparing GPU execution. |
| `boot_kind` | Startup state: `"cold"` when Quail prepares the model or kernels, or `"warm"` when preparation is already complete. |
| `worker_total_s` | Total worker time, including startup and result preparation. |
| `datafusion_s` | Time spent planning SQL and running DataFusion operators outside the AI work. |

Use `wall_s` to compare query execution. Report `boot_s` separately when
startup matters.

## Tokens and rows

| Field | Meaning |
| --- | --- |
| `fresh_tokens` | Token positions computed by the model. A position computed twice counts twice. |
| `cached_tokens` | Token positions read from KV, the cached attention state. |
| `evaluated_documents` | Documents read by AI operations. |
| `evaluated_document_pairs` | Document pairs read by AI joins. |
| `documents_per_second` | Evaluated documents divided by AI execution time. |

Fresh and cached tokens measure different work. Do not add them to estimate
the original input length because repeated computation can count one token
position more than once.

## Memory and cost

| Field | Meaning |
| --- | --- |
| `peak_gib` | Highest GPU memory use during the run, in gibibytes. |
| `usd_per_query` | GPU cost for AI execution, excluding startup and DataFusion work. |

Quail calculates `usd_per_query` from `wall_s`, the number of GPUs, and the
hourly price in the device configuration. A rental bill can be higher
because the process also uses the GPU during startup and idle time.

## Operation metrics

`report["node_metrics"]` maps each operation ID to its measurements.
`result.explain()` presents the main fields in the measured plan, so start
with the plan before reading the dictionary.

| Field | Meaning |
| --- | --- |
| `wall_s` | Time spent in the operation. |
| `input_rows` | Rows or pairs received by the operation. |
| `output_rows` | Rows or pairs returned by the operation. |
| `evaluated_documents` | Documents read by the model. |
| `evaluated_document_pairs` | Document pairs read by the model. |
| `fresh_tokens` | Token positions computed by the model. |
| `cached_tokens` | Token positions read from KV. |

Each operation reports only the fields it measures. Operation times can
overlap, so their sum is not the query time.

## Queries with several AI regions

An AI region is a group of AI functions Quail runs together. A query with
one region stores the fields directly in `result.report`. A query with
several regions stores one report per region in `result.report["regions"]`.
A query without an AI function has no AI region report.
