---
title: Metrics
---

Read `result.report` for measurements from a completed run.
Use [`result.explain()`](/docs/user-guide/results#measure-the-plan)
to compare operator measurements with estimates.

## Read a query report

E.g., with the `reviews` table from
[Running queries](/docs/user-guide/sessions) registered on an open session:

```python
query = session.sql("""
    SELECT r.id FROM reviews r
    WHERE AI.IF(PROMPT('Does this review discuss the ending? {0}', r.body))
""", dialect="bq")
result = query.run()
report = result.report
print("Model region execution seconds:", report["wall_s"])
print("Model startup seconds:", report["boot_s"])
print("Token positions computed:", report["fresh_tokens"])
```

For a query with one model region, the report contains that region's
measurements and a separate `datafusion_s` field. For several model
regions, read each report in `result.report["regions"]`.
A query without AI calls has no model region report.

## Query totals

### Execution time

| Field | Meaning |
| --- | --- |
| `wall_s` | Model region execution seconds, excluding model startup and result collection. |
| `boot_s` | Model startup seconds. |
| `worker_total_s` | Seconds spent running the model region, including startup and result preparation. Excludes DataFusion work outside the region. |
| `datafusion_s` | Seconds outside the model region, including SQL planning and surrounding operators. Available for one-region queries. |
| `boot_kind` | `"cold"` if the model or kernels need preparation; `"warm"` otherwise. |

`report["boot"]` breaks startup into `load_model_s`, `arena_s`, and
`warm_kernels_s`: weight loading, KV allocation, and kernel preparation.

### Token counts

| Field | Meaning |
| --- | --- |
| `fresh_tokens` | Token positions computed by the model. Recomputing a position counts again. |
| `cached_tokens` | Token positions read from saved KV, when available. |

`fresh_tokens` does not count every token in every prompt when Quail
reuses KV. Do not treat it as total input tokens.

## Operator metrics

`report["node_metrics"]` maps operator IDs to measurements.
`explain(verbose=True)` shows the IDs.

| Field | Meaning |
| --- | --- |
| `wall_s` | Operator time in seconds. |
| `input_rows`, `output_rows` | Rows or pairs received and returned. |
| `evaluated_documents` | Documents evaluated by the model. |
| `evaluated_document_pairs` | Document pairs evaluated by the model. |
| `fresh_tokens`, `cached_tokens` | Operator token counts, as defined above. |

Available measurements depend on the operator. Do not add operator
times to calculate elapsed query time.

## Filters and joins

`report["stages"]` holds measurements for individual `AI.IF` filters
and joins. A single operator can have several entries.

| Field | Meaning |
| --- | --- |
| `op` | `"filter"` or `"join"`. |
| `written_position` | Zero-based position in the query. `explain()` displays positions from one. |
| `provided_selectivity` | Selectivity supplied in SQL, or `None`. |
| `observed_selectivity` | Fraction of evaluated documents or pairs that pass. |
| `evaluated` | Documents evaluated by a filter. |
| `tuples` | Pairs evaluated by a join. |
| `alias` | Table alias for a filter. |
| `anchor`, `partners` | Table aliases for a join. |

The execution order can differ from the written order.
Score and classification measurements appear in `node_metrics`.

## GPU cost

E.g., estimate GPU cost for the model region in the query above:

```python
hourly_price = query.session.device.usd_per_hour
gpus = query.session.config.gpus
cost_usd = report["wall_s"] / 3600 * gpus * hourly_price
print("Model region GPU cost in dollars:", cost_usd)
```

This uses Quail's configured hourly price. It excludes model startup
and DataFusion work outside the region, so it is not the full rental bill.
