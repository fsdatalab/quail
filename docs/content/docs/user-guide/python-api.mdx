title: Python builder API
description: Building queries in Python instead of SQL.
---

The builder mirrors the SQL surface construct for construct. It
starts from `Session.docs(name)` and ends with `select(...)`, which
returns a runnable `Query`. The examples use the QUAIL-B predicates
over the `reviews` and `aspects` tables from the
[quickstart](/docs/user-guide/quickstart).

```python
from quail import col, prompt

F1 = ("Judge strictly from the review above whether it mentions at "
      "least one positive aspect of the movie.\n\n{0}\n\nInstruction: "
      "answer TRUE if the review mentions at least one positive aspect "
      "of the movie, FALSE otherwise.")
F4 = ("Judge strictly from the review above whether it discusses the "
      "ending of the movie.\n\n{0}\n\nInstruction: answer TRUE if the "
      "review discusses the ending of the movie, FALSE otherwise.")

query = (session.docs("reviews").alias("r")
         .ai_filter(prompt(F1, col("r.body")), selectivity=0.6)
         .ai_filter(prompt(F4, col("r.body")), selectivity=0.2)
         .limit(100)
         .select("r.id", "r.body"))
```

This is QUAIL-B's IMDB-6 with a limit.

## Methods

| Method | SQL equivalent |
| --- | --- |
| `docs(provider)` | `FROM provider` |
| `.alias(a)` | `FROM provider a`. Must come right after `docs()`. |
| `.ai_filter(prompt, selectivity=None)` | A `WHERE AI_FILTER(...)` term over one table. |
| `.ai_join(others, prompt, selectivity=None, anchor=None, semantics="full")` | `JOIN ... ON AI_FILTER(...)`, or `EXISTS` / `NOT EXISTS`. |
| `.join(other, on=None)` | `JOIN ... ON col = col`. The next `.ai_filter()` over both tables is the AI predicate asked of those pairs. |
| `.apply(fn, columns=[...], name=None, ids=None, kind="per_batch")` | No SQL form. A Python function between two operators; see below. |
| `.apply_table(fn, columns=[...], name=None, ids=None)` | `.apply(..., kind="barrier")`: the function runs once over every survivor. |
| `.limit(n)` | `LIMIT n` |
| `.select(*cols, order="as_written")` | The `SELECT` list. Returns the `Query`. |

`col("r.body")` is a qualified column. `col("body")` is unqualified
and resolves when exactly one table in scope has that column. `"*"`
in `select` expands to every column of every table.

## Joins

`others` is one `docs(...)` builder or a list of them. Each side must
be a single, optionally filtered, `docs(...)` query. Filters on a
joined side are carried into the combined query.

```python
DISCUSS_ASPECT = ("Does the review in DOCUMENT {0} discuss the movie "
                  "aspect in DOCUMENT {1}?")

pairs = (session.docs("reviews").alias("r")
         .ai_filter(prompt(F1, col("r.body")), selectivity=0.6)
         .ai_join(session.docs("aspects").alias("a"),
                  prompt(DISCUSS_ASPECT, col("r.body"), col("a.aspect")),
                  selectivity=0.15)
         .select("r.id", "a.aspect"))
```

That is the quickstart's join. A chain over four tables, QUAIL-B's
IMDB-9, adds one `ai_join` per table:

```python
ASPECT_SENTIMENT = ("Does the review in DOCUMENT {0} express positive "
                    "sentiment about the movie aspect in DOCUMENT {1}?")

r1 = session.docs("reviews").alias("r1")
a1 = session.docs("aspects").alias("a1")
r2 = session.docs("reviews").alias("r2")
a2 = session.docs("aspects").alias("a2")

chain = (r1
         .ai_join(a1, prompt(DISCUSS_ASPECT, col("r1.body"), col("a1.aspect")))
         .ai_join(r2, prompt(DISCUSS_ASPECT, col("r2.body"), col("a1.aspect")))
         .ai_join(a2, prompt(ASPECT_SENTIMENT, col("r2.body"), col("a2.aspect")))
         .select("r1.id", "a1.id", "r2.id", "a2.id", order="by_cost"))
```

For `semantics="full"` the prompt must reference every table the call
joins, plus at least one table already in the query, so every join
connects to the join graph.

`semantics="exists"` and `semantics="anti"` take exactly one inner
table. The prompt names the inner table and one outer table. The
anchor is always the outer table.

```python
no_aspect = (session.docs("reviews").alias("r")
             .ai_join(session.docs("aspects").alias("a"),
                      prompt(DISCUSS_ASPECT, col("r.body"), col("a.aspect")),
                      semantics="anti")
             .select("r.id"))
```

## Joins over pairs

When an ordinary column relates the two tables, `join(other, on=...)`
takes `col(...) == col(...)` conditions (one or a list) and the next
`ai_filter` over both tables is the question asked of the pairs the
conditions allow. Every other pair is never built, and the planner
prices the join by the number of equal pairs. This is QUAIL-B's
FEV-10: a claim names its Wikipedia page, and an evidence row's id is
its page name.

```python
SUPPORT = ("Does the passage in DOCUMENT {1} support the claim in "
           "DOCUMENT {0}?")

same_page = (session.docs("claims").alias("c")
             .ai_filter(prompt(F11, col("c.claim")))
             .join(session.docs("evidence").alias("e"),
                   on=col("c.evidence_wiki_url") == col("e.id"))
             .ai_filter(prompt(SUPPORT, col("c.claim"), col("e.text")))
             .select("c.id", "e.id"))
```

`ai_join(other, prompt)` is the shorthand for `join(other)` followed
by `ai_filter(prompt)` when every pair is a candidate. A `join()` with
no `ai_filter` over its pairs is refused at `select()`: a plain join
belongs in the source database.

## A function between two operators

`apply(fn, columns=[...])` puts a Python function in the plan. The
function receives a dict of Arrow tables keyed by alias. Each table
holds that alias's row indices under the alias name plus the listed
columns. What it returns depends on where it sits:

- After a filter (or a scan): the ids to keep, as a list, an Arrow
  array, or a one-column table. `ids="drop"` (the default) lets it
  leave ids out; `ids="preserve"` says it returns every id.
- After `join(other)`: the pairs the next `ai_filter` is asked about,
  as a table with both alias columns. This is the built-in equality
  written by hand: FEV-10 again, with the pairing in Python.

A function never invents an id. One that returns an id it was not
given, or drops an id under `ids="preserve"`, fails the query.

```python
def same_page(tables):
    claims, evidence = tables["c"], tables["e"]
    return claims.join(evidence, keys=["evidence_wiki_url"],
                       right_keys=["id"]).select(["c", "e"])

same_page_pairs = (session.docs("claims").alias("c")
                   .ai_filter(prompt(F11, col("c.claim")))
                   .join(session.docs("evidence").alias("e"))
                   .apply(same_page, columns=[col("c.evidence_wiki_url"),
                                              col("e.id")])
                   .ai_filter(prompt(SUPPORT, col("c.claim"), col("e.text")))
                   .select("c.id", "e.id"))
```

`kind` says how the function runs. `per_batch`, the default, runs it
on each batch of survivors a filter chain hands its join, so the
chain keeps streaming and its survivors' KV stays pinned. `barrier`
(`apply_table`) runs it once over every survivor; the planner then
finishes the chain before the function, and the join starts after
it. The function is registered on the session under `name` (its own
name by default); a session refuses two different functions under one
name. Today per-batch functions run on one GPU, and `apply` is
accepted by the Quail backend only; the planner refuses it otherwise.

## Filter order

`select(..., order=...)` sets the rule for ordering filter predicates
over one table:

- `"as_written"`: run predicates in the order you wrote them.
- `"by_cost"`: order by estimated cost using the selectivities you
  gave.

The SQL front end takes the same argument as `session.sql(text,
order=...)`. When `order` is left unset, Quail picks `by_cost` if
every predicate has a selectivity and `as_written` otherwise. The
chosen rule is reported as `order_rule` in the result report and in
`explain()`.

## Speed of light estimate

`quail.speed_of_light_estimate(query, answer)` returns the ideal time of
a query on one device without running it: every distinct document prefix
computed once and kept in KV, forward passes packed across the whole
query, and no host or scheduling overhead. The
[SoL model](/docs/architecture/sol-model) page has the equations.

`answer(prompt, assignment)` must return the exact TRUE or FALSE answer
of one prompt for one row assignment. `assignment` maps each alias in
the prompt to a row index of that alias's table. The estimator uses it
for the survivors at every filter and join stage, so it needs labels for
every row and every pair the query can evaluate. QUAIL-B passes its
saved reference labels.

```python
def answer(prompt, assignment):
    return labels[prompt.template][tuple(assignment.values())]

estimate = quail.speed_of_light_estimate(query, answer)
estimate.seconds          # ideal time on the session's device
estimate.fresh_tokens     # input tokens a model forward pass processes
estimate.usd_per_query    # seconds times the device's hourly price
estimate.assumptions()    # KV capacity, plan space, prefix reuse
estimate.as_dict()        # everything above plus per stage records
```

Keyword arguments: `model` and `device` price another spec than the
session's, `chunk_tokens` overrides the planner's chunk budget, and
`credit_shared_prefixes=False` computes each document once and reuses it
only across that document's own questions instead of sharing prefixes
across documents.

The estimate uses the answers you give it and unlimited KV. It is an
estimate, not a measured run, and says nothing about accuracy.

## Prompt helpers

The text the engine sends for a prompt is available without a session.
`quail.bind_prompt(template, (quail.ColumnRef(alias, table, column),))`
and `quail.bind_join_prompt(...)` return the bound prompt with its
preamble, tail, and token counts when given a tokenizer.
`quail.render_join_prompt_text(prompt, documents, anchor)` renders one
join tuple, and `quail.true_false_ids(tokenizer)` returns the token ids
the engine reads as TRUE and FALSE. `quail.SHARED_PRE` is the preamble
every document prefix starts with. QUAIL-B's labeling pass uses these
to ask the reference model the exact question the engine asks.

## Errors

Every mistake in the builder raises `quail.logical.CompileError` at
the call that made it, with a message that names the fix. Examples:
an alias set after a filter, two document columns on one table, a
join prompt that does not reference a joined table, or an anchor that
is not part of the join.
