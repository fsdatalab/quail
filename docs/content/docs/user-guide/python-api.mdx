title: Python API
---

The Python builder supports the same query operations as SQL. Start
with a table registered on a `Session`, add operators, and call `select()`
to create a query. The model runs when you call `run()` or `collect()`.

The examples below use an existing `session`. See
[Sessions](/docs/user-guide/sessions) for session creation and
[table registration](/docs/user-guide/sessions#registering-tables) for registering inputs.

Import `col` to refer to columns and `prompt` to write model questions:

```python
from quail import col, prompt
```

## Example

For example, suppose `reviews` contains review text in `body`, and
`aspects` contains movie aspects in `aspect`. This query keeps positive
reviews, then returns each review paired with the aspects it discusses:

```python
query = (
    session.docs("reviews").alias("r")
    .ai_if(prompt('Is this review positive?\n\n{0}', col("r.body")))
    .ai_join(
        session.docs("aspects").alias("a"),
        prompt('Does the review discuss this aspect?\n\n{0}\n\n{1}',
               col("r.body"), col("a.aspect")))
    .select("r.id", "a.aspect")
)
result = query.collect()
```

## Operators

### ai_if

`ai_if(prompt, selectivity=None)`

Filter rows with an AI predicate. The model evaluates the prompt on
each row and keeps those that return TRUE.

```python
query = (
    session.docs("reviews").alias("r")
    .ai_if(
        prompt('Is this review positive?\n\n{0}', col("r.body")),
        selectivity=0.6)
    .select("r.id")
)
result = query.collect()
```

`selectivity` is optional; a predicate without one is planned as if
20% of its rows pass. If you want to apply several predicates, add
multiple `ai_if` calls. Quail reorders them by estimated cost to
reduce total work. Pass `order="as_written"` to `select()` to keep
the written order.

### ai_classify

`ai_classify(prompt, labels, *, name, descriptions=None, task_description="", probabilities=False)`

Assign one supplied label to each document. `name` sets the label column's
name. Include that name in `select()` to return it, or use `label_in()`
to keep only documents with selected labels.

| Parameter | Type | Description |
| --- | --- | --- |
| `prompt` | `Prompt` | Question and document columns, built with `prompt()`. |
| `labels` | `Iterable[str]`, `Iterable[tuple[str, str \| None]]`, or `str` | Labels, label and description pairs, or a registered label table name. |
| `name` | `str` | Name of the result column. |
| `descriptions` | `Iterable[str \| None]` or `None` | Optional description for each label, in the same order. |
| `task_description` | `str` | Extra instructions, up to 50 words. Defaults to `""`. |
| `probabilities` | `bool` | Also returns `<name>_probabilities`, a map from each label to its probability. Defaults to `False`. |

```python
query = (
    session.docs("reviews").alias("r")
    .ai_classify(
        prompt('What sentiment does this review express? {0}', col("r.body")),
        ["positive", "negative", "neutral", "mixed"],
        name="sentiment")
    .label_in("sentiment", ["negative", "mixed"], selectivity=0.3)
    .select("r.id", "sentiment")
)
result = query.collect()
```

In this example, Quail classifies each review once. It keeps negative
and mixed reviews, then returns their IDs and sentiment labels. The
`selectivity=0.3` hint estimates that 30% of reviews pass the label
condition; it does not change which labels pass.

Provide descriptions through either label pairs or `descriptions`.
Using both raises a compilation error. The
[SQL reference](/docs/user-guide/sql#aiclassify) lists label requirements,
probability output, and limits on classifications of joined rows.

### label_in

`label_in(name: str, labels: Iterable[str], selectivity: float | None = None)`

Keep documents whose computed label matches one of the supplied values.
Call `ai_classify()` first to create the label column. `label_in()`
tests that column without calling the model again.

| Parameter | Type | Description |
| --- | --- | --- |
| `name` | `str` | Column name given to an earlier `ai_classify()` call. |
| `labels` | `Iterable[str]` | Labels to keep, such as `["negative", "mixed"]`. A list or tuple of strings works. |
| `selectivity` | `float` or `None` | Estimated fraction of documents kept. `None` uses the default estimate of `0.2`. |

For example, after classifying reviews into the `sentiment` column,
`label_in("sentiment", ["negative", "mixed"])` keeps reviews with either
of those labels.

`label_in()` does not work on a classification of joined rows.

### ai_join

`ai_join(others, prompt, selectivity=None, anchor=None, semantics="full")`

Join two or more tables with an AI predicate. The model evaluates the
prompt on each pair of rows.

```python
query = (
    session.docs("reviews").alias("r")
    .ai_join(
        session.docs("aspects").alias("a"),
        prompt('Does the review discuss this aspect?\n\n{0}\n\n{1}',
               col("r.body"), col("a.aspect")),
        selectivity=0.15)
    .select("r.id", "a.aspect")
)
result = query.collect()
```

`selectivity` and `anchor` are optional. Pass `semantics="exists"` to
keep outer rows that match at least one inner row, or
`semantics="anti"` to keep outer rows that match none.

### join

`join(other, on=None)`

Add relational predicates to restrict which pairs the model sees.
Follow `join()` with `ai_if()` over both tables:

```python
query = (
    session.docs("claims").alias("c")
    .join(
        session.docs("evidence").alias("e"),
        on=col("c.wiki_url") == col("e.id"))
    .ai_if(
        prompt('Does the passage support the claim?\n\n{0}\n\n{1}',
               col("c.claim"), col("e.text")))
    .select("c.id", "e.id")
)
result = query.collect()
```

### limit

`limit(n)`

Return at most `n` rows.

```python
query = (
    session.docs("reviews").alias("r")
    .ai_if(prompt('Is this review positive?\n\n{0}', col("r.body")))
    .limit(100)
    .select("r.id", "r.body")
)
```

### order_by

`order_by(*keys)`

Sort result rows by table columns or named AI outputs. Pass a column name
as a string for ascending order. A tuple `(name, direction)` accepts
`"asc"` or `"desc"` as the direction. An optional third string specifies
`"nulls first"` or `"nulls last"`. By default, ascending order puts nulls
last and descending order puts them first.

E.g., imagine a `reviews` table with review text in `body` and ratings
in `stars`. This query returns ten positive reviews with the
highest ratings:

```python
query = (
    session.docs("reviews").alias("r")
    .ai_if(prompt('Is this review positive?\n\n{0}', col("r.body")))
    .order_by(("r.stars", "desc", "nulls last"), "r.id")
    .limit(10)
    .select("r.id", "r.body")
)
result = query.collect()
```

The example query uses `"r.id"` as its second sorting column to order
reviews with equal ratings. Sorting columns need not appear in `select()`,
except when using `distinct()`.

### offset

`offset(n)`

Skip `n` rows before applying `limit()`. The argument must be an integer
greater than or equal to zero. Use `order_by()` to specify which rows to
skip. Without an explicit order, the skipped rows can differ between runs.

### distinct

`distinct()`

Remove duplicate rows by comparing all columns passed to `select()`.
Quail removes duplicates before sorting and applying `offset()` or
`limit()`. Every sorting column must appear in `select()`.

Sorting or removing duplicates prevents `limit()` from stopping AI
evaluation early. An offset greater than zero has the same effect.

### select

`select(*cols)`

Specify which columns to return. This must be the last operator
and returns a `Query`.

```python
.select("r.id")               # one column
.select("r.id", "a.aspect")   # multiple columns
.select("*")                   # all columns from all tables
```

### collect

`collect(limit=None)`

Execute the query and return a `pyarrow.Table`. This is when the
model runs. See [Explain plans and runs](/docs/user-guide/results)
for `run()`, `explain()`, `explain(analyze=True)`, and the
execution report.

## User-defined functions

User-defined functions run on the CPU between AI operators. They do
not run on the GPU. Quail may reorder AI filters and joins around
each other, but it will not move an AI operator across a
user-defined function.

### apply

`apply(fn, columns=[], name=None, ids=None, kind="per_batch")`

Insert a Python function into the query plan. The function receives
a dict of Arrow tables keyed by alias.

The main use case is pairing rows from two tables before an AI join.
For example, a claims table has an `evidence_wiki_url` column that
names the evidence page for each claim. Instead of evaluating the AI
predicate on every claim-evidence pair, you pair them by URL first:

```python
def match_by_url(tables):
    """Pair each claim with the evidence row its URL names.

    tables["c"] is a pyarrow.Table with columns "c" (the document ids),
    "evidence_wiki_url", and any other columns requested.
    tables["e"] has columns "e" (the document ids) and "id".
    The returned table must have columns "c" and "e" (the id columns
    from each side) to identify the pairs.
    """
    return tables["c"].join(
        tables["e"],
        keys=["evidence_wiki_url"],
        right_keys=["id"],
        join_type="inner",
    ).select(["c", "e"])

query = (
    session.docs("claims").alias("c")
    .join(session.docs("evidence").alias("e"))
    .apply(match_by_url,
           columns=[col("c.evidence_wiki_url"), col("e.id")])
    .ai_if(
        prompt('Does the passage support the claim?\n\n{0}\n\n{1}',
               col("c.claim"), col("e.text")))
    .select("c.id", "e.id")
)
result = query.collect()
```

You can also use `apply` after a filter to drop rows with custom
Python logic before the next AI operator runs.

`kind="per_batch"` (the default) runs the function on each batch of
rows in a pipeline. Outside a pipeline, the function gets all input rows
in one call. Use `apply_table()` when the function needs all rows at
once.

### apply_table

`apply_table(fn, columns=[], name=None, ids=None)`

Like `apply`, but waits for the preceding stage to finish and calls
`fn` once with all surviving rows. Equivalent to
`apply(..., kind="barrier")`.

Use this when your function needs to see every surviving row at once.
In a pipeline, `apply` gets the rows in batches. With `apply_table`,
Quail first finishes the stage before it, then calls your function one
time with all the rows.

```python
def deduplicate(tables):
    reviews = tables["r"]
    groups = reviews.group_by("body").aggregate([("r", "min")])
    return groups.column("r_min")

query = (
    session.docs("reviews").alias("r")
    .apply_table(deduplicate, columns=[col("r.body")])
    .ai_if(prompt('Is this review positive?\n\n{0}', col("r.body")))
    .select("r.id")
)
result = query.collect()
```

The planner preserves the order of operators around `apply_table()`.
It does not move an operator across the function call.

## Errors

Mistakes raise `quail.logical.CompileError` at the call that caused
them.
