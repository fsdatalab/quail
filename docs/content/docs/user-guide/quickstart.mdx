Every output on this page comes from one run of
[`docs/examples/quickstart.py`](https://github.com/fsdatalab/quail-exploration/blob/extensible-engine/docs/examples/quickstart.py)
on an H100 through Modal, with Qwen3 4B fp8. The reviews are the first
eight short reviews from the pinned `stanfordnlp/imdb` revision the
QUAIL-B benchmark uses, and the questions are the benchmark's own
predicates.

<Steps>
<Step>

## Load real documents

```python
import pyarrow as pa
import pyarrow.parquet as pq
from huggingface_hub import hf_hub_download

path = hf_hub_download(
    "stanfordnlp/imdb",
    "plain_text/train-00000-of-00001.parquet",
    repo_type="dataset",
    revision="e6281661ce1c48d982bc483cf8a173c1bbeb5d31",
)
texts = pq.read_table(path, columns=["text"]).column("text").to_pylist()
picked = [t for t in texts if 250 < len(t) < 600 and "<br" not in t][:8]

reviews = pa.table({"id": [f"rv{i}" for i in range(8)], "body": picked})
aspects = pa.table({
    "id": [f"as{i}" for i in range(12)],
    "aspect": ["the acting", "the plot", "the directing",
               "the cinematography", "the soundtrack", "the pacing",
               "the ending", "the dialogue", "the special effects",
               "the character development", "the screenplay",
               "the editing"],
})
```

</Step>
<Step>

## Open a session and register the tables

```python
import quail

session = quail.Session()
session.register("reviews", quail.DocumentProvider.from_table(reviews, id_col="id"))
session.register("aspects", quail.DocumentProvider.from_table(aspects, id_col="id"))
```

`Session()` selects the Quail backend, Qwen3 4B fp8, one H100, and the
Modal compute provider. `id_col` names the column that identifies a
document. See [Configuration](/docs/user-guide/configuration) and
[Data sources](/docs/user-guide/data-sources) for the other choices.

</Step>
<Step>

## Write a filter

The question is QUAIL-B's predicate F1. In SQL or with the builder:

<Tabs items={['SQL', 'Python']}>
<Tab value="SQL">

```python
query = session.sql("""
    SELECT r.id
    FROM reviews r
    WHERE AI_FILTER(PROMPT('Judge strictly from the review above whether it mentions at least one positive aspect of the movie.

{0}

Instruction: answer TRUE if the review mentions at least one positive aspect of the movie, FALSE otherwise.', r.body))
""")
```

</Tab>
<Tab value="Python">

```python
from quail import col, prompt

F1 = ("Judge strictly from the review above whether it mentions at "
      "least one positive aspect of the movie.\n\n{0}\n\nInstruction: "
      "answer TRUE if the review mentions at least one positive aspect "
      "of the movie, FALSE otherwise.")

query = (session.docs("reviews").alias("r")
         .ai_filter(prompt(F1, col("r.body")))
         .select("r.id"))
```

</Tab>
</Tabs>

Both build the same logical plan. The text before `{0}` becomes the
question suffix after the document, so the document's tokens do not
depend on the question.

</Step>

```text
    stage {'written_pos': 0, 'question_tokens': 51, 'preamble_tokens': 2, 'selectivity': None, 'expected_docs': 8.0}

```

This ran on the client with no GPU. It tokenized the eight reviews
(693 tokens), planned one `PackedFilter` node with a 51-token
question, and noted that with a single stage nothing reads the KV
again, so the arena is not written.

## Run it

```python

```


Four of the eight reviews mention at least one positive aspect. rv0

## Join reviews to aspects

The join asks, for each surviving review and each of the twelve
aspects, whether the review discusses that aspect. It is QUAIL-B's
IMDB-3 shape: filter F1, then the `DISCUSS_ASPECT` join.

```python
pairs = session.sql("""
    SELECT r.id, a.aspect
    FROM reviews r
    JOIN aspects a
      ON AI_FILTER(PROMPT('Does the review in DOCUMENT {0} discuss the movie aspect in DOCUMENT {1}?', r.body, a.aspect),
                   {'selectivity': 0.15})
    WHERE AI_FILTER(PROMPT('Judge strictly from the review above whether it mentions at least one positive aspect of the movie.

{0}

Instruction: answer TRUE if the review mentions at least one positive aspect of the movie, FALSE otherwise.', r.body), {'selectivity': 0.6})
""").run()
print(pairs.collect().to_pandas().to_string(index=False))
```

```text

r.id       a.aspect

 rv0       the plot
 rv0     the pacing
 rv0   the dialogue
 rv0 the screenplay

 rv2       the plot
 rv2  the directing
 rv2     the pacing

```

The plan for this query keeps the filter survivors' KV resident so
the join packs no document tokens again:

```text
  PackedFilter filter:r alias=r arena_writes=True keep_kv=True ... <- input:r[ids:r]
  AnchoredJoin group:0 anchor=r anchor_resident=filter keep_anchor_kv=False <- filter:r[ids:r], input:a[ids:a]
    stage {'written_pos': 0, 'anchor': 'r', 'partners': ['a'], 'semantics': 'full', 'selectivity': 0.15, 'expected_tuples': 57.6, ...}
  Recombine recombine alias_order=['r', 'a'] <- group:0[join_answers:0], group:0[ids:r], input:a[ids:a]
  Project sink columns=['r.id', 'a.aspect'] <- recombine[tuples]
  remark: keep KV on 'r': all survivors priced as resident for the join, 451 expected tokens per worker of the 362,250-token arena
```

And the report confirms it happened:

```text
wall_s: 1.53   boot_kind: warm   fresh_tokens: 1849
stages:
  filter r   evaluated 8   observed_selectivity 0.5
  join r x a evaluated 48 tuples   observed_selectivity 0.2083
kv_manager:
  retained_after_filters 4   join_anchor_hits 4   join_anchor_misses 0
```

The second query found a warm container, so `boot_s` is 0. The join
evaluated 48 tuples (4 surviving reviews times 12 aspects) and every
anchor hit KV left by the filter. 10 pairs passed.
