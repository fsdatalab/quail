This quickstart runs a filter over eight published IMDB reviews. It uses
QUAIL-B's IMDB-1 predicate to keep reviews that mention at least one positive
aspect of the movie.

Model execution requires an H100. You can use a local H100 or submit the same
code to a Modal H100.

## 1. Install

Quail requires Python 3.12 and currently installs from this repository.
Install [uv](https://docs.astral.sh/uv/getting-started/installation/) first,
then run:

```bash
git clone https://github.com/fsdatalab/quail.git
cd quail
uv sync --no-dev
```

## 2. Run the example

<Tabs items={['Local GPU', 'Modal H100']}>
<Tab value="Local GPU">

```bash
uv run python demos/quickstart.py
```

</Tab>
<Tab value="Modal H100">

```bash
uv run --no-sync --with 'modal[api-proxy-support]==1.5.4' modal setup
```

Then submit the example and keep its full log:

```bash
mkdir -p results
uv run --no-sync --with 'modal[api-proxy-support]==1.5.4' \
  modal run demos/quickstart_modal.py \
  2>&1 | tee results/quickstart.log
```

The command prints a Modal function call id before waiting for the result.
Keep that id in the log so you can retrieve the call after a disconnect.

## 3. Read the query

[`demos/quickstart.py`](https://github.com/fsdatalab/quail/blob/main/demos/quickstart.py)
does four things:

```python
import quail

reviews = load_reviews()

config = quail.EngineConfig(
    gpus=1,
    model="qwen3-4b-fp8",
    backend="quail",
    device="h100-sxm",
)

with quail.Session(config) as session:
    session.register(
        "reviews",
        quail.DocumentProvider.from_table(reviews, id_col="id"),
    )
    query = session.sql(FILTER_SQL)
    result = query.run()
    rows = result.collect()
    report = result.report
```

1. `load_reviews()` downloads the public IMDB train split at a fixed revision
   and selects eight short reviews.
2. `Session.register()` gives the Arrow table the SQL name `reviews`.
3. `Session.sql()` compiles the filter into a Quail logical plan.
4. `run()` executes the filter. `collect()` returns an Arrow table.

`FILTER_SQL` contains the complete predicate text:

```sql
SELECT r.id
FROM reviews r
WHERE AI_FILTER(PROMPT(
  'Judge strictly from the review above whether it mentions at least one
   positive aspect of the movie.

   {0}

   Instruction: answer TRUE if the review mentions at least one positive
   aspect of the movie, FALSE otherwise.',
  r.body
))
```

The Python builder can express the same query without SQL. Both front ends
compile to the same Quail logical plan.

## 4. Inspect the result

`Query.run()` returns a `QueryResult`:

```python
rows = result.collect()     # pyarrow.Table
count = result.count()      # number of matching rows
metrics = result.report     # query time, token counts, and stage metrics
```

Start with these report fields:

| Field | Meaning |
| --- | --- |
| `wall_s` | Query time in seconds, excluding model startup. |
| `boot_s` | Model startup time. |
| `fresh_tokens` | Input tokens computed in model forward passes. |
| `stages` | Rows or pairs evaluated and kept at each filter or join. |
| `node_metrics` | Metrics for each physical plan node. |

See [Results and explain](/docs/user-guide/results) for every result method
and report field.

## 5. Inspect the plan without a GPU run

Call `explain()` before `run()`:

```python
print(query.explain())
```

The output has two parts:

- The logical plan shows the query's filters, joins, scans, and projection.
- The physical plan shows the chosen backend, token budgets, expected row
  counts, KV reuse, and estimated model time.

Planning tokenizes a sample of each document column, but it does not execute
the model.
