---
title: Query results and plans
---

`query.run()` runs a query and keeps its rows and measurements together.
`query.explain()` shows the plan and does not run the model.
[Quail Server](/docs/user-guide/server) covers queries on a server.

The examples need an open session with a `reviews` table holding `id`
and `body`. [Running queries](/docs/user-guide/sessions) shows the setup.

## Read the results

The program below returns the reviews discussing the ending:

```python
query = session.sql("""
    SELECT r.id
    FROM reviews r
    WHERE AI.IF(PROMPT('Does this review discuss the ending? {0}', r.body))
""", dialect="bq")
result = query.run()
print(result.collect().to_pydict())
```

`run()` returns a `QueryResult`. `result.collect()` returns a
`pyarrow.Table` and does not run the model again.
`query.collect()` is a shortcut for `query.run().collect()`.

`execute_stream()` reads the finished query's rows in batches:

```python
with result.execute_stream(batch_rows=1024) as reader:
    for batch in reader:
        print(batch.to_pydict())
```

Pass `limit` to `collect()` or `execute_stream()` to read fewer rows.
`limit` does not reduce the model work, which has already finished.

### Classification answers

`result.answer_tables["classifies"]` holds every label the model
computed, including the labels of rows a later filter removed. The
program below classifies the reviews and prints the answer table:

```python
classified = session.sql("""
    SELECT r.id,
           AI.CLASSIFY(r.body, ARRAY['positive', 'negative', 'mixed']) AS sentiment
    FROM reviews r
""", dialect="bq").run()
print(classified.answer_tables["classifies"]["sentiment"].to_pydict())
```

The table has two columns, `r` and `sentiment`. `r` holds the row's
position in the input, counted from zero, and not the review ID. An
answer over joined rows has one position column per table alias.

## Preview the plan

`query.explain()` plans the query and does not load the model onto the
GPU. `verbose=True` adds operator IDs and GPU settings.

### Read the logical plan

The *logical plan* is DataFusion's plan of the query, with one `AiNode`
per AI call. Read the plan from the bottom line upward:

- `TableScan` reads a registered table.
- `AiNode` computes an answer and can filter rows on the answer.
- `Projection` selects the result columns.

### Read the physical plan

The *physical plan* says how Quail runs one model region. The plan
lists GPU settings and an estimate for each operator.

| Column | Meaning |
| --- | --- |
| `est. rows` | `est. rows` is the rows Quail expects an operator to return, or the documents or pairs Quail expects to reach a filter. |
| `est. pass` | `est. pass` is the selectivity: the fraction of documents or pairs Quail expects to pass. |
| `est. time` | `est. time` is the estimated GPU time. |

A `*` marks a default selectivity, which is 20%. A filter over three
reviews then has an estimate of 0.6 passing rows.

Quail estimates time from the GPU's peak compute rate and memory
bandwidth, so a query on a GPU takes longer than its estimate.

### Show execution settings

`query.explain(verbose=True)` adds node connections and KV retention
settings. You need the node IDs to
[edit a physical plan](/docs/user-guide/editing-plans).

## Measure the plan

`result.explain()` adds measurements to the physical plan.
`result.explain()` reads the finished run and does not call the model
again.

| Column | Meaning |
| --- | --- |
| `rows` | `rows` is the measured rows an operator returned, or the documents or pairs reaching a filter. |
| `pass` | `pass` is the measured selectivity. |
| `time` | `time` is the measured operator time. |
| `fresh tokens` | `fresh tokens` counts the token positions the model computed. A position computed twice counts twice; a position read from saved KV does not count. |

Compare `rows` and `pass` with their estimates before you compare times.
A filter passing more rows than estimated gives later operators more
work. `result.report` holds the query totals; see
[Metrics](/docs/user-guide/metrics).

### Run a query to inspect its measurements

`query.explain(analyze=True)` runs the query and returns the plans with
measurements. Each call runs the query again. Use `query.run()` when you
also need the rows.

## Refusals

A `Refusal` explains why a query cannot run with its configuration.
One reason is a model whose weights exceed one GPU's memory.

`query.explain()` displays the reason, and `query.run()` raises
`quail.RefusalError`. Change the input or the configuration named in the
reason, then run the query again.
