---
title: Query results and plans
---

Use `query.run()` to keep rows and measurements from the same run.
Use `query.explain()` to inspect the plan without running the model.
For remote queries, see [Quail Server](/docs/user-guide/server).

The examples require an open session with a `reviews` table containing
`id` and `body`. See [Running queries](/docs/user-guide/sessions) for setup.

## Read the results

E.g., return reviews that discuss the ending:

```python
query = session.sql("""
    SELECT r.id
    FROM reviews r
    WHERE AI.IF(PROMPT('Does this review discuss the ending? {0}', r.body))
""", dialect="bq")
result = query.run()
print(result.collect().to_pydict())
```

`run()` returns a `QueryResult`. `result.collect()` returns a
`pyarrow.Table` without running the model again.
`query.collect()` is a shortcut for `query.run().collect()`.

E.g., read the completed query's rows in batches:

```python
with result.execute_stream(batch_rows=1024) as reader:
    for batch in reader:
        print(batch.to_pydict())
```

Pass `limit` to either collection method to read fewer rows.
This does not reduce the model work already completed.

### Classification answers

`result.answer_tables["classifies"]` contains computed labels,
including labels for rows that later filters remove.
E.g., classify the reviews and inspect the answer table:

```python
classified = session.sql("""
    SELECT r.id,
           AI.CLASSIFY(r.body, ARRAY['positive', 'negative', 'mixed']) AS sentiment
    FROM reviews r
""", dialect="bq").run()
print(classified.answer_tables["classifies"]["sentiment"].to_pydict())
```

The table contains `r` and `sentiment`. `r` holds zero-based input row
indices, not review IDs. Joined answers have an index column for each
table alias.

## Preview the plan

Call `query.explain()` before `run()` to plan without loading the model
onto the GPU. Add `verbose=True` to see operator IDs and GPU settings.

### Read the logical plan

The *logical plan* is DataFusion's plan of the query, with `AiNode`s
for AI calls. Read it from the inputs upward:

- `TableScan` reads a registered table.
- `AiNode` computes an answer and can filter rows using that answer.
- `Projection` selects result columns.

### Read the physical plan

The *physical plan* specifies how Quail runs one model region.
It includes GPU settings and estimates for each operator.

| Column | Meaning |
| --- | --- |
| `est. rows` | Expected rows returned by an operator, or documents or pairs reaching a filter. |
| `est. pass` | Selectivity: the fraction of documents or pairs expected to pass. |
| `est. time` | Estimated GPU time. |

A `*` marks a default selectivity. The default is 20%.
E.g., a filter over three reviews has an estimate of 0.6 passing rows.

Time estimates use peak compute rates and memory bandwidth, so a
query on a GPU takes longer than its estimate.

### Show execution settings

`query.explain(verbose=True)` adds node connections and KV retention
settings. Use it to [edit a physical plan](/docs/user-guide/editing-plans).

## Measure the plan

`result.explain()` adds measurements to the physical plan.
It uses the completed run and does not call the model again.

| Column | Meaning |
| --- | --- |
| `rows` | Measured rows returned by an operator, or documents or pairs reaching a filter. |
| `pass` | Measured selectivity. |
| `time` | Measured operator time. |
| `fresh tokens` | Token positions computed by the model. Recomputing a position counts again; reading saved KV does not. |

Compare `rows` and `pass` with their estimates before comparing times.
A filter that passes more rows gives later operators more work.
Read query totals from `result.report`; see [Metrics](/docs/user-guide/metrics).

### Run a query to inspect its measurements

`query.explain(analyze=True)` runs the query and returns plans with
measurements. Each call runs it again. Use `query.run()` when you also
need the rows from that run.

## Refusals

A `Refusal` explains why a query cannot run with its configuration.
E.g., the model's weights may exceed one GPU's memory.

`query.explain()` displays the reason. `query.run()` raises
`quail.RefusalError`. Change the input or configuration that the reason
identifies before trying again.
