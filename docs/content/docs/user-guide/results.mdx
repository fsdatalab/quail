---
title: Query results and plans
---

Preview a query plan before you use the GPU. Run the query when the plan
looks correct, then compare the measured work with the estimates.

The examples continue the two-review program from
[Running queries](/docs/user-guide/sessions). The `reviews` table has an
`id` column and review text in `body`.

## Create the query

`session.sql()` checks the SQL and returns a `Query`. The call does not run
the model.

```python
query = session.sql("""
    SELECT r.id
    FROM reviews r
    WHERE AI.IF(PROMPT('Is the following review positive? {0}', r.body))
""", dialect="bq")
```

## Preview the plan

`query.explain()` returns the estimated plan without running the model:

```python
print(query.explain())
```

```text title="Output"
logical:
  Projection: r.id
    AiNode: __quail_answer_1 = ai_filter(prompt(Utf8("Is the following review positive? {0}"), r.body)), filter: __quail_answer_1, returns: []
      SubqueryAlias: r
        TableScan: reviews projection=[id, body]

physical: backend=quail, model=qwen3-4b-fp8, gpus=1
  KV=bf16, chunk budget=110,376 tokens, admission budget=353,136 tokens
  architecture=qwen3 (36 layers), weights=fp8
  kernels: linear layers: fp8 GEMM (DeepGEMM)

                                                                  est. rows   est. pass   est. time
  AiFilter: r                                                           0.4                 1.09 ms
    KV: not stored
    predicate 1  PROMPT('DOCUMENT:\n{0}\n\nIs the following …')           2        20%*
    Scan reviews as r                                                     2
      tokens=10, mean_document_tokens=5
  * no selectivity was given; the planner assumes 20%
  est. time is each node's work alone; node times do not add up to the plan estimate
  because chunk packing shares forward passes across nodes
```

The logical plan describes the SQL operations. Read the logical plan from
the bottom upward:

- `TableScan` reads `reviews`.
- `AiNode` asks the model and filters the rows.
- `Projection` returns `r.id`.

The physical plan describes the GPU work. The estimated columns mean:

| Column | Meaning |
| --- | --- |
| `est. rows` | Rows expected after an operation, or rows expected to reach a filter. |
| `est. pass` | Fraction of rows expected to pass a filter. |
| `est. time` | GPU time expected for one operation. |

The `*` marks the default pass estimate of 20%. The estimate does not
include model startup or DataFusion work.

## Run the query

`query.run()` runs the query and returns a `QueryResult`. The result keeps
the rows, measured plan, and report from one run.

```python
result = query.run()
print(result.collect().to_pydict())
```

```text title="Output"
{'r.id': ['r1', 'r2']}
```

`result.collect()` returns a PyArrow table without running the model again.
`query.collect()` is a shortcut for `query.run().collect()` when you need
only the rows.

Pass `limit` to `result.collect(limit=100)` to read fewer result rows. The
limit does not reduce model work because the run has already finished.

## Stream the rows

`result.execute_stream()` reads a finished result in Arrow record batches.
Use streaming when the full result does not fit in memory.

```python
with result.execute_stream(batch_rows=1024) as reader:
    for batch in reader:
        print(batch.to_pydict())
```

```text title="Output"
{'r.id': ['r1', 'r2']}
```

## Inspect the measured plan

`result.explain()` returns the measured plan without running the model
again:

```python
print(result.explain())
```

```text title="Output"
                    est. rows   rows   est. pass   pass      time   fresh tokens
AiFilter: r                0.4      2                      11.3 ms            100
  KV: not stored
  predicate 1                2      2        20%*   100%
  Scan: r                    2      2                      1.21 ms
    tokens=10, mean_document_tokens=5
* no selectivity was given; the planner assumes 20%
```

The measured columns mean:

| Column | Meaning |
| --- | --- |
| `rows` | Rows returned by an operation, or rows reaching a filter. |
| `pass` | Fraction of rows passing a filter. |
| `time` | Time spent in one operation. |
| `fresh tokens` | Token positions computed by the model instead of read from KV. KV is the cached attention state. |

Compare `rows` and `pass` with their estimates before you compare times.
More passing rows give later operations more work. `result.report` holds
the totals for the same run. [Metrics](/docs/user-guide/metrics) explains
each total and the GPU cost.

Use `query.explain(verbose=True)` when you need operator IDs, node
connections, or KV settings.

## Handle a refusal

A `Refusal` explains why a query cannot run with its configuration. For
example, a model can need more GPU memory than the selected GPU provides.

`query.explain()` includes the refusal. `query.run()` raises
`quail.RefusalError`. Change the input or configuration named in the
refusal, then run the query again.

[Quail Server](/docs/user-guide/server) explains how to read results from a
server query.
