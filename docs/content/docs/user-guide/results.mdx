## Preview the plan

Call `explain()` to see the query plan without running it:

```python
query = session.sql("...", dialect="snowflake")
print(query.explain())
```

No model execution happens. Quail tokenizes a sample of each document
column to estimate token lengths, but does not load the model.

The output has two parts:

```text
logical:
  Project: r.id, a.aspect
    SemanticJoin (full)
      PROMPT('...', r.body, a.aspect) (selectivity=15%)
      Join
        cross
        SemanticFilter
          PROMPT('...', r.body) (selectivity=60%)
          Scan reviews as r [body, id]
        Scan aspects as a [aspect]

physical: (backend=quail, model=qwen3-4b-fp8, workers=1)
  KV=bf16, chunk budget=110,376 tokens
  Project: r.id, a.aspect
    AiJoin: anchor=r (estimated_seconds=0.003)
      AiFilter: r (estimated_rows=4.8, estimated_seconds=0.004)
        Scan reviews as r (estimated_rows=8)
      Scan aspects as a (estimated_rows=12)
```

**Logical plan.** The top section shows the query structure. Read it
bottom-up: scans are at the leaves, the projection is at the root.
Each predicate appears under the operator that evaluates it.

**Physical plan.** The bottom section shows what the execution engine
will do:

- **backend and model**: which engine and model run the query.
- **chunk budget**: maximum tokens per model forward pass.
- **estimated_rows**: how many documents or pairs the planner expects
  at each node, based on selectivities you provided.
- **estimated_seconds**: the planner's time estimate for each node's
  model work.
- **anchor**: for a join, which table's documents stay in GPU memory.

`explain(verbose=True)` adds node ids, port connections, KV retention
decisions, and planner remarks.

## Refusals

If the planner refuses the query (for example, a document too long
for one forward pass), `explain()` prints the reason instead of a
plan. `run()` raises `quail.RefusalError` for the same case.

## Running a query

`run()` executes the query and returns a `QueryResult`:

```python
result = query.run()

table = result.collect()          # pyarrow.Table
rows = result.to_rows()           # list of tuples
n = result.count()                # row count (len(result) works too)
stream = result.execute_stream()  # pyarrow.RecordBatchReader
report = result.report            # execution metrics (see Metrics page)
```

All row accessors accept `limit=`. If you are on Modal, collect the
rows before returning from the function.

`query.collect()` is a shortcut that calls `run().collect()`.

See [Metrics](/docs/user-guide/metrics) for every field in
`result.report`.
