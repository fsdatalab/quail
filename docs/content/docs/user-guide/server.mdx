---
title: Quail Server
---

Quail Server runs the SQL a client sends over
[Arrow Flight](https://arrow.apache.org/docs/format/Flight.html), a
protocol for moving Arrow tables between processes. You submit a query
through the Python `Session` API and read its rows later by ID. Any
Arrow Flight client can call the server too.

## Start the server

Install Quail on a machine with a
[supported GPU](/docs/user-guide/models), then start the server:

```bash
uv pip install quail-engine
quail-server --model qwen3-4b-fp8 --device h100-sxm
```

- The server needs `--model` and `--device`, and runs one model.
- `--gpus` defaults to 1, and `--backend` defaults to `quail`.
- `--listen` defaults to `127.0.0.1:50051`.
- `--data` names the directory for submitted queries and their rows,
  and defaults to `quail-server-data`.

The server starts one worker process per GPU. The first query loads the
model, and later queries reuse the loaded model.

Set `QUAIL_SERVER_TOKEN` on the server, and the server refuses every
call without the token. Set the same variable on the client, and
`Session` sends the token. The server does not encrypt its traffic, so
listen on another address, such as `--listen 0.0.0.0:50051`, only on a
trusted private network.

## Submit a query

Pass the server's address as `endpoint`. The program below submits a
filter over two reviews:

```python
import pyarrow as pa
import quail

reviews = pa.table({
    "id": ["r1", "r2"],
    "body": ["The ending was excellent.", "I liked the soundtrack."],
})
config = quail.EngineConfig(model="qwen3-4b-fp8", device="h100-sxm")
endpoint = "grpc://127.0.0.1:50051"

with quail.Session(config=config, endpoint=endpoint) as session:
    session.register("reviews", quail.DocumentProvider.from_table(reviews, id_col="id"))
    query = session.sql("""
        SELECT r.id
        FROM reviews r
        WHERE AI.IF(PROMPT('Does this review discuss the ending? {0}', r.body))
    """, dialect="bq")
    run = query.submit()
    print(run.id)
    for status in run.watch():
        print(status.state)
    result = run.result()
    print(result.collect().to_pydict())
```

`submit()` returns once the server has saved the query. Save `run.id`;
the server keeps running the query after the client exits.
`run.result()` waits for the query and downloads its rows.
`query.collect()` submits, waits, and returns the rows in one call.

- `register` uploads the provider's rows to the server.
- The server keeps a table in memory, so register the table again after
  the server restarts.
- The server runs every query on its own model, whatever model the
  client's `config` names.
- `order` needs a local session.

## Inspect a query

`run.status()` returns the query's current status. `run.watch()` yields
the status each time the status changes, until the query finishes.

| State | Meaning |
| --- | --- |
| `queued`, `running` | The query has not finished. |
| `succeeded` | The query finished, and its rows are available. |
| `failed`, `cancelled` | The query ended with no rows, and `status.error` gives the reason. |

`status.progress` holds a model region's counts while the region runs.
`query.explain()` returns the server's plan, with each model region as
one operator.

| Call | What it returns |
| --- | --- |
| `status.plans` | `status.plans` holds each model region's plan once the server has planned it: the plan's `text` and the planner's `estimated_seconds`. |
| `run.answers(after=0)` | `run.answers` returns the model's answers so far, during the query and after it. Pass the returned `next` as `after` to read the following answers. |
| `run.report()` | `run.report` returns each model region's report once the query has succeeded. See [Metrics](/docs/user-guide/metrics). |
| `status.tables` | `status.tables` lists the rows each operator returned, saved once the query has succeeded. |

The program below prints each filter answer as the model gives it:

```python
seen = 0
for status in run.watch():
    page = run.answers(after=seen)
    seen = page["next"]
    for event in page["answers"]:
        if event["kind"] == "filter":
            print(event["alias"], event["documents"])
```

An answer event reports one batch: the tokens the model reads in one
forward pass. An event's `kind` is `filter`, `join`, `score`, or `evict`.
A filter event lists each document's row, the last stage to ask about
the document, and whether the document passed.

## Reconnect to a query

The program below reconnects with the ID from
[Submit a query](#submit-a-query). You do not register the table again:

```python
query_id = run.id
with quail.Session(config=config, endpoint=endpoint) as session:
    saved = session.get_run(query_id)
    print(saved.result().collect().to_pydict())
```

Reuse the `query_id` in `submit()` to retry a submission whose reply
you lost. The server returns the existing query when the SQL and the
dialect match, and refuses the ID when they differ.

## Stop a query or handle a failure

- Call `run.cancel()` to cancel a query.
- Set `timeout_s` in `submit()` to limit how long a query may run; a
  query has no limit by default.
- `run.result()` raises `QueryFailedError` when the query did not
  succeed, and `run.status().error` gives the reason.

The server runs one query at a time, and the other queries wait in the
order you submitted them. A server restarted on the same data directory
still has every finished query and its rows. The server marks an
unfinished query `failed`; submit the query again with a new ID.

## Call the server without Quail

| Flight call | What it does |
| --- | --- |
| `DoPut`, path `[table, id column]` | The server registers the uploaded rows as a table. |
| `DoGet`, ticket is SQL | The server runs the query and returns its rows. |
| `DoAction` `submit` | The server queues a query. The body is JSON with `sql`, and optionally `dialect`, `id`, and `timeout_s`. |
| `DoAction` `status`, `cancel` | The server returns the status as JSON. The body is the query ID. `status` also takes JSON with `id`, `after`, and `wait_s`, and then answers once the status's `revision` is past `after`. |
| `DoAction` `answers` | The server returns the run's answer events and `next`. The body is JSON with `id`, `after`, and `limit`. |
| `DoAction` `report` | The server returns each model region's report. The body is the query ID. |
| `DoAction` `list` | The server returns every submitted query. |
| `DoAction` `explain` | The server returns the plan. The body is JSON with `sql`, and optionally `dialect`. |
| `DoGet`, ticket `{"query_id": id}` | The server returns the saved rows of a succeeded query. `"table": n` in the ticket selects the operator rows at position `n` of the status's `tables`. |

The program below runs a query with `pyarrow.flight`:

```python
import pyarrow.flight as flight

client = flight.FlightClient("grpc://127.0.0.1:50051")
rows = client.do_get(flight.Ticket(b"SELECT count(*) FROM reviews")).read_all()
```
