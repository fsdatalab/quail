---
title: Quail Server
---

Quail Server accepts SQL over HTTP. Submit queries through the Python
`Session` API and retrieve them later by ID.

## Start the server

On a machine with a [supported GPU](/docs/user-guide/models):

```bash
uv pip install "quail-engine[server]"
quail-server
```

Defaults: `127.0.0.1:8642`, one GPU, and data in `~/.quail/server`.
The first query loads its model; later queries can reuse it.
Use `quail-server --help` for configuration options.

### Connect from another machine

Set `QUAIL_SERVER_TOKEN` to an access token on both machines.
Start the server with `quail-server --host 0.0.0.0`.

Use `http://<host>:8642` only on a trusted private network.
On an untrusted network, use an HTTPS reverse proxy to encrypt the token
and query data.

## Submit a query

Install `quail-engine` on the client and pass the server URL as `endpoint`.
E.g., submit a filter over two reviews:

```python
import pyarrow as pa
import quail

reviews = pa.table({
    "id": ["r1", "r2"],
    "body": ["The ending was excellent.", "I liked the soundtrack."],
})
config = quail.EngineConfig(model="qwen3-4b-fp8", device="h100-sxm")
endpoint = "http://127.0.0.1:8642"

with quail.Session(config=config, endpoint=endpoint) as session:
    session.register("reviews", quail.DocumentProvider.from_table(reviews, id_col="id"))
    query = session.sql("""
        SELECT r.id
        FROM reviews r
        WHERE AI.IF(PROMPT('Does this review discuss the ending? {0}', r.body))
    """, dialect="bq")
    run = query.submit()
    print(run.id)
    for status in run.watch():
        print(status.state)
    result = run.result()
    print(result.collect().to_pydict())
```

`submit()` returns after the server saves the query. Save `run.id`.
The query continues after the client exits.
`run.result()` waits for completion and downloads the result.
Use `query.collect()` when you only need rows and want to wait for them.

### Send input tables

- Quail uploads `from_table`, `from_parquet`, `from_ipc`, and
  `from_dataset` inputs. It uploads identical files only once.
- For `from_hf`, the server downloads the Hugging Face data at the commit
  selected during registration.
- Custom providers and edited physical plans require a local session.

## Inspect a query

### Read its status

`run.status()` returns the current status. `run.watch()` yields updates.

| States | Meaning |
| --- | --- |
| `queued`, `planning`, `running` | The query has not finished. |
| `succeeded` | Results are available. |
| `failed`, `interrupted`, `cancelled` | The query ended without a result. |

`status.phase` describes the current activity. `status.progress` holds
execution counts. Either can be `None` before an update.

### Read its plan and metrics

E.g., inspect the plan after planning finishes:

```python
status = run.status()
if status.plan is not None:
    print(status.plan["text"])
```

After execution, use `result.explain()` and `result.report`.
`query.explain()` is unavailable on a server session.
See [Query results and plans](/docs/user-guide/results) and
[Metrics](/docs/user-guide/metrics).

### Inspect it in a browser

Open `http://<host>:8642/` to list recent queries.
Open `http://<host>:8642/queries/<query_id>` for one query's plan and status,
including a preview of its first 20 result rows.
Enter `QUAIL_SERVER_TOKEN` when the page asks for it.

## Reconnect to a query

E.g., reconnect with the ID from the submission above. Table registration
is not necessary:

```python
query_id = run.id
with quail.Session(config=config, endpoint=endpoint) as session:
    saved = session.get_run(query_id)
    print(saved.result().collect().to_pydict())
```

To retry a submission after losing the HTTP reply, reuse its `query_id`
in `submit()`. The server returns the existing query only if its SQL,
inputs, configuration, and timeout match. Otherwise it reports
`QueryIdConflictError`.

## Stop a query or handle a failure

- Call `run.cancel()` to cancel.
- Set `timeout_s` in `submit()` to limit time after the query leaves
  the queue. The default is 1,000 seconds.
- If the query does not succeed, `run.result()` raises `QueryFailedError`.
  Read `run.status().error` for the reason.

After a server restart, queued queries resume. Queries that were planning
or running become `interrupted`; submit them again with a new ID.
Keep the server data directory to retain completed results.

## Run the server on Modal

From a repository checkout with an authenticated Modal CLI, create the
`quail-server-token` secret with `QUAIL_SERVER_TOKEN`. Include `HF_TOKEN`
if the server needs gated model weights. Then deploy:

```bash
modal deploy -m quail.server.modal_app 2>&1 | tee server-deploy.log
```

The default deployment uses one H100 in the `quail-engine` app.
Pass the printed endpoint URL to `Session` and set the same
`QUAIL_SERVER_TOKEN` on the client.

Inputs and results live on `quail-results` under `/results/quail-server/`.
A restart restores the latest saved database copy; recent status updates
can be lost. The container stops after 15 idle minutes.
Its replacement loads the model on the next query.
