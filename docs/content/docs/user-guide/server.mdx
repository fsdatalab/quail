---
title: Quail Server
---

Quail Server runs SQL sent over [Arrow Flight](https://arrow.apache.org/docs/format/Flight.html).
Submit queries through the Python `Session` API and retrieve them later
by ID. Any Arrow Flight client can call it too.

## Start the server

On a machine with a [supported GPU](/docs/user-guide/models), from a
repository checkout:

```bash
tools/build.sh
cargo build --workspace --locked
target/debug/quail-server --model qwen3-4b-fp8 --device h100-sxm
```

- `--model` and `--device` are required. The server runs one model.
- `--gpus` defaults to 1 and `--backend` to `quail`.
- `--listen` defaults to `127.0.0.1:50051`.
- `--data` is the directory for submitted queries and their rows. It
  defaults to `quail-server-data`.

The server starts one GPU worker process per GPU. The first query
loads the model; later queries reuse it.

The server has no access token and no encryption. Listen on another
address, such as `--listen 0.0.0.0:50051`, only on a trusted private
network.

## Submit a query

Pass the server address as `endpoint`.
E.g., submit a filter over two reviews:

```python
import pyarrow as pa
import quail

reviews = pa.table({
    "id": ["r1", "r2"],
    "body": ["The ending was excellent.", "I liked the soundtrack."],
})
config = quail.EngineConfig(model="qwen3-4b-fp8", device="h100-sxm")
endpoint = "grpc://127.0.0.1:50051"

with quail.Session(config=config, endpoint=endpoint) as session:
    session.register("reviews", quail.DocumentProvider.from_table(reviews, id_col="id"))
    query = session.sql("""
        SELECT r.id
        FROM reviews r
        WHERE AI.IF(PROMPT('Does this review discuss the ending? {0}', r.body))
    """, dialect="bq")
    run = query.submit()
    print(run.id)
    for status in run.watch():
        print(status.state)
    result = run.result()
    print(result.collect().to_pydict())
```

`submit()` returns after the server saves the query. Save `run.id`.
The query continues after the client exits.
`run.result()` waits for the query and downloads its rows.
Use `query.collect()` when you only need rows and want to wait for them.

- `register` uploads the provider's rows to the server.
- The server keeps a table in memory. Register it again after the
  server restarts.
- The server runs queries on its own model, whatever the client's
  `config` names.
- `order` and edited physical plans require a local session.

## Inspect a query

`run.status()` returns the current status. `run.watch()` yields it
until the query finishes.

| State | Meaning |
| --- | --- |
| `queued`, `running` | The query has not finished. |
| `succeeded` | Rows are available. |
| `failed`, `cancelled` | The query ended without rows. `status.error` says why. |

While a model region runs, `status.progress` holds its counts.
`query.explain()` returns the server's plan, with each model region as
one operator. A remote result holds rows only; it has no report.

## Reconnect to a query

E.g., reconnect with the ID from the submission above. Table registration
is not necessary:

```python
query_id = run.id
with quail.Session(config=config, endpoint=endpoint) as session:
    saved = session.get_run(query_id)
    print(saved.result().collect().to_pydict())
```

To retry a submission after losing the reply, reuse its `query_id`
in `submit()`. The server returns the existing query if its SQL and
dialect match. Otherwise it refuses the id.

## Stop a query or handle a failure

- Call `run.cancel()` to cancel.
- Set `timeout_s` in `submit()` to limit the time a query may run.
  There is no default limit.
- If the query does not succeed, `run.result()` raises `QueryFailedError`.
  Read `run.status().error` for the reason.

One query runs at a time; the others wait in the order submitted.
After a restart on the same data directory, the server still has every
finished query and its rows. A query that had not finished is `failed`;
submit it again with a new ID.

## Call the server without Quail

| Flight call | What it does |
| --- | --- |
| `DoPut`, path `[table, id column]` | Registers the uploaded rows as a table. |
| `DoGet`, ticket is SQL | Runs the query and returns its rows. |
| `DoAction` `submit` | Queues a query. Body: JSON with `sql`, and optionally `dialect`, `id`, `timeout_s`. |
| `DoAction` `status`, `cancel` | Body: the query ID. Returns the status as JSON. |
| `DoAction` `list` | Returns every submitted query. |
| `DoAction` `explain` | Body: JSON with `sql`, and optionally `dialect`. Returns the plan. |
| `DoGet`, ticket `{"query_id": id}` | Returns the saved rows of a query that succeeded. |

E.g., run a query with `pyarrow.flight`:

```python
import pyarrow.flight as flight

client = flight.FlightClient("grpc://127.0.0.1:50051")
rows = client.do_get(flight.Ticket(b"SELECT count(*) FROM reviews")).read_all()
```
