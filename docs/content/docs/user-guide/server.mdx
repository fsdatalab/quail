---
title: Quail Server
---

Use Quail Server to run queries on a GPU machine from another program or
computer. The server keeps the model available and continues running a
submitted query after the client disconnects. The client can reconnect
with the query ID and read the saved rows.

## Start the server

Install Quail on a machine with a
[supported GPU](/docs/user-guide/models), then start one server:

```bash
uv pip install quail-engine
quail-server --model qwen3-4b-fp8 --device h100-sxm
```

```text title="Server output"
Quail Server: qwen3-4b-fp8 on h100-sxm, at 127.0.0.1:50051
```

The server may print a Hugging Face download progress bar before the
startup line when the tokenizer cache is empty.

| Option | Meaning | Default |
| --- | --- | --- |
| `--model` | Model run by the server. | Required |
| `--device` | GPU type used by the server. | Required |
| `--gpus` | Number of GPU workers and model copies. | `1` |
| `--backend` | Execution backend. | `quail` |
| `--listen` | Address used by the gRPC server. | `127.0.0.1:50051` |
| `--data` | Directory for query records and finished rows. | `quail-server-data` |

The server starts one worker per GPU. The first query loads the model.
Later queries reuse the loaded model.

## Connect a Python client

Pass the server address as `endpoint`. The client uploads each registered
table and sends SQL to the server over Arrow Flight, a gRPC protocol for
moving Arrow tables between processes.

```python
import pyarrow as pa
import quail

reviews = pa.table({
    "id": ["r1", "r2"],
    "body": ["The ending was excellent.", "I liked the soundtrack."],
})
provider = quail.DocumentProvider.from_table(reviews, id_col="id")
config = quail.EngineConfig(model="qwen3-4b-fp8", device="h100-sxm")

with quail.Session(
    config=config,
    endpoint="grpc://127.0.0.1:50051",
) as session:
    session.register("reviews", provider)
    query = session.sql("""
        SELECT r.id
        FROM reviews r
        WHERE AI.IF(PROMPT('Does the review discuss the ending? {0}', r.body))
    """, dialect="bq")
    rows = query.collect()
```

`query.collect()` submits the query, waits for completion, and returns a
PyArrow table. Use the returned `rows` as you would use rows from a local
session.

The server uses the model, device, GPU count, and backend from its startup
command. The client still passes `EngineConfig` because local and remote
sessions share one API.

## Submit a query without waiting

`query.submit()` saves the query and returns a `QueryRun`, a handle for the
saved query. Give the query a stable ID when another process may need the
result:

```python
run = query.submit(query_id="ending-reviews-001")
query_id = run.id
```

The server keeps running after the client disconnects. Save `query_id`
outside the client process.

Use `run.watch()` to receive each status change. Use `run.result()` to
wait for completion and download the saved rows.

```python
result = run.result()
rows = result.collect()
```

| State | Meaning |
| --- | --- |
| `queued` | The query is waiting for the current query to finish. |
| `running` | The server is running the query. |
| `succeeded` | The rows are ready. |
| `failed` | The query ended without rows. `status.error` gives the reason. |
| `cancelled` | A client cancelled the query. |

## Reconnect to a query

Create another remote session and pass the saved ID to `get_run()`. The
server already has the query and finished rows, so the new client does not
register the table again.

```python
with quail.Session(
    config=config,
    endpoint="grpc://127.0.0.1:50051",
) as session:
    saved = session.get_run("ending-reviews-001")
    rows = saved.result().collect()
```

Submitting the same SQL and dialect with the same query ID returns the
existing query. Submitting different SQL or a different dialect with the
same ID returns an error.

## Inspect or stop a query

An AI region is a group of AI functions Quail runs together.

| Call | Result |
| --- | --- |
| `run.status()` | Current state, progress, error, and row count. |
| `run.watch()` | Each status change until the query finishes. |
| `run.report()` | Metrics for each AI region after success. |
| `run.cancel()` | A request to stop the query. |
| `query.explain()` | Plan produced by the server. |

Pass `timeout_s` to `query.submit()` to limit execution time. A query has
no time limit when `timeout_s` is omitted. `run.result()` raises
`QueryFailedError` after a failure or cancellation.

[Query results and plans](/docs/user-guide/results) explains plans.
[Metrics](/docs/user-guide/metrics) explains the report fields.

## Wait for another query

The server runs one query at a time. Other queries wait in submission
order. `run.status()` returns `queued` while a query waits.

## Restart the server

The `--data` option chooses the directory for query records and finished
rows. The default creates `quail-server-data` in the directory where the
server starts. A client can reconnect to a finished query after a server
restart.

The server keeps registered tables in memory, so register each table again
after a restart. A restart marks every unfinished query as failed. Submit a
failed query again with a new ID.

## Secure the connection

Set `QUAIL_SERVER_TOKEN` on the server to require a token. Set the same
environment variable on each client so `Session` sends the token.

Quail Server does not encrypt network traffic. The default address accepts
connections only from the same machine. Use another address, such as
`--listen 0.0.0.0:50051`, only on a trusted private network.
