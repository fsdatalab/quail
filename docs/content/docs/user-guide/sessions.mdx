title: Running queries
---

Use a session to choose a model and make tables available to SQL.
The session can run several queries without registering the tables again.

## Configure a session

Set `model` and `device` in `EngineConfig`. Both fields are required.
The `gpus` field defaults to 1. [Models and GPUs](/docs/user-guide/models)
lists the supported values.

## Register tables

Register each data source before you use it in SQL. `DocumentProvider`
connects Quail to the supported sources:

| Method | Source |
| --- | --- |
| `DocumentProvider.from_table(table, id_col)` | In-memory [PyArrow table](https://arrow.apache.org/docs/python/generated/pyarrow.Table.html) |
| `DocumentProvider.from_parquet(path, id_col)` | Parquet file or directory |
| `DocumentProvider.from_ipc(path, id_col)` | Arrow IPC file |
| `DocumentProvider.from_dataset(dataset, id_col)` | [PyArrow dataset](https://arrow.apache.org/docs/python/dataset.html) |
| `DocumentProvider.from_hf(dataset, id_col)` | Hugging Face repository name; optional `split`, `config`, and `revision` |

Each method returns a `TableProvider`. A table provider supplies table
columns and rows to Quail. `session.register(name, provider)` makes the
provider available in SQL under `name`.

Each table provider needs an `id_col`. The `id_col` value names the column
used to identify each row. Implement `quail.TableProvider` to read another
data source.

## Run a query

For example, the program below registers two reviews and returns each
review the model considers positive:

```python
import pyarrow as pa
import quail

reviews = pa.table({
    "id": ["r1", "r2"],
    "body": ["The acting was excellent.", "The plot was confusing."],
})
config = quail.EngineConfig(model="qwen3-4b-fp8", device="h100-sxm")
with quail.Session(config=config) as session:
    provider = quail.DocumentProvider.from_table(reviews, id_col="id")
    session.register("reviews", provider)
    query = session.sql("""
        SELECT r.id
        FROM reviews r
        WHERE AI.IF(PROMPT('Is the following review positive? {0}', r.body))
    """, dialect="bq")
    result = query.run()
    print(result.collect())
```

```text title="Output"
pyarrow.Table
r.id: string
----
r.id: [["r1","r2"]]
```

`sql()` returns a [`Query`](/docs/user-guide/results#read-the-results).
`run()` runs the query and returns a `QueryResult`. `result.collect()`
returns the rows as an Arrow table without running the query again.

## Inspect a query

`query.explain()` returns the estimated plan without running the model.
`result.explain()` returns the measured plan after `query.run()` finishes.
`result.report` holds the query time and token counts.
Use the estimated plan to check the query before GPU work starts. Use the
measured plan and report to find the most expensive query steps.

```python title="Estimated plan"
print(query.explain())
```

## Run on Quail Server

Pass `endpoint` to submit queries to
[Quail Server](/docs/user-guide/server). Set `endpoint` to the server's
address when you create the session. For example, use
`grpc://127.0.0.1:50051` for a server on the same computer.

`sql()` returns a [`RemoteQuery`](/docs/user-guide/server#submit-a-query),
which represents a query on Quail Server. The server keeps an accepted
query running after the client exits. Save the query ID from `submit()`
to read the query from another client.

## Use several GPUs

Set `gpus` in `EngineConfig`. Each GPU holds one complete copy of the
model. For example, the following configuration uses four GPUs:

```python
config = quail.EngineConfig(
    model="qwen3-4b-fp8",
    device="h100-sxm",
    gpus=4,
)
```
