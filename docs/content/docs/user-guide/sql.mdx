## What is AI-SQL?

AI-SQL extends standard SQL with operators that call a language model
during query execution. You can filter rows, join tables, and match
documents using natural language conditions instead of exact column
comparisons.

For example, suppose you registered a `reviews` table with columns `id`
and `body`. This query returns IDs of reviews that discuss the movie's
ending:

```sql
SELECT r.id
FROM reviews r
WHERE AI.IF(PROMPT('Does this review discuss the ending of the movie?\n\n{0}', r.body))
```

The model reads each review and returns TRUE or FALSE. Quail keeps
the rows where the answer is TRUE.

Major database vendors define their own AI-SQL syntax, including
[Snowflake Cortex AISQL](https://docs.snowflake.com/en/user-guide/snowflake-cortex/aisql),
[BigQuery AI functions](https://cloud.google.com/blog/products/data-analytics/sql-reimagined-for-the-ai-era-with-bigquery-ai-functions),
and [Databricks AI Functions](https://docs.databricks.com/aws/en/large-language-models/ai-functions).
Quail supports two of these dialects:

```python
session.sql(text, dialect="snowflake")  # AI_FILTER syntax
session.sql(text, dialect="bq")         # AI.IF syntax
```

Both compile to the same plan. The rest of this page uses the
BigQuery dialect.

## PROMPT

`PROMPT` combines a question template with document column references.
The placeholders `{0}`, `{1}`, and so on identify the columns in argument
order. Quail puts document text before the question in the model's input
so it can reuse document computations across questions.

For a filter, the prompt references one column:

```sql
PROMPT('Does this review discuss the ending of the movie?\n\n{0}', r.body)
```

Here `{0}` identifies each review's `body` text.

For a join, the prompt references one column from each table:

```sql
PROMPT('Does the review discuss this aspect?\n\nReview: {0}\nAspect: {1}',
       r.body, a.aspect)
```

Here `{0}` is the review and `{1}` is the aspect, and the model
answers for every pair.

## AI operators

### AI.IF

`AI.IF` takes a `PROMPT` and evaluates it on each row or each pair
of rows. The model returns TRUE or FALSE.

#### Filtering

Use `AI.IF` in a `WHERE` clause to filter rows:

```sql
SELECT r.id
FROM reviews r
WHERE AI.IF(PROMPT('Does this review mention a positive aspect?\n\n{0}', r.body))
  AND AI.IF(PROMPT('Does this review discuss the ending?\n\n{0}', r.body))
```

You can chain multiple filters with `AND`. Quail requires all
filters on one table to read the same document column, so it can
compute the document's model state once and reuse it across filters.

#### Joining

Use `AI.IF` to join two tables with a natural language condition.
The model evaluates the prompt on each pair of rows.

```sql
SELECT r.id, a.aspect
FROM reviews r, aspects a
WHERE AI.IF(PROMPT('Does the review discuss this aspect?\n\nReview: {0}\nAspect: {1}',
                   r.body, a.aspect))
```

You can also add relational predicates on `ON` to restrict which
pairs the model sees. You can add more than one.

```sql
SELECT c.id, e.id
FROM claims c
JOIN evidence e
  ON c.wiki_url = e.id
 AND AI.IF(PROMPT('Does the passage support the claim?\n\nClaim: {0}\nPassage: {1}',
                  c.claim, e.text))
```

Here the model only evaluates pairs where `c.wiki_url = e.id`,
instead of the full cross product.

#### EXISTS and NOT EXISTS

`EXISTS` and `NOT EXISTS` are semi-join operators. For each row in
the outer table, the subquery runs against the inner table.
`EXISTS` keeps the outer row if the subquery returns at least one
match. `NOT EXISTS` keeps it if the subquery returns no matches.

This `EXISTS` query finds reviews that discuss at least one aspect:

```sql
SELECT r.id
FROM reviews r
WHERE EXISTS (
    SELECT 1 FROM aspects a
    WHERE AI.IF(PROMPT('Does the review discuss this aspect?\n\nReview: {0}\nAspect: {1}',
                       r.body, a.aspect)))
```

This `NOT EXISTS` query finds reviews that do *not* discuss any of
the listed aspects:

```sql
SELECT r.id
FROM reviews r
WHERE NOT EXISTS (
    SELECT 1 FROM aspects a
    WHERE AI.IF(PROMPT('Does the review discuss this aspect?\n\nReview: {0}\nAspect: {1}',
                       r.body, a.aspect)))
```

The subquery must be `SELECT 1 FROM <table> WHERE AI.IF(...)`.

#### Options

Both `AI.IF` and `AI_FILTER` accept an optional second argument with
planning hints:

```sql
AI.IF(PROMPT(...), {'selectivity': 0.3, 'anchor': 'r'})
AI_FILTER(PROMPT(...), {'selectivity': 0.3, 'anchor': 'r'})
```

- **`selectivity`** estimates the fraction of rows or pairs that pass.
  Quail uses it to choose filter and join order. An inaccurate estimate
  can produce a slower plan, but does not change predicate answers.
  The default is `0.2`, meaning 20%.
- **`anchor`** (joins only): optional. When evaluating a join, Quail
  picks one side to process first and keep in GPU memory, so those
  documents are not reprocessed for each pair. This side is called
  the *anchor*. You usually want it to be the table with longer
  documents. If omitted, Quail chooses automatically to minimize
  query cost.

### AI.SCORE

`AI.SCORE(PROMPT(...))` returns a score between 0 and 1 as a
`FLOAT64`. Higher scores mean the model more strongly favors "yes" over
"no" for the prompt. Use it in `SELECT` to return scores, or compare it
with a threshold in `WHERE` or `JOIN ... ON`.

All models on the [supported models page](/docs/user-guide/models) can
run `AI.SCORE`. For example, select a reranker with:

```python
config = quail.EngineConfig(
    model="qwen3-reranker-0.6b-bf16",
    device="h100-sxm",
)
```

Rerankers score the model's preference for "yes" over "no". The Qwen3
FP8 models and DiffusionGemma score TRUE against FALSE using the `AI.IF`
prompt layout. [Decision 2.0 Kai](/docs/user-guide/models#decision-20-kai-06b)
returns the probability of "Yes" when choosing between "Yes" and "No".

`AI.SCORE(...) > 0.5` can select different rows from `AI.IF(...)`, because
they use different execution paths. Validate the chosen operator and
threshold on labeled examples for your task.

#### Return scores

Give the score column a name with `AS`:

```sql
SELECT d.id,
       AI.SCORE(PROMPT('Does the customer request a refund? {0}', d.body))
           AS refund_score
FROM documents d
```

#### Filter rows

Compare the score with `<`, `<=`, `>`, or `>=`. The threshold may be
on either side of the comparison:

```sql
SELECT d.id
FROM documents d
WHERE AI.SCORE(
    PROMPT('Does the customer request a refund? {0}', d.body),
    {'selectivity': 0.1}
) >= 0.75
```

The optional `selectivity` hint estimates the fraction of rows that pass
the comparison. Quail uses it to order filters and assumes 20% if omitted.
The hint does not change the scores or threshold.

#### Join tables

For a prompt with two document arguments, a reranker includes the first in
its query and uses the second as its candidate document. A generative
model reads the pair in the `AI.IF` join layout. The
template mentions `{0}` once, where that document is inserted; refer to
it again in words:

```sql
SELECT q.id, d.id
FROM queries q
JOIN documents d ON AI.SCORE(
    PROMPT('Is {1} relevant to {0}?', q.text, d.body)
) >= 0.8
```

A pair score returned in `SELECT` without a comparison runs over
every pair, so write the tables with `CROSS JOIN`. An `ON` column
equality narrows the pairs only when the score is compared in `ON`.

In the reranker's query text, a placeholder that stands alone at the
start or end of the template marks where the document goes and is
left out, since the reranker holds the document in its own field. A
placeholder inside a sentence reads "this document".

When the same score appears in `SELECT`, a filter, or a join condition,
Quail computes it once. Two comparisons of one score, such as a range,
share that one computation. A query cannot combine `AI.SCORE` with
`AI.IF`.

#### Score definition

Quail computes the score from the model's `yes` and `no` logits:

```text
score = exp(yes_logit) / (exp(yes_logit) + exp(no_logit))
```

A generative model uses its highest TRUE and FALSE logits, over the
spellings `TRUE`, `True`, and their space-prefixed forms, in place of
`yes` and `no`. A reranker is trained to give this score; a generative
model is not, so the same threshold can select different fractions of
rows on different models.

A score of 0.75 does not mean 75% accuracy. Choose the threshold using
labeled examples for your task.

### AI.CLASSIFY

`AI.CLASSIFY` assigns one of your supplied categories to each input row.
For example, for a `reviews` table with text in `body`, this query returns
a sentiment label alongside each review ID:

```sql
SELECT r.id,
       AI.CLASSIFY(r.body, ARRAY['positive', 'negative', 'mixed']) AS sentiment
FROM reviews r;
```

#### Syntax

`AI.CLASSIFY(input, categories[, options])`

#### Arguments

| Argument | Type | Description |
| --- | --- | --- |
| `input` | `STRING` column or `PROMPT` | The document to classify. A `PROMPT` can add a question or refer to two documents. |
| `categories` | `ARRAY` or table name | 2 to 255 labels, each with an optional description. Labels must not be empty, and two labels must not differ only in case. |
| `options` | Object | Optional settings, such as `{'probabilities': true}`. |

`categories` can have one of these forms:

- Strings: `ARRAY['refund', 'praise']`.
- Label and description pairs: `ARRAY[('refund', 'asks for money back'), ('praise', NULL)]`.
- Objects: `ARRAY[{'label': 'refund', 'description': 'asks for money back'}, {'label': 'praise'}]`.
- A registered table name: `kinds`. The table has a `label` column, and
  it can have a `description` column and an integer `ordinal` column.
  Quail sorts the labels by `ordinal` if the column exists, and by label
  text if not.

A description tells what a category means, in 25 words or fewer. You
can also name the argument: `categories => ARRAY['refund', 'praise']`.

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `task_description` | `STRING` | Empty | Extra instructions, up to 50 words. |
| `selectivity` | `FLOAT` | `0.2` | Estimated fraction of rows kept by a `WHERE` condition on the classification result. |
| `probabilities` | `BOOLEAN` | `false` | Also returns the probability of each category. |

#### Output

The result is a `STRING` containing one supplied label. Use `AS` to name
the result column. With `probabilities` set to `true`, Quail also returns
`<name>_probabilities`, a `MAP<STRING, DOUBLE>` from each label to its
probability. The probabilities sum to 1. They describe the model's relative preference
among the supplied categories; they are not measured accuracy for your task.

- When two labels have the same score, Quail returns the label that is
  first in the list.
- With vLLM or SGLang, a row whose generated answer matches no label is
  not in the result.

For how Quail reads the label, see
[label scoring](/docs/architecture/execution#label-scoring).

#### Inspect classification answers

The result rows contain the classification columns selected by the query.
You can also read the model's labels from `result.answer_tables`, including
labels for rows removed by a later filter.

For example, after running the sentiment query above, read its labels with:

```python
result = query.run()
labels = result.answer_tables["classifies"]["sentiment"]
print(labels.to_pydict())
```

The answer table contains `r` and `sentiment`. The `r` values are input row
indices starting at zero, rather than the review IDs in `r.id`.
For classifications of joined rows, the answer table includes an index
column for each table alias. It can contain more rows than the final result
because it includes labels computed before later filters.

#### Examples

##### Classify reviews

Ask for each review's sentiment and return the label alongside its text:

```sql
SELECT r.id, r.body,
       AI.CLASSIFY(
           PROMPT('What sentiment does this review express? {0}', r.body),
           ARRAY['positive', 'negative', 'mixed']) AS sentiment
FROM reviews r;
```

Example output:

```text
id  body                                     sentiment
1   The food was delicious.                   positive
2   My order arrived cold.                    negative
3   Great food, but the delivery was late.    mixed
```

##### Keep selected categories

Use `IN` in `WHERE` to keep negative or mixed reviews:

```sql
SELECT r.id,
       AI.CLASSIFY(PROMPT('What sentiment does this review express? {0}', r.body),
                   ARRAY['positive', 'negative', 'mixed']) AS sentiment
FROM reviews r
WHERE AI.CLASSIFY(PROMPT('What sentiment does this review express? {0}', r.body),
                  ARRAY['positive', 'negative', 'mixed'])
      IN ('negative', 'mixed');
```

Example output for the same reviews:

```text
id  sentiment
2   negative
3   mixed
```

- `=` keeps one category. Other comparisons raise `CompileError`.
- A category that is not in the list matches no rows.
- Quail classifies each review one time. The same label decides the
  `WHERE` condition and fills the `sentiment` column.
- In `SELECT`, the call must be its own item, not part of a larger
  expression.

##### Return probabilities

Set `probabilities` to `true` to include a probability for every category:

```sql
SELECT r.id,
       AI.CLASSIFY(PROMPT('What sentiment does this review express? {0}', r.body),
                   ARRAY['positive', 'negative', 'mixed'],
                   {'probabilities': true}) AS sentiment
FROM reviews r;
```

One example output row:

```text
id  sentiment  sentiment_probabilities
1   positive   {'positive': 0.90, 'negative': 0.03, 'mixed': 0.07}
```

Only the Quail backend returns probabilities, and only for a
classification of one document. It does not return them for joined
rows, or with vLLM or SGLang.

##### Classify joined rows

A classification can also label a pair of documents kept by an `AI.IF`
join. Use a `PROMPT` that refers to both documents.

For example, suppose a `reviews` table contains review text and an
`aspects` table contains movie aspects. This query first finds the aspects
each review discusses, then classifies its opinion of each matched aspect:

```sql
SELECT r.id, a.aspect,
       AI.CLASSIFY(
           PROMPT('What is the opinion of the review about the aspect? {0} {1}',
                  r.body, a.aspect),
           ARRAY['positive', 'negative', 'mixed']) AS opinion
FROM reviews r
JOIN aspects a ON AI.IF(
    PROMPT('Does the review discuss this aspect? {0} {1}', r.body, a.aspect));
```

These limits apply:

- With the Quail backend, the classification and its `AI.IF` join run on
  one GPU.
- A `WHERE` condition cannot test the label of a joined row.
- A query cannot classify joined rows and also use `AI.SCORE`.

See [classifying joined rows](/docs/architecture/execution#classifying-joined-rows).

## SELECT, FROM, JOIN, LIMIT

Quail supports these SQL clauses with the following limits:

- **`SELECT`** lists columns and `AI.SCORE` or `AI.CLASSIFY`
  outputs with column aliases. `*` expands to all table columns. Other computed expressions
  are unsupported.
- **`FROM`** names a registered table, with an optional alias.
- **`JOIN`** and `CROSS JOIN` are supported. Outer joins (`LEFT`,
  `RIGHT`, `FULL`) are not.
- **`LIMIT`** takes a positive integer.

## Unsupported SQL operators (for now)

- `GROUP BY`, `ORDER BY`, `DISTINCT`, `HAVING`, window functions
- `UNION`, `EXCEPT`, `INTERSECT`, `OFFSET`
- `OR` between AI predicates
- Queries with no AI operator
- `JOIN` with only relational predicates (no AI operator)
- Outer joins (`LEFT`, `RIGHT`, `FULL`)

Using any of these raises `quail.logical.CompileError`.
