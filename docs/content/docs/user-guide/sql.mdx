## AI-SQL

Quail can filter, score, and classify documents in SQL. It accepts two
SQL dialects:

```python
session.sql(text, dialect="snowflake")  # AI_FILTER
session.sql(text, dialect="bq")         # AI.IF
```

The examples below use `dialect="bq"`.

## PROMPT

`PROMPT(template, column, ...)` defines a question about the supplied
columns. `{0}` refers to the first column, `{1}` to the second, and so on.
For generative models, Quail places documents before the question so
later questions can reuse their saved model state. See
[prompt binding](/docs/architecture/logical-plans#prompt-binding).

For a filter, the prompt references one column:

```sql
PROMPT('Does this review discuss the ending of the movie?\n\n{0}', r.body)
```

For a join, the prompt references one column from each table:

```sql
PROMPT('Does the review discuss this aspect?\n\nReview: {0}\nAspect: {1}',
       r.body, a.aspect)
```

The model evaluates the question for each document pair.

## AI operators

| Function | Description | Return type |
| --- | --- | --- |
| `AI.IF(prompt[, options])` | Tests a condition on a document or document pair. | `BOOLEAN` |
| `AI.SCORE(prompt[, options])` | Scores a document or document pair against a condition. | `FLOAT64` |
| `AI.CLASSIFY(input, categories[, options])` | Assigns a label from a category list. | `STRING` |

### AI.IF

`AI.IF(prompt[, options])`

Returns `TRUE` or `FALSE` for a condition on a document or document pair.
The Snowflake dialect uses `AI_FILTER`.

#### Filtering

Use `AI.IF` in a `WHERE` clause to filter rows:

```sql
SELECT r.id
FROM reviews r
WHERE AI.IF(PROMPT('Does this review mention a positive aspect?\n\n{0}', r.body))
  AND AI.IF(PROMPT('Does this review discuss the ending?\n\n{0}', r.body))
```

You can chain multiple filters with `AND`. Quail requires all
filters on one table to read the same document column, so it can
compute the document's model state once and reuse it across filters.

#### Joining

Use `AI.IF` to join two tables with a natural language condition.
The model evaluates the prompt on each pair of rows.

```sql
SELECT r.id, a.aspect
FROM reviews r, aspects a
WHERE AI.IF(PROMPT('Does the review discuss this aspect?\n\nReview: {0}\nAspect: {1}',
                   r.body, a.aspect))
```

You can also add relational predicates on `ON` to restrict which
pairs the model sees. You can add more than one.

```sql
SELECT c.id, e.id
FROM claims c
JOIN evidence e
  ON c.wiki_url = e.id
 AND AI.IF(PROMPT('Does the passage support the claim?\n\nClaim: {0}\nPassage: {1}',
                  c.claim, e.text))
```

Here the model only evaluates pairs where `c.wiki_url = e.id`,
instead of the full cross product.

#### EXISTS and NOT EXISTS

`EXISTS` and `NOT EXISTS` are semi-join operators. For each row in
the outer table, the subquery runs against the inner table.
`EXISTS` keeps the outer row if the subquery returns at least one
match. `NOT EXISTS` keeps it if the subquery returns no matches.

This `EXISTS` query finds reviews that discuss at least one aspect:

```sql
SELECT r.id
FROM reviews r
WHERE EXISTS (
    SELECT 1 FROM aspects a
    WHERE AI.IF(PROMPT('Does the review discuss this aspect?\n\nReview: {0}\nAspect: {1}',
                       r.body, a.aspect)))
```

This `NOT EXISTS` query finds reviews that do *not* discuss any of
the listed aspects:

```sql
SELECT r.id
FROM reviews r
WHERE NOT EXISTS (
    SELECT 1 FROM aspects a
    WHERE AI.IF(PROMPT('Does the review discuss this aspect?\n\nReview: {0}\nAspect: {1}',
                       r.body, a.aspect)))
```

The subquery must be `SELECT 1 FROM <table> WHERE AI.IF(...)`.

#### Options

Both `AI.IF` and `AI_FILTER` accept an optional second argument with
planning hints:

```sql
AI.IF(PROMPT(...), {'selectivity': 0.3, 'anchor': 'r'})
AI_FILTER(PROMPT(...), {'selectivity': 0.3, 'anchor': 'r'})
```

- **`selectivity`**: optional. Your estimate of the fraction of rows
  that will pass. It does not need to be accurate. Quail uses it to
  decide which filters and joins to run first. If you leave it out,
  Quail assumes 20% of rows pass.
- **`anchor`** (joins only): optional. When evaluating a join, Quail
  picks one side to process first and keep in GPU memory, so those
  documents are not reprocessed for each pair. This side is called
  the *anchor*. You usually want it to be the table with longer
  documents. If omitted, Quail chooses automatically to minimize
  query cost.

### AI.SCORE

`AI.SCORE(prompt[, options])`

Returns a `FLOAT64` between 0 and 1. Higher scores mean the model
favors "yes" more strongly. Return scores in `SELECT` or compare them
with a threshold in `WHERE` or `JOIN ... ON`.

All supported models can run `AI.SCORE`, including rerankers:

```python
config = quail.EngineConfig(
    model="qwen3-reranker-0.6b-bf16",
    device="h100-sxm",
)
```

- Rerankers use a prompt that asks whether the document meets the
  query's requirements, with "yes" and "no" as the answers.
- Generative models use the `AI.IF` prompt and compare TRUE with FALSE.
  `AI.SCORE` and `AI.IF` run through different execution code, so a
  score above 0.5 can disagree with an `AI.IF` answer.

Use `gpus` to run a model copy on each GPU.

#### Return scores

Give the score column a name with `AS`:

```sql
SELECT d.id,
       AI.SCORE(PROMPT('Does the customer request a refund? {0}', d.body))
           AS refund_score
FROM documents d
```

#### Filter rows

Compare the score with `<`, `<=`, `>`, or `>=`. The threshold may be
on either side of the comparison:

```sql
SELECT d.id
FROM documents d
WHERE AI.SCORE(
    PROMPT('Does the customer request a refund? {0}', d.body),
    {'selectivity': 0.1}
) >= 0.75
```

`selectivity` estimates how many rows pass the threshold. Quail uses
it to order filters and defaults to `0.2`. It does not affect the scores.

#### Join tables

For a two-document prompt, a reranker includes the first document in its
query and scores the second document against it. A generative model uses
the `AI.IF` join layout. Use `{0}` once in the template. Refer to that document by name if you
need to mention it again:

```sql
SELECT q.id, d.id
FROM queries q
JOIN documents d ON AI.SCORE(
    PROMPT('Is {1} relevant to {0}?', q.text, d.body)
) >= 0.8
```

To return a score for every document pair, use `CROSS JOIN`. To restrict
pairs by column equality, put both the equality and score comparison
in `ON`.

For rerankers, a placeholder at the start or end of the template is
removed because the document is passed separately. Inside a sentence,
the placeholder becomes "this document".

When the same `AI.SCORE` call appears more than once, Quail evaluates
it once per document or pair. A query cannot combine `AI.SCORE` with `AI.IF`.

#### Score definition

Quail computes the score from the model's `yes` and `no` logits:

```text
score = exp(yes_logit) / (exp(yes_logit) + exp(no_logit))
```

For generative models, `yes_logit` is the highest TRUE token logit
and `no_logit` is the highest FALSE token logit, including alternative
spellings and space-prefixed forms. Rerankers are trained to produce
these scores. The same threshold can select different rows on
different models.

A score of 0.75 does not mean 75% accuracy. Choose the threshold using
labeled examples for your task.

### AI.CLASSIFY

`AI.CLASSIFY(input, categories[, options])`

Returns one of the supplied labels as a `STRING`. Use it in `SELECT`
to return labels, or with `=` and `IN` in `WHERE` to filter rows.
When the same `AI.CLASSIFY` call appears in `SELECT` and `WHERE`,
Quail evaluates it once per document. Classification requires a
generative model.

#### Parameters

| Parameter | Description |
| --- | --- |
| `input` | A document column or `PROMPT`. Use a two-document prompt to classify pairs. |
| `categories` | A list or registered table of 2 to 255 nonempty labels. Labels must be unique ignoring case. |
| `options` | Optional task description, selectivity estimate, and output mode. |

Categories can be supplied as:

- Strings: `ARRAY['refund', 'praise']`.
- Label and description pairs: `ARRAY[('refund', 'asks for money back'), ('praise', NULL)]`.
- Objects: `ARRAY[{'label': 'refund', 'description': 'asks for money back'}, {'label': 'praise'}]`.
- A registered label table: `kinds`.

Each description may contain up to 25 words. A label table needs a
`label` column. Optional columns are `description` and an integer
`ordinal`. Quail sorts labels by `ordinal` if present, otherwise by
label text. You can also name the category argument:
`categories => ARRAY['refund', 'praise']`.

#### Options

| Option | Default | Description |
| --- | --- | --- |
| `task_description` | Empty | Extra instructions added after the question, up to 50 words. |
| `selectivity` | `0.2` | Estimated fraction of rows kept by a label filter. |
| `output_mode` | `'single'` | One label per document. Other modes are unsupported. |
| `probabilities` | `false` | Adds `<name>_probabilities`, a `MAP<STRING, DOUBLE>` from each label to its probability. |

When label scores tie, Quail chooses the label listed first. See
[scoring methods](/docs/architecture/planning#choosing-classification-scoring).

The vLLM and SGLang backends generate label text. If Quail cannot
match the answer to a supplied label, it leaves that row out of the
result. For example, "other" matches neither "refund" nor "praise".

#### Examples

Return each review's sentiment. Use `AS` to name the label column.
The `AI.CLASSIFY` call must be a separate item in `SELECT`. It cannot
be nested inside another expression.

```sql
SELECT r.id,
       AI.CLASSIFY(
           PROMPT('What sentiment does this review express? {0}', r.body),
           ARRAY['positive', 'negative', 'neutral', 'mixed']) AS sentiment
FROM reviews r;
```

Return sentiment labels and keep negative or mixed reviews. Label
filters support `=` and `IN`. A label outside the supplied list matches
no rows. Other comparisons raise `CompileError`.

```sql
SELECT r.id,
       AI.CLASSIFY(PROMPT('What sentiment does this review express? {0}', r.body),
                   ARRAY['positive', 'negative', 'neutral', 'mixed']) AS sentiment
FROM reviews r
WHERE AI.CLASSIFY(PROMPT('What sentiment does this review express? {0}', r.body),
                  ARRAY['positive', 'negative', 'neutral', 'mixed'])
      IN ('negative', 'mixed');
```

Classify a document column with a task description:

```sql
SELECT r.id,
       AI.CLASSIFY(r.body, ARRAY['refund', 'praise'],
                   {'task_description': 'Classify the customer request.'}) AS kind
FROM reviews r;
```

Set `probabilities` to `true` to return a probability for every label.
The example adds `topic_probabilities` beside `topic`, such as
`{'refund': 0.91, 'shipping': 0.07, 'praise': 0.02}`. The probabilities
sum to 1 across the supplied labels. Returning probabilities does not
require another model forward pass.

Probabilities are unsupported for document pairs and on the vLLM and
SGLang backends.

```sql
SELECT r.id,
       AI.CLASSIFY(PROMPT('What is the request about? {0}', r.body),
                   ARRAY['refund', 'shipping', 'praise'],
                   {'probabilities': true}) AS topic
FROM reviews r;
```

Return a numeric score and a label:

```sql
SELECT r.id,
       AI.SCORE(PROMPT('Does the customer request a refund? {0}', r.body)) AS refund_score,
       AI.CLASSIFY(PROMPT('What is the request about? {0}', r.body),
                   ARRAY['refund', 'shipping', 'praise']) AS topic
FROM reviews r;
```

Classify each review's sentiment about a matched aspect. Each prompt
uses one column from each table. Refer to the documents as
`DOCUMENT {0}` and `DOCUMENT {1}`.

```sql
SELECT r.id, a.id,
       AI.CLASSIFY(
           PROMPT('What sentiment does DOCUMENT {0} express about DOCUMENT {1}?',
                  r.body, a.aspect),
           ARRAY['positive', 'negative', 'neutral', 'mixed']) AS aspect_sentiment
FROM reviews r
JOIN aspects a
  ON AI.IF(PROMPT('Does DOCUMENT {0} discuss DOCUMENT {1}?', r.body, a.aspect));
```

With the Quail backend, pair classification must run on one GPU in the
same pipeline as its AI join. You cannot filter pair labels in `WHERE`,
return multiple independent pair classifications, or combine pair
classification with `AI.SCORE`. See
[joined classification execution](/docs/architecture/execution#classifying-joined-rows).

### AI.EXTRACT

<Callout type="info">Not implemented.</Callout>

Pull structured fields out of each document, like Snowflake's
[AI_EXTRACT](https://docs.snowflake.com/en/user-guide/snowflake-cortex/aisql).
Example:

```sql
SELECT AI.EXTRACT(r.body, 'movie_title', 'rating') AS extracted
FROM reviews r
```

### AI.MAP

<Callout type="info">Not implemented.</Callout>

Run a free-form instruction on each document and return the generated
text, like Snowflake's
[AI_COMPLETE](https://docs.snowflake.com/en/user-guide/snowflake-cortex/aisql).
Example:

```sql
SELECT AI.MAP('Summarize this review in one sentence.\n\n{0}', r.body) AS summary
FROM reviews r
```

## SELECT, FROM, JOIN, LIMIT

The following SQL clauses are supported:

- **`SELECT`** lists columns and named `AI.SCORE` or `AI.CLASSIFY`
  outputs. `*` expands to all table columns. Other computed expressions
  are unsupported.
- **`FROM`** names a registered table, with an optional alias.
- **`JOIN`** and `CROSS JOIN` are supported. Outer joins (`LEFT`,
  `RIGHT`, `FULL`) are not.
- **`LIMIT`** takes a positive integer.

## Unsupported SQL operators

- `GROUP BY`, `ORDER BY`, `DISTINCT`, `HAVING`, window functions
- `UNION`, `EXCEPT`, `INTERSECT`, `OFFSET`
- `OR` between AI predicates
- Queries with no AI predicate
- `JOIN` with only relational predicates (no AI operator)
- Outer joins (`LEFT`, `RIGHT`, `FULL`)

Using any of these raises `quail.logical.CompileError`.
