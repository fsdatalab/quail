AI functions ask a [model](/docs/user-guide/models) about the text in
each row and return its answer as a SQL value.

| Function | Description |
| --- | --- |
| [`PROMPT(template, value, ...)`](#prompttemplate-value-) | The text the model reads: the template with each `{n}` replaced by a value. |
| [`AI.IF(prompt[, options])`](#aiifprompt-options) | `TRUE` or `FALSE`: the model's answer to a yes-or-no question. |
| [`AI.SCORE(prompt[, options])`](#aiscoreprompt-options) | A score from 0 to 1: how strongly the model answers yes. |
| [`AI.CLASSIFY(input, categories[, options])`](#aiclassifyinput-categories-options) | One label from `categories`. |
| [`AI.EXTRACT(input, questions)`](#aiextractinput-questions) | A struct of answers copied from the document. |
| [`AI.EXTRACT_SPAN(input, questions)`](#aiextract_spaninput-questions) | A struct of the positions of those answers. |
| [`AI.MAP(input, instruction[, max_tokens])`](#aimapinput-instruction-max_tokens) | Text the model writes for each document. |
| [`AI.SAE_FEATURES(prompt, options)`](#aisae_featuresprompt-options) | A list of features and their strengths. |
| [`HINT(condition, options)`](#hintcondition-options) | The value of `condition`, with an estimate of how many rows pass it. |

## Example tables

Every example on this page reads these two tables. A model's answer is
not fixed, so each result shows what one model returned.

`reviews`:

| id | body |
| --- | --- |
| 1 | The ending was perfect and the cast was great. |
| 2 | Too long, and the ending made no sense. |
| 3 | Great music, but I want my money back. |

`aspects`:

| id | aspect |
| --- | --- |
| 1 | ending |
| 2 | music |

The examples use the default Snowflake dialect. With `dialect="bq"`,
write an options object such as `{'selectivity': 0.3}` as
`STRUCT(0.3 AS selectivity)`.

## Functions

### `PROMPT(template, value, ...)`

```sql
SELECT r.id
FROM reviews r
WHERE AI.IF(PROMPT('Does the review discuss the ending? {0}', r.body));
```

| | |
| --- | --- |
| **Description** | Builds the text the model reads. `{0}` is the first value after the template, `{1}` the second. Every value needs a placeholder. |
| **Result** | `(1)`, `(2)` |
| **Values** | Columns of one table form one document, and the same column may appear twice. Columns of two tables form a pair; see [Joining](#joining). |

### `AI.IF(prompt[, options])`

```sql
SELECT r.id
FROM reviews r
WHERE AI.IF(PROMPT('Does the reviewer ask for a refund? {0}', r.body));
```

| | |
| --- | --- |
| **Description** | Returns `TRUE` or `FALSE`. In `WHERE`, keeps the rows the model answers yes for; `NOT AI.IF(...)` keeps the others. |
| **Result** | `(3)` |
| **Alias** | `AI_FILTER` |
| **Options** | `selectivity`, `anchor`; see [Options](#options). |

### `AI.SCORE(prompt[, options])`

```sql
SELECT r.id,
       AI.SCORE(PROMPT('Does the reviewer ask for a refund? {0}', r.body)) AS refund
FROM reviews r;
```

| | |
| --- | --- |
| **Description** | Returns a `FLOAT64` from 0 to 1. A higher score is a stronger yes. A score is not a probability of being right; choose a threshold from labeled examples. |
| **Result** | `(1, 0.02)`, `(2, 0.1)`, `(3, 0.94)` |
| **Alias** | `AI_SCORE` |
| **Options** | `selectivity`; see [Options](#options). |

### `AI.CLASSIFY(input, categories[, options])`

```sql
SELECT r.id,
       AI.CLASSIFY(r.body, ['positive', 'negative', 'mixed']) AS sentiment
FROM reviews r;
```

| | |
| --- | --- |
| **Description** | Returns one label from `categories` as a `STRING`. |
| **Result** | `(1, 'positive')`, `(2, 'negative')`, `(3, 'mixed')` |
| **Alias** | `AI_CLASSIFY` |
| **input** | A text column, or a `PROMPT` over one document or a pair. |
| **categories** | At least two labels that differ ignoring case. Labels can carry descriptions of at most 25 words; give every label one: `[{'label': 'refund', 'description': 'asks for money back'}, ...]`. |
| **Options** | `selectivity`, `task_description`, `probabilities`; see [Options](#options). |

### `AI.EXTRACT(input, questions)`

```sql
SELECT r.id,
       AI.EXTRACT(r.body, {'complaint': 'What does the reviewer complain about?'})
           AS answers
FROM reviews r;
```

| | |
| --- | --- |
| **Description** | Returns a struct with one `STRING` field per question, holding text copied from the document. A field is `NULL` when the document has no answer. Read a field as `AI.EXTRACT(...)['complaint']`. |
| **Result** | `(1, {complaint: NULL})`, `(2, {complaint: 'the ending made no sense'})`, `(3, {complaint: 'I want my money back'})` |
| **Alias** | `AI_EXTRACT` |
| **input** | A text column. |
| **questions** | An object from field names to questions. |

### `AI.EXTRACT_SPAN(input, questions)`

```sql
SELECT r.id,
       AI.EXTRACT_SPAN(r.body, {'complaint': 'What does the reviewer complain about?'})
           AS spans
FROM reviews r;
```

| | |
| --- | --- |
| **Description** | Returns the struct `AI.EXTRACT` returns for the same arguments, with each field a span: `start` and `end` character positions. `end` is one past the last character, so Python's `body[start:end]` is the answer. |
| **Result** | `(1, {complaint: NULL})`, `(2, {complaint: {start: 14, end: 38}})`, `(3, {complaint: {start: 17, end: 37}})` |
| **Alias** | `AI_EXTRACT_SPAN` |

### `AI.MAP(input, instruction[, max_tokens])`

```sql
SELECT r.id,
       AI.MAP(r.body, 'Summarize the review in one sentence.', 32) AS summary
FROM reviews r;
```

| | |
| --- | --- |
| **Description** | Returns the `STRING` the model writes for the document, with no whitespace around it. |
| **Result** | `(1, 'Praises the ending and the cast.')`, `(2, 'Says the film is too long and the ending makes no sense.')`, `(3, 'Likes the music but wants a refund.')` |
| **Alias** | `AI_MAP` |
| **input** | A text column. |
| **instruction** | A string literal. |
| **max_tokens** | The most tokens in an answer: an integer from 1 to 32768. Default: 256. |

### `AI.SAE_FEATURES(prompt, options)`

```sql
SELECT r.id,
       AI.SAE_FEATURES(PROMPT('{0} What does the reviewer want?', r.body),
                       {'pooling': 'last'}) AS features
FROM reviews r;
```

| | |
| --- | --- |
| **Description** | Returns a list of `{feature, strength}` structs from a sparse autoencoder (SAE), strongest first. A feature is an integer ID with no text label. A strength is a nonnegative activation, not a probability. |
| **Result** | `(1, [{feature: 18113, strength: 6.2}, {feature: 902, strength: 2.4}, ...])`, and so on for each row. |
| **Alias** | `AI_SAE_FEATURES` |
| **prompt** | A `PROMPT` over one document column. |
| **pooling** | `'last'`: the features of the prompt's last token, at most 100. `'max'`: each feature's largest strength over all tokens, often thousands. |
| **Model** | `qwen3.5-2b-sae-bf16` only. That model runs no other AI function. |

### `HINT(condition, options)`

```sql
SELECT r.id
FROM reviews r
WHERE HINT(AI.CLASSIFY(r.body, ['positive', 'negative', 'mixed']) = 'negative',
           {'selectivity': 0.3});
```

| | |
| --- | --- |
| **Description** | Returns the value of `condition`. The `selectivity` option estimates the fraction of rows that pass it. Quail uses the estimate to order work; it does not change which rows pass. |
| **Result** | `(2)` |
| **Options** | `selectivity` only. |

## Options

Pass options as an object, such as `{'selectivity': 0.3}`.

| Option | Functions | Meaning |
| --- | --- | --- |
| `selectivity` | `AI.IF`, `AI.SCORE`, `AI.CLASSIFY`, `HINT` | The fraction of rows or pairs expected to pass the test. Default: 0.2. It changes speed, not answers. |
| `anchor` | `AI.IF` in a join | The alias of the table whose rows the model reads first. Quail chooses one when it is omitted. |
| `task_description` | `AI.CLASSIFY` | Extra instructions for the model. |
| `probabilities` | `AI.CLASSIFY` | `true` adds a column `<alias>_probabilities` that maps each label to its probability. It appears only when the query returns the label directly, not when only `WHERE` reads it or SQL above groups it. |

## Joining

`AI.IF` in `ON` asks the model about each pair of rows. Its `PROMPT`
reads one column from each table.

```sql
SELECT r.id, a.aspect
FROM reviews r
JOIN aspects a
  ON AI.IF(PROMPT('Does the review discuss this aspect? {0} {1}', r.body, a.aspect));
```

Result: `(1, 'ending')`, `(2, 'ending')`, `(3, 'music')`.

- Add an equality, such as `ON r.id = a.id AND AI.IF(...)`, to ask only
  about pairs that match it.
- `AI.SCORE(...) >= 0.8` in `ON` keeps the pairs that score at least 0.8.
- `AI.CLASSIFY` over a `PROMPT` of two tables labels each pair.
- `LEFT`, `RIGHT`, and `FULL` joins keep their unmatched rows as usual.

## EXISTS and NOT EXISTS

An `AI.IF` in a subquery keeps the rows with at least one match
(`EXISTS`) or with none (`NOT EXISTS`).

```sql
SELECT r.id
FROM reviews r
WHERE NOT EXISTS (
    SELECT 1 FROM aspects a
    WHERE AI.IF(PROMPT('Does the review praise this aspect? {0} {1}',
                       r.body, a.aspect)));
```

Result: `(2)`. With `EXISTS`, the result is `(1)`, `(3)`.

## Filter by category

`WHERE` cannot read a `SELECT` alias. Repeat the call; the model answers
it once.

```sql
SELECT r.id,
       AI.CLASSIFY(r.body, ['positive', 'negative', 'mixed']) AS sentiment
FROM reviews r
WHERE AI.CLASSIFY(r.body, ['positive', 'negative', 'mixed']) IN ('negative', 'mixed');
```

Result: `(2, 'negative')`, `(3, 'mixed')`.

- Write the repeated call exactly the same way. Calls that differ only in
  case, whitespace, or punctuation are an error.
- A test that names a label outside `categories` is an error.

## Filter on answers

Every answer works in SQL like a column of its type.

```sql
SELECT r.id
FROM reviews r
WHERE AI.EXTRACT(r.body, {'complaint': 'What does the reviewer complain about?'})['complaint']
      LIKE '%ending%';
```

Result: `(2)`.

- Compare a score with `<`, `<=`, `>`, or `>=` and a number from 0 to 1.
- Test map text with `=`, `LIKE`, or `ILIKE`.
- A comparison drops `NULL` answers. Use `IS NULL` to keep them.
- A `LIMIT` stops the model once enough rows pass.

## NULL documents

An AI function of a `NULL` document returns `NULL`, and the model is not
asked. If `reviews` had a row `(4, NULL)`:

```sql
SELECT r.id, AI.CLASSIFY(r.body, ['positive', 'negative', 'mixed']) AS sentiment
FROM reviews r;
```

Result: `(1, 'positive')`, `(2, 'negative')`, `(3, 'mixed')`, `(4, NULL)`.

- `WHERE AI.IF(...)` and `WHERE NOT AI.IF(...)` both drop row 4.
- A `PROMPT` over several columns is `NULL` when any of them is.
- A pair with a `NULL` document matches nothing in a join, and its
  `AI.SCORE` is `NULL`.
- In `NOT EXISTS`, the model is still asked about a row whose document
  is `NULL`, with empty text.
