Examples use `dialect="bq"` and require registered input tables.
Choose a [model](/docs/user-guide/models) that supports the function.

## Functions

Square brackets mark optional arguments.

| Function | Answer |
| --- | --- |
| [`PROMPT(template, column, ...)`](#prompt) | Text for the model. |
| [`AI.IF(prompt[, options])`](#aiif) | Boolean. |
| [`AI.SCORE(prompt[, options])`](#aiscore) | Score from 0 to 1. |
| [`AI.CLASSIFY(input, categories[, options])`](#aiclassify) | One supplied label. |
| [`AI.EXTRACT(input, questions)`](#aiextract) | Struct of answers copied from the document. |
| [`AI.EXTRACT_SPAN(input, questions)`](#answer-positions) | Struct of answer spans. |
| [`AI.MAP(input, instruction[, max_tokens])`](#aimap) | Text answer. |
| [`AI.SAE_FEATURES(prompt, options)`](#aisae_features) | List of features and strengths. |
| [`HINT(condition, options)`](#planning-hints) | The condition's value, with a selectivity estimate for planning. |

## PROMPT

`PROMPT` inserts document columns into literal text. `{0}` refers to the
first column argument, `{1}` to the second.
E.g., `PROMPT('Does the review discuss the aspect? {0} {1}', r.body, a.aspect)`
reads a review and an aspect.

Arguments can read struct fields or apply
[text functions](/docs/user-guide/sql/sql-functions#column-expressions).

### Repeated calls

`WHERE` cannot read a `SELECT` alias. Repeat the AI call when a query
both returns and filters its answer. Quail computes the repeated answer
once within the model region.

Keep the arguments identical. For calls with the same function, columns,
and options, Quail rejects text that differs only in case, whitespace,
or punctuation. Near-identical text with a small spelling change can
raise `SimilarCallWarning`; those calls can produce different answers.

## AI.IF

`AI.IF(prompt[, options])` returns `TRUE` or `FALSE`.
`AI_FILTER` is its Snowflake spelling.

### Filtering

E.g., `reviews(id, body)` contains movie reviews. Keep reviews that
mention a positive aspect and discuss the ending:

```sql
SELECT r.id
FROM reviews r
WHERE AI.IF(PROMPT('Does this review mention a positive aspect? {0}', r.body))
  AND AI.IF(PROMPT('Does this review discuss the ending? {0}', r.body));
```

Use `AND` when every filter must pass. Calls that read the same document
can share model-region work. Other expression shapes use the
[SQL fallback](/docs/user-guide/sql/sql-functions#unsupported-sql).

`NOT AI.IF(...)` keeps the rows the model answers no for. It is the same
filter: Quail orders it by cost with the other filters, and a `LIMIT`
stops it early. `AI.IF(...) = FALSE` is the same test. A `selectivity`
option still gives the fraction of rows the model answers yes for. E.g., keep reviews that do not discuss the
ending:

```sql
SELECT r.id
FROM reviews r
WHERE NOT AI.IF(PROMPT('Does this review discuss the ending? {0}', r.body));
```

`NOT AI.IF(...)` over joined rows uses the SQL fallback.

E.g., if `reviews` also has a boolean `flagged` column, keep flagged
reviews or reviews that mention a refund:

```sql
SELECT r.id
FROM reviews r
WHERE r.flagged
   OR AI.IF(PROMPT('Does this review mention a refund? {0}', r.body));
```

For eligible same-input `AI.IF` disjunctions, Quail checks ordinary
conditions first and skips model calls once a term is `TRUE`. It can also
stop after the first passing AI term.

Other disjunctions, including score comparisons and predicates over joined
inputs, use the [SQL fallback](/docs/user-guide/sql/sql-functions#unsupported-sql)
when they cannot form an optimized model region. DataFusion evaluates the
condition over named AI answers; this path need not skip model calls just
because another term is already true.

### Joining

E.g., `claims(id, claim, wiki_url)` identifies passages in
`evidence(id, text)`. Ask the model only about pairs with matching IDs:

```sql
SELECT c.id, e.id
FROM claims c
JOIN evidence e
  ON c.wiki_url = e.id
 AND AI.IF(PROMPT('Does the passage support the claim? {0} {1}', c.claim, e.text));
```

Omit the equality to let the model consider every claim–passage pair.

### EXISTS and NOT EXISTS

E.g., return reviews that discuss at least one row in `aspects(id, aspect)`:

```sql
SELECT r.id
FROM reviews r
WHERE EXISTS (
    SELECT 1 FROM aspects a
    WHERE AI.IF(PROMPT('Does the review discuss this aspect? {0} {1}',
                       r.body, a.aspect)));
```

Replace `EXISTS` with `NOT EXISTS` to keep reviews with no matching aspect.

### Options

Pass an object as the second argument.
E.g., `{'selectivity': 0.3, 'anchor': 'c'}` for the join above.

| Option | Meaning |
| --- | --- |
| `selectivity` | Fraction of documents or pairs expected to pass. Default: `0.2`. It changes planning, not answers. |
| `anchor` | Join table alias whose document KV Quail reuses across pairs. Quail chooses it when omitted. |

## AI.SCORE

`AI.SCORE(prompt[, options])` returns a `FLOAT64` from 0 to 1.
Higher scores mean a stronger preference for a positive answer.
A score of 0.75 does not mean the model is correct 75% of the time.
Choose thresholds using labeled examples.

### Return scores

E.g., score refund requests in `documents(id, body)`:

```sql
SELECT d.id,
       AI.SCORE(PROMPT('Does the customer request a refund? {0}', d.body))
           AS refund_score
FROM documents d;
```

### Filter rows

Compare a score with `<`, `<=`, `>`, or `>=` and a threshold from 0 to 1.
E.g., keep scores of at least 0.75:

```sql
SELECT d.id
FROM documents d
WHERE AI.SCORE(PROMPT('Does the customer request a refund? {0}', d.body),
               {'selectivity': 0.1}) >= 0.75;
```

`selectivity` estimates the fraction passing the comparison.
It does not change scores.

### Join tables

E.g., match `queries(id, text)` to relevant `documents(id, body)`:

```sql
SELECT q.id, d.id
FROM queries q
JOIN documents d ON AI.SCORE(
    PROMPT('Is {1} relevant to {0}?', q.text, d.body)) >= 0.8;
```

The optimized pair-scoring path uses `{0}` exactly once. Other prompt
shapes use the SQL fallback over materialized pairs.
Use `CROSS JOIN` with `AI.SCORE` in `SELECT` to return unfiltered pair scores.
A query can combine `AI.SCORE`, `AI.IF`, and `AI.CLASSIFY`; incompatible
operators run in separate model regions. The configured model must support
the requested operations.

### Model behavior

See [Models](/docs/user-guide/models) for supported configurations.
Rerankers interpret the first prompt document as a search query.
[Decision 2.0 Kai](/docs/user-guide/models#decision-20-kai-06b) returns its
probability of Yes. The SAE model does not support scores.

## AI.CLASSIFY

`AI.CLASSIFY(input, categories[, options])` returns a supplied label
as a `STRING`.

E.g., label each review in `reviews(id, body)`:

```sql
SELECT r.id,
       AI.CLASSIFY(r.body, ARRAY['positive', 'negative', 'mixed']) AS sentiment
FROM reviews r;
```

### Arguments

| Argument | Type | Meaning |
| --- | --- | --- |
| `input` | Text column or `PROMPT` | One document, or a prompt over a document pair. |
| `categories` | Array | At least two nonempty labels that differ when compared without case sensitivity. |
| `options` | Object | Optional settings below. |

Each label can have a description of at most 25 words.
E.g., use `ARRAY[{'label': 'refund', 'description': 'asks for money back'}, {'label': 'praise'}]`.
Quail also accepts `(label, description)` pairs in the array.

### Optional parameters

| Option | Default | Meaning |
| --- | --- | --- |
| `task_description` | Empty | Extra instructions. |
| `selectivity` | `0.2` | Fraction expected to pass a filter on the label. |
| `probabilities` | `false` | Add `<alias>_probabilities`, a map from labels to probabilities. |

Probabilities sum to 1. They are available for individual documents,
not joined classifications. Quail returns them only when the query
returns the classification's rows directly. It omits them when the label
appears only in `WHERE` or DataFusion runs SQL above the classification.

### Query examples

#### Filter by category

E.g., return negative or mixed reviews. Repeat the call in `WHERE`;
Quail classifies each review once:

```sql
SELECT r.id,
       AI.CLASSIFY(r.body, ARRAY['positive', 'negative', 'mixed']) AS sentiment
FROM reviews r
WHERE AI.CLASSIFY(r.body, ARRAY['positive', 'negative', 'mixed'])
      IN ('negative', 'mixed');
```

Use `=` to keep one label. A label outside the supplied array matches
no rows.

#### Classify joined rows

E.g., classify a review's opinion about each matching aspect:

```sql
SELECT r.id, a.aspect,
       AI.CLASSIFY(PROMPT('What is the opinion about the aspect? {0} {1}',
                          r.body, a.aspect),
                   ARRAY['positive', 'negative', 'mixed']) AS opinion
FROM reviews r
JOIN aspects a ON AI.IF(
    PROMPT('Does the review discuss this aspect? {0} {1}', r.body, a.aspect));
```

The optimized joined-classification operator requires one GPU. A query
that also uses `AI.SCORE` can run those calls in separate model regions.
See [Classification answers](/docs/user-guide/results#classification-answers)
to inspect labels that later filters remove.

## AI.EXTRACT

`AI.EXTRACT(input, questions)` copies answers from one document.
`input` is a text column. `questions` maps field names to question strings.
The answer is a struct with a nullable `STRING` field per question.
A field is null when the model finds no answer.

E.g., extract the end date and signer from `contracts(id, text)`:

```sql
SELECT c.id,
       AI.EXTRACT(c.text, {'end_date': 'When does the lease end?',
                           'signer': 'Who signed it?'}) AS lease
FROM contracts c;
```

### Answer positions

`AI.EXTRACT_SPAN` takes the same arguments as `AI.EXTRACT`.
It returns a struct with the same fields; each field contains `start`
and `end` character positions. `end` excludes the character at that
position, so Python's `text[start:end]` returns the answer.

E.g., return an answer and its span from the same extraction:

```sql
SELECT c.id,
       AI.EXTRACT(c.text, {'end_date': 'When does the lease end?'}) AS lease,
       AI.EXTRACT_SPAN(c.text, {'end_date': 'When does the lease end?'}) AS lease_span
FROM contracts c;
```

### Filter on answers

E.g., return leases whose extracted end date contains "2027":

```sql
SELECT c.id,
       AI.EXTRACT(c.text, {'end_date': 'When does the lease end?'}) AS lease
FROM contracts c
WHERE AI.EXTRACT(c.text, {'end_date': 'When does the lease end?'})['end_date']
      LIKE '%2027%';
```

Quail extracts each answer once. The filter excludes null answers.
Use `IS NULL` to keep documents with no answer.
Span fields support comparisons too.

### Limits

Use a [model](/docs/user-guide/models) that supports extraction.
Quail can reorder AI calls to reduce estimated work. Set
`order="as_written"` in `session.sql()` to preserve written order.

## AI.MAP

`AI.MAP(input, instruction[, max_tokens])` writes a `STRING` answer
for each document. `input` is a text column; `instruction` is a string
literal. `max_tokens` is a positive integer, with a default of 256.
An answer ends when the model finishes or reaches this limit.

E.g., summarize only negative reviews:

```sql
SELECT r.id,
       AI.MAP(r.body, 'Summarize the review in one sentence.') AS summary
FROM reviews r
WHERE AI.IF(PROMPT('Is this review negative? {0}', r.body));
```

### Use answers in the query

A map answer works as a text column in SQL.
E.g., return complaints that mention the ending:

```sql
SELECT r.id,
       AI.MAP(r.body, 'List what the review complains about.') AS complaints
FROM reviews r
WHERE AI.MAP(r.body, 'List what the review complains about.') ILIKE '%ending%';
```

Quail writes each answer once and reuses it for the filter and result.

## AI.SAE_FEATURES

`AI.SAE_FEATURES` returns sparse autoencoder (SAE) features of a prompt,
not generated text. Each feature has an integer ID and a strength.
Strengths are nonnegative activation values, not probabilities.

E.g., read features from `tickets(id, request)`:

```sql
SELECT t.id,
       AI.SAE_FEATURES(PROMPT('{0}\n\nWhat is the customer asking for?', t.request),
                       {'pooling': 'last'}) AS intent
FROM tickets t;
```

The answer is a list of `{'feature': ID, 'strength': value}` structs,
ordered from strongest to weakest. Feature IDs have no text labels.
Inspect documents with high strengths to interpret a feature.

### Arguments

| Argument | Meaning |
| --- | --- |
| `prompt` | `PROMPT` over one document column. |
| `options` | Object with `pooling` set to `'last'` or `'max'`. |

### Pooling

| Value | Features |
| --- | --- |
| `'last'` | Features of the prompt's last token; at most 100 with the supported SAE. The question follows the document. |
| `'max'` | Maximum strength of each feature over all prompt tokens. The list can contain thousands of features. |

### Unnest the features

Use DataFusion's `UNNEST` in `SELECT`, not `FROM`.
It returns one row per feature and repeats the other selected columns.
An empty list contributes no rows.

E.g., count requests per feature:

```sql
SELECT x.f['feature'] AS feature, COUNT(*) AS requests
FROM (
    SELECT t.id,
           UNNEST(AI.SAE_FEATURES(
               PROMPT('{0}\n\nWhat is the customer asking for?', t.request),
               {'pooling': 'last'})) AS f
    FROM tickets t
) x
GROUP BY x.f['feature']
ORDER BY requests DESC;
```

### Limits

Use `qwen3.5-2b-sae-bf16` in a separate session from other AI functions.
Unnest the list before testing feature IDs or strengths.
See [Find customer intents](/docs/demos/support-intents) for an application.

## Planning hints

`HINT(condition, {'selectivity': fraction})` estimates the fraction of
documents that pass a test of an AI answer. The default is `0.2`.
It changes planning, not which rows pass.

E.g., estimate that 40% of contracts have an extracted end date in 2027:

```sql
SELECT c.id
FROM contracts c
WHERE HINT(
    AI.EXTRACT(c.text, {'end_date': 'When does the lease end?'})['end_date']
        LIKE '%2027%',
    {'selectivity': 0.4});
```
