An AI function asks a [model](/docs/user-guide/models) about the text in
a row and returns the model's answer as a SQL value.

| Function | Description |
| --- | --- |
| [`PROMPT(template, value, ...)`](#prompttemplate-value-) | `PROMPT` builds the text the model reads. |
| [`AI.IF(prompt[, options])`](#aiifprompt-options) | `AI.IF` returns `TRUE` when the model answers yes to the prompt. |
| [`AI.SCORE(prompt[, options])`](#aiscoreprompt-options) | `AI.SCORE` returns a number from 0 to 1; a higher number is a stronger yes. |
| [`AI.CLASSIFY(input, categories[, options])`](#aiclassifyinput-categories-options) | `AI.CLASSIFY` returns the one label from `categories` the model chooses. |
| [`AI.EXTRACT(input, questions)`](#aiextractinput-questions) | `AI.EXTRACT` returns each question's answer as text copied from the document. |
| [`AI.EXTRACT_SPAN(input, questions)`](#aiextract_spaninput-questions) | `AI.EXTRACT_SPAN` returns the position of each `AI.EXTRACT` answer in the document. |
| [`AI.MAP(input, instruction[, max_tokens])`](#aimapinput-instruction-max_tokens) | `AI.MAP` returns the text the model writes for the document. |
| [`AI.SAE_FEATURES(prompt, options)`](#aisae_featuresprompt-options) | `AI.SAE_FEATURES` returns the model's strongest internal features for the prompt. |
| [`HINT(condition, options)`](#hintcondition-options) | `HINT` returns `condition` and tells Quail what fraction of rows pass. |

## Example tables

Every example on the page reads two tables, `reviews` and `aspects`.
A model can answer differently on another run, so each result shows
what one model returned.

`reviews`:

| id | body |
| --- | --- |
| 1 | The ending was perfect and the cast was great. |
| 2 | Too long, and the ending made no sense. |
| 3 | Great music, but I want my money back. |

`aspects`:

| id | aspect |
| --- | --- |
| 1 | ending |
| 2 | music |

The examples use the default Snowflake dialect. BigQuery syntax
(`dialect="bq"`) writes an options object such as
`{'selectivity': 0.3}` as `STRUCT(0.3 AS selectivity)`.

## Use AI answers in SQL

Use an AI function wherever SQL accepts the function's return type. A
relational operator filters, joins, groups, sorts, or limits rows.
DataFusion applies relational operators to the values returned by AI
functions.

- `SELECT` returns an AI answer as a result column. A projection is the
  list of expressions after `SELECT`.
- `WHERE` keeps rows based on an AI answer.
- `JOIN ... ON` keeps pairs of rows based on an AI answer.
- `GROUP BY` and aggregate functions summarize AI answers.
- `HAVING` filters groups based on an AI answer.
- `ORDER BY` sorts rows by an AI answer.

Each function entry lists the supported uses. [SQL with AI functions](./sql-functions)
shows how DataFusion operators affect AI calls and model work.

## Functions

### `PROMPT(template, value, ...)`

```sql
SELECT r.id
FROM reviews r
WHERE AI.IF(PROMPT('Does the review discuss the ending? {0}', r.body));
```

| | |
| --- | --- |
| **Description** | `PROMPT` builds the text the model reads: the template with each placeholder replaced by a value. `{0}` is the first value after the template, and `{1}` is the second. Every value needs a placeholder. |
| **Use in SQL** | Use `PROMPT` as the input to `AI.IF`, `AI.SCORE`, `AI.CLASSIFY`, or `AI.SAE_FEATURES`. `PROMPT` does not return a result column by itself. |
| **Result** | `(1)`, `(2)` |
| **Values** | Columns of one table form one document, and one column may appear twice. Columns of two tables form a pair; see [Joining](#joining). |

### `AI.IF(prompt[, options])`

```sql
SELECT r.id
FROM reviews r
WHERE AI.IF(PROMPT('Does the reviewer ask for a refund? {0}', r.body));
```

| | |
| --- | --- |
| **Description** | `AI.IF` returns `TRUE` when the model answers yes to the prompt, and `FALSE` when the model answers no. `WHERE AI.IF(...)` keeps the rows with a yes; `WHERE NOT AI.IF(...)` keeps the rows with a no. |
| **Use in SQL** | Use `AI.IF` in `SELECT`, `WHERE`, `JOIN ... ON`, `HAVING`, `CASE`, or any other Boolean expression. |
| **Result** | `(3)` |
| **Alias** | `AI_FILTER` |
| **Options** | `selectivity`, `anchor`; see [Options](#options). |

### `AI.SCORE(prompt[, options])`

```sql
SELECT r.id,
       AI.SCORE(PROMPT('Does the reviewer ask for a refund? {0}', r.body)) AS refund
FROM reviews r;
```

| | |
| --- | --- |
| **Description** | `AI.SCORE` returns a `FLOAT64` from 0 to 1. A higher score is a stronger yes. A score is not the probability of a correct answer, so choose a threshold from labeled examples. |
| **Use in SQL** | Use `AI.SCORE` in `SELECT`. Compare the score in `WHERE`, `JOIN ... ON`, or `HAVING`. Use the score in `ORDER BY` or an aggregate function. |
| **Result** | `(1, 0.02)`, `(2, 0.1)`, `(3, 0.94)` |
| **Alias** | `AI_SCORE` |
| **Options** | `selectivity`; see [Options](#options). |

### `AI.CLASSIFY(input, categories[, options])`

```sql
SELECT r.id,
       AI.CLASSIFY(r.body, ['positive', 'negative', 'mixed']) AS sentiment
FROM reviews r;
```

| | |
| --- | --- |
| **Description** | `AI.CLASSIFY` returns the one label from `categories` the model chooses, as a `STRING`. |
| **Use in SQL** | Use `AI.CLASSIFY` in `SELECT`. Compare the label in `WHERE`, `JOIN ... ON`, or `HAVING`. Use the label in `GROUP BY`, `ORDER BY`, or an aggregate function. |
| **Result** | `(1, 'positive')`, `(2, 'negative')`, `(3, 'mixed')` |
| **Alias** | `AI_CLASSIFY` |
| **input** | A text column, or a `PROMPT` over one document or a pair. |
| **categories** | A list of at least two labels. Two labels must differ by more than letter case. A label can carry a description of at most 25 words; give every label a description or none: `[{'label': 'refund', 'description': 'asks for money back'}, ...]`. |
| **Options** | `selectivity`, `task_description`, `probabilities`; see [Options](#options). |

### `AI.EXTRACT(input, questions)`

```sql
SELECT r.id,
       AI.EXTRACT(r.body, {'complaint': 'What does the reviewer complain about?'})
           AS answers
FROM reviews r;
```

| | |
| --- | --- |
| **Description** | `AI.EXTRACT` returns a struct with one `STRING` field per question. Each field holds text copied from the document. A field is `NULL` when the document has no answer. Read a field as `AI.EXTRACT(...)['complaint']`. |
| **Use in SQL** | Use the returned struct in `SELECT`. Read a field in `SELECT`, `WHERE`, `JOIN ... ON`, `GROUP BY`, `HAVING`, or `ORDER BY`. |
| **Result** | `(1, {complaint: NULL})`, `(2, {complaint: 'the ending made no sense'})`, `(3, {complaint: 'I want my money back'})` |
| **Alias** | `AI_EXTRACT` |
| **input** | A text column. |
| **questions** | An object from field names to questions. |

### `AI.EXTRACT_SPAN(input, questions)`

```sql
SELECT r.id,
       AI.EXTRACT_SPAN(r.body, {'complaint': 'What does the reviewer complain about?'})
           AS spans
FROM reviews r;
```

| | |
| --- | --- |
| **Description** | `AI.EXTRACT_SPAN` returns a struct with one field per question, as `AI.EXTRACT` does for the same arguments. Each field is a span: the `start` and `end` character positions of the answer in the document. `end` is one past the last character, so Python's `body[start:end]` is the answer. |
| **Use in SQL** | Use the returned struct in `SELECT`. Read a span or its `start` and `end` fields in `SELECT`, `WHERE`, `JOIN ... ON`, `GROUP BY`, `HAVING`, or `ORDER BY`. |
| **Result** | `(1, {complaint: NULL})`, `(2, {complaint: {start: 14, end: 38}})`, `(3, {complaint: {start: 17, end: 37}})` |
| **Alias** | `AI_EXTRACT_SPAN` |

### `AI.MAP(input, instruction[, max_tokens])`

```sql
SELECT r.id,
       AI.MAP(r.body, 'Summarize the review in one sentence.', 32) AS summary
FROM reviews r;
```

| | |
| --- | --- |
| **Description** | `AI.MAP` returns the `STRING` the model writes for the document. The text has no whitespace at its start or end. |
| **Use in SQL** | Use `AI.MAP` in `SELECT`. Compare the text in `WHERE`, `JOIN ... ON`, or `HAVING`. Use the text in `GROUP BY`, `ORDER BY`, or an aggregate function. |
| **Result** | `(1, 'Praises the ending and the cast.')`, `(2, 'Says the film is too long and the ending makes no sense.')`, `(3, 'Likes the music but wants a refund.')` |
| **Alias** | `AI_MAP` |
| **input** | A text column. |
| **instruction** | A string literal. |
| **max_tokens** | `max_tokens` limits the tokens in an answer. It is an integer from 1 to 32768, and its default is 256. |

### `AI.SAE_FEATURES(prompt, options)`

```sql
SELECT r.id,
       AI.SAE_FEATURES(PROMPT('{0} What does the reviewer want?', r.body),
                       {'pooling': 'last'}) AS features
FROM reviews r;
```

| | |
| --- | --- |
| **Description** | `AI.SAE_FEATURES` returns a list of `{feature, strength}` structs, strongest first. A sparse autoencoder (SAE), a second model reading the first model's internal state, computes the features. A feature is an integer ID with no text label. A strength is a nonnegative activation, not a probability. |
| **Use in SQL** | Use `AI.SAE_FEATURES` in `SELECT`. Use `UNNEST` to return one row per feature. Use list functions to measure or filter the returned list. |
| **Result** | `(1, [{feature: 18113, strength: 6.2}, {feature: 902, strength: 2.4}, ...])`, and so on for each row. |
| **Alias** | `AI_SAE_FEATURES` |
| **prompt** | A `PROMPT` over one document column. |
| **pooling** | `'last'` returns the features of the prompt's last token, at most 100. `'max'` returns each feature's largest strength over all tokens, often thousands of features. |
| **Model** | `AI.SAE_FEATURES` runs on `qwen3.5-2b-sae-bf16` only, and `qwen3.5-2b-sae-bf16` runs no other AI function. |

### `HINT(condition, options)`

```sql
SELECT r.id
FROM reviews r
WHERE HINT(AI.CLASSIFY(r.body, ['positive', 'negative', 'mixed']) = 'negative',
           {'selectivity': 0.3});
```

| | |
| --- | --- |
| **Description** | `HINT` returns the value of `condition`. The `selectivity` option gives the fraction of rows you expect to pass `condition`. Quail uses the fraction to order its work; the fraction does not change which rows pass. |
| **Use in SQL** | Wrap a Boolean condition in `WHERE`, `JOIN ... ON`, `HAVING`, `CASE`, or any other Boolean expression. |
| **Result** | `(2)` |
| **Options** | `HINT` takes `selectivity` only. |

## Options

Pass options as an object, such as `{'selectivity': 0.3}`.

| Option | Functions | Meaning |
| --- | --- | --- |
| `selectivity` | `AI.IF`, `AI.SCORE`, `AI.CLASSIFY`, `HINT` | `selectivity` is the fraction of rows or pairs you expect to pass the test. Its default is 0.2. It changes speed, not answers. |
| `anchor` | `AI.IF` in a join | `anchor` is the alias of the table whose rows the model reads first. Quail chooses a table when you omit `anchor`. |
| `task_description` | `AI.CLASSIFY` | `task_description` gives the model extra instructions. |
| `probabilities` | `AI.CLASSIFY` | `true` adds a column `<alias>_probabilities`, a map from each label to its probability. Quail adds the column only when the query returns the label directly. A query whose `WHERE` alone reads the label, or whose SQL groups the label, gets no such column. |

## Joining

`AI.IF` in `ON` asks the model about each pair of rows. The `PROMPT`
reads one column from each table.

```sql
SELECT r.id, a.aspect
FROM reviews r
JOIN aspects a
  ON AI.IF(PROMPT('Does the review discuss the aspect? {0} {1}', r.body, a.aspect));
```

Result: `(1, 'ending')`, `(2, 'ending')`, `(3, 'music')`.

- Add an equality, such as `ON r.id = a.id AND AI.IF(...)`, and the
  model reads only the pairs with equal values.
- `AI.SCORE(...) >= 0.8` in `ON` keeps the pairs with a score of at
  least 0.8.
- `AI.CLASSIFY` over a `PROMPT` of two tables labels each pair.
- `LEFT`, `RIGHT`, and `FULL` joins keep their unmatched rows as usual.

## EXISTS and NOT EXISTS

`AI.IF` in a subquery keeps the rows with at least one match (`EXISTS`)
or with no match (`NOT EXISTS`).

```sql
SELECT r.id
FROM reviews r
WHERE NOT EXISTS (
    SELECT 1 FROM aspects a
    WHERE AI.IF(PROMPT('Does the review praise the aspect? {0} {1}',
                       r.body, a.aspect)));
```

Result: `(2)`. `EXISTS` returns `(1)`, `(3)`.

## Filter by category

`WHERE` cannot read a `SELECT` alias. Repeat the call in `WHERE`; the
model answers the two calls once.

```sql
SELECT r.id,
       AI.CLASSIFY(r.body, ['positive', 'negative', 'mixed']) AS sentiment
FROM reviews r
WHERE AI.CLASSIFY(r.body, ['positive', 'negative', 'mixed']) IN ('negative', 'mixed');
```

Result: `(2, 'negative')`, `(3, 'mixed')`.

- Write the repeated call exactly as the first call. Quail raises an
  error for two calls differing only in case, whitespace, or
  punctuation.
- Quail raises an error for a test naming a label outside `categories`.

## Filter on answers

Every answer works in SQL like a column of its type.

```sql
SELECT r.id
FROM reviews r
WHERE AI.EXTRACT(r.body, {'complaint': 'What does the reviewer complain about?'})['complaint']
      LIKE '%ending%';
```

Result: `(2)`.

- Compare a score with `<`, `<=`, `>`, or `>=` and a number from 0 to 1.
- Test map text with `=`, `LIKE`, or `ILIKE`.
- A comparison drops `NULL` answers. Use `IS NULL` to keep them.
- `LIMIT` stops the model once enough rows pass.

## NULL documents

An AI function returns `NULL` for a `NULL` document and does not ask
the model. Suppose `reviews` also had a row `(4, NULL)`:

```sql
SELECT r.id, AI.CLASSIFY(r.body, ['positive', 'negative', 'mixed']) AS sentiment
FROM reviews r;
```

Result: `(1, 'positive')`, `(2, 'negative')`, `(3, 'mixed')`, `(4, NULL)`.

- `WHERE AI.IF(...)` and `WHERE NOT AI.IF(...)` both drop row 4.
- `PROMPT` over several columns is `NULL` when one column is `NULL`.
- A pair with a `NULL` document matches nothing in a join, and its
  `AI.SCORE` is `NULL`.
- `NOT EXISTS` still asks the model about a row with a `NULL` document,
  and the model reads empty text for the document.
