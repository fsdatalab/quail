during query execution. You can filter rows, join tables, score documents,
assign labels, and extract answers using natural language instructions.

## Write a query

For example, suppose you registered a `reviews` table with columns `id`
and `body`. This query returns IDs of reviews that discuss the movie's
ending:

```sql
SELECT r.id
FROM reviews r
WHERE AI.IF(PROMPT('Does this review discuss the ending of the movie?\n\n{0}', r.body))
```

The model reads each review and returns TRUE or FALSE. Quail keeps
the rows where the answer is TRUE.

Quail supports Snowflake and BigQuery syntax:

```python
session.sql(text, dialect="snowflake")  # AI_FILTER syntax
session.sql(text, dialect="bq")         # AI.IF syntax
```

The query above uses the BigQuery dialect (`dialect="bq"`).

## SQL around the model's work

Quail plans the part of a query that calls the model, together with
the operators around it that Quail runs itself, as one model region.
DataFusion runs any SQL outside the regions. For example, this query
unions the reviews about the ending with every aspect's id, and sorts
the result:

```python
query = session.sql("""
    SELECT r.id FROM reviews r
    WHERE AI.IF(PROMPT('Does this review discuss the ending?\n\n{0}', r.body))
    UNION ALL SELECT a.id FROM aspects a
    ORDER BY id
""", dialect="bq")
query.collect()
```

The filter is one model region; DataFusion runs the union and the sort.
`session.sql` returns a `DataFusionQuery` for such a query. It has the
methods of a `Query`. `plan()` gives each region's physical plan, and
`explain()` gives DataFusion's plan, then each region's.

A query that is one model region, with no SQL around it, is a `Query`.
DataFusion runs it too, through its `ModelRegionExec` operator, and the
region's result keeps the plan and metrics that `explain(analyze=True)`
reads.
