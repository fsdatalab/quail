AI-SQL extends standard SQL with functions that call a language model
during query execution. You can filter rows, join tables, score documents,
assign labels, and extract answers using natural language instructions.

## Write a query

For example, suppose you registered a `reviews` table with columns `id`
and `body`. This query returns IDs of reviews that discuss the movie's
ending:

```sql
SELECT r.id
FROM reviews r
WHERE AI.IF(PROMPT('Does this review discuss the ending of the movie?\n\n{0}', r.body))
```

The model reads each review and returns TRUE or FALSE. Quail keeps
the rows where the answer is TRUE.

Quail supports Snowflake and BigQuery syntax:

```python
session.sql(text, dialect="snowflake")  # AI_FILTER syntax
session.sql(text, dialect="bq")         # AI.IF syntax
```

The query above uses the BigQuery dialect (`dialect="bq"`).

## SQL around the model's work

Quail runs the operators that call the model, and the operators that
change how much the model reads: the filters and joins below a model
call, and a LIMIT or DISTINCT that can stop the model early. Together
they are one model region. DataFusion runs the rest of the query on
the region's rows: GROUP BY, HAVING, windows, ORDER BY without a LIMIT,
and anything else.

For example, this query classifies the reviews that pass a filter and
counts them by label:

```python
query = session.sql("""
    SELECT AI.CLASSIFY(PROMPT('Tone? {0}', r.body), ['good', 'bad']) AS tone,
           COUNT(*) AS n
    FROM reviews r
    WHERE r.stars > 3
    GROUP BY tone
    ORDER BY n DESC
""")
query.collect()
```

The region scans `reviews` with `r.stars > 3` and classifies each
review. DataFusion groups the labels, counts them, and sorts the
groups. `query.explain()` shows DataFusion's plan, with the region as
one `ModelRegion` node, and then the region's plan. `query.plan()` is
the region's physical plan.

A query with two model regions, such as a UNION of two AI filters, is
a `DataFusionQuery`. It has the methods of a `Query`. `plan()` gives
each region's physical plan, and `explain()` gives DataFusion's plan,
then each region's.

A CTE or FROM subquery whose body groups or windows rows that a later
model call reads is computed by DataFusion between two model regions:
the second region reads its rows as a table named by the CTE.
