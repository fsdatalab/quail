---
title: SQL functions
---

DataFusion runs SQL around Quail's model regions. This includes queries
without AI calls. Use DataFusion's
[SQL reference](https://datafusion.apache.org/user-guide/sql/index.html)
for ordinary SQL syntax; this page covers its use with AI functions.

Examples use `dialect="bq"` unless stated otherwise.
Register the input tables before running them.

## SQL clauses

### SELECT, FROM, JOIN, LIMIT

| Clause | Use |
| --- | --- |
| `SELECT` | Return columns or expressions. Use `AS` to give computed columns a name. |
| `FROM` | Read a registered table, CTE, or subquery. |
| `JOIN` | Combine rows; see [Joins](#joins). |
| `LIMIT` | Return at most this many rows. `LIMIT 0` returns no rows without running the model. |

### WITH

Use a common table expression (CTE) when an AI call reads another call's
answer. E.g., extract a contract clause, then score that clause rather
than the full contract. The `contracts` table has `id` and `text` columns:

```sql
WITH clauses AS (
    SELECT c.id,
           AI.EXTRACT(c.text, {'terms': 'What is the termination clause?'}) AS clause
    FROM contracts c
)
SELECT x.id,
       AI.SCORE(PROMPT('Can the tenant terminate early? {0}', x.clause.terms)) AS score
FROM clauses x;
```

A `FROM` subquery serves the same purpose. Use a CTE or subquery when
an AI call must read a value from `GROUP BY` or a window calculation.

### Joins

Use `AI.IF` in `ON` for a [join](/docs/user-guide/sql/ai-functions#joining).
Add column comparisons to restrict the pairs that the model reads.
`LEFT`, `RIGHT`, and `FULL` joins can also use AI predicates in `ON`.
Quail finds matching pairs with an inner AI join, then DataFusion restores
the unmatched rows from the original inputs. Duplicate rows remain separate,
and null join keys follow the SQL predicate's null semantics.
Not every join needs an AI call.

### EXISTS and NOT EXISTS

Use `EXISTS` to keep rows with at least one match.
Use `NOT EXISTS` to keep rows with none.
See [AI examples](/docs/user-guide/sql/ai-functions#exists-and-not-exists).

### WHERE and ON

`WHERE` and `ON` accept DataFusion expressions. Filters that read one
input table run before AI calls that read those rows.

**`WHERE` cannot read a `SELECT` alias.** Repeat the AI call to test its
answer; Quail computes the repeated answer once.
See [Filter by category](/docs/user-guide/sql/ai-functions#filter-by-category)
and [Filter on answers](/docs/user-guide/sql/ai-functions#filter-on-answers).

- Comparisons exclude null values. Use `IS NULL` to keep them.
- Combine ordinary conditions with `AND`, `OR`, or `NOT`.
- AI answers can appear inside `OR`, `NOT`, comparisons, and other SQL
  expressions. The [fallback](#unsupported-sql) may evaluate answers before
  applying the condition; do not assume SQL short-circuiting avoids model work.

### ORDER BY

Only `ORDER BY` specifies result order. Without it, rows can appear in
any order, including when the query has `LIMIT`.
Use `ASC` or `DESC` for direction and `NULLS FIRST` or `NULLS LAST` for
explicit null placement.

E.g., return the ten highest refund scores from `documents(id, body)`.
Use the ID to order rows with equal scores:

```sql
SELECT d.id,
       AI.SCORE(PROMPT('Does the customer request a refund? {0}', d.body))
           AS refund_score
FROM documents d
ORDER BY refund_score DESC NULLS LAST, d.id ASC
LIMIT 10;
```

### SELECT DISTINCT

`SELECT DISTINCT` removes duplicate result rows. A sorting expression
must appear in the selected columns when the query uses `DISTINCT`.

### OFFSET

`OFFSET n` skips `n` rows before applying `LIMIT`.
Use `ORDER BY` if you need to control which rows it skips.
Sorting and aggregation can require more model work than the final
row limit suggests. Inspect `query.explain()` rather than assuming that
`LIMIT` limits AI calls.

## Column expressions

Use a dotted path for a struct field, such as `p.details.body`.
DataFusion's
[scalar functions](https://datafusion.apache.org/user-guide/sql/scalar_functions.html)
work in expressions, including document arguments to `PROMPT`.

E.g., a `pages` table has `id` and a `details` struct with a `body` field:

```sql
SELECT p.id, LENGTH(p.details.body) AS body_length
FROM pages p
WHERE AI.IF(PROMPT('Does the page discuss shipping? {0}', p.details.body))
ORDER BY body_length;
```

Functions can nest. E.g., `LOWER(TRIM(p.details.body))` removes surrounding
spaces and converts the text to lowercase.

### Scalar functions

DataFusion evaluates scalar expressions. A test of an AI answer runs
after that answer is available.

E.g., restrict reviews to ratings within one star of 4:

```sql
SELECT r.id, ABS(r.stars - 4) AS gap
FROM reviews r
WHERE ABS(r.stars - 4) <= 1
  AND AI.IF(PROMPT('Is the review positive? {0}', r.body));
```

## Text conditions

| Expression | Meaning |
| --- | --- |
| `value LIKE pattern` | Case-sensitive match; `%` matches any text and `_` matches one character. |
| `value ILIKE pattern` | The same match without case sensitivity. |
| `REGEXP_CONTAINS(value, pattern)` in BigQuery | Regular expression match anywhere in the value. |
| `REGEXP_LIKE(value, pattern)` in BigQuery | Regular expression match anywhere in the value. |
| `REGEXP_LIKE(value, pattern)` in Snowflake | Regular expression match against the whole value. |
| `RLIKE(value, pattern)` in Snowflake | Alias for `REGEXP_LIKE`. |

E.g., for `r.body = 'Great Film'`, Snowflake's
`REGEXP_LIKE(r.body, 'Film')` is false;
`REGEXP_LIKE(r.body, '.*Film.*')` is true.

Use `RLIKE(value, pattern)`, not the removed `value RLIKE pattern`
or `value REGEXP pattern` operators.
Text conditions also work on
[extracted answers](/docs/user-guide/sql/ai-functions#filter-on-answers).

## GROUP BY and HAVING

DataFusion groups the rows that model regions return.
Use `HAVING` to filter the groups.

E.g., count reviews by sentiment and keep labels with more than ten
reviews. The `reviews` table has review text in `body`:

```sql
SELECT AI.CLASSIFY(PROMPT('What is the sentiment? {0}', r.body),
                   ['positive', 'negative', 'mixed']) AS sentiment,
       COUNT(*) AS review_count
FROM reviews r
GROUP BY sentiment
HAVING COUNT(*) > 10
ORDER BY review_count DESC;
```

### Aggregate functions

Use DataFusion's
[aggregate functions](https://datafusion.apache.org/user-guide/sql/aggregate_functions.html)
on stored columns or AI answers. An aggregate can read an AI call
directly. Without `GROUP BY`, it reads all rows that pass `WHERE`.

## Window functions

DataFusion computes windows over rows that model regions return.
A window adds a value without combining its input rows into one row.

E.g., the `steps` table has text and a unique `step_index` within each
`run_id`. Classify each step and return the preceding step's label:

```sql
WITH classified AS (
    SELECT s.id, s.run_id, s.step_index,
           AI.CLASSIFY(PROMPT('What does the agent do here? {0}', s.text),
                       ['plan', 'act', 'reflect']) AS kind
    FROM steps s
)
SELECT c.id, c.kind,
       LAG(c.kind) OVER (
           PARTITION BY c.run_id ORDER BY c.step_index) AS previous
FROM classified c
ORDER BY c.run_id, c.step_index;
```

The first step in each run has a null `previous` value.
The window reads existing labels; it does not call the model again.

### Supported functions

Use DataFusion's
[window functions](https://datafusion.apache.org/user-guide/sql/window_functions.html)
and window frames. `ORDER BY` inside `OVER` controls the calculation;
the query's outer `ORDER BY` controls returned row order.

### Window limits

An AI call can read a window expression through the fallback: DataFusion
computes the window result before the model reads it. To refer to the window
result by a column name, put it in a CTE or `FROM` subquery.

## Unsupported SQL

An expression need not fit Quail's optimized model-region shapes to use
an AI answer. Quail first tries its existing optimized plan. If that shape
is unsupported, it computes each AI call as a named column over a
DataFusion-computed region input, then runs the original SQL operator over
those columns in DataFusion. The input can itself be a join, aggregate,
window calculation, CTE, literal row, or other DataFusion relation; it need
not be a base table. `VALUES` rows with AI calls use the same projection
fallback, preserving duplicate rows.

This fallback covers SQL combinations of AI answers rather than adding a
separate model operator for every expression shape. It preserves the SQL
operator's result semantics, but can require more model calls and
materialization than an optimized region. Outer joins with AI in `ON`
add a matching-pairs step to restore unmatched rows correctly.

Fallback does not make invalid SQL or invalid AI arguments valid.
DataFusion still checks the SQL; Quail still checks prompt arguments,
function options, and model capabilities. See
[AI functions](/docs/user-guide/sql/ai-functions) for function-specific
limits and [Refusals](/docs/user-guide/results#refusals) for configuration
errors.
