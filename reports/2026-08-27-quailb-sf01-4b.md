# QuailB SF 0.1 with Qwen3 4B fp8

## Setup

- The benchmark has the 30 current QuailB queries at scale factor 0.1.
- Every engine uses Qwen3 4B fp8 on one H100!.
- Query time excludes model startup.
- GPU cost uses $3.9492 per H100! hour.
- Quail uses pipelining, token-based admission, and KV rewind.
- Stock vLLM submits filters in stage major waves.
- Pipelined vLLM submits the next filter as soon as each document passes its
  current filter.
- Both vLLM configurations use the same full cross product join code.
- Each query family ran in a separate Modal container. Each container ran all
  Quail queries, then all stock vLLM queries, then all pipelined vLLM queries.
- Quail and both vLLM configurations used the same H100! within each query
  family.
- Quail cleared KV before each query. vLLM reset its prefix cache before each
  query and configuration.
- Quail used a 0.95 GPU pool fraction. Both vLLM configurations used 0.91 GPU
  memory utilization and had space for 479,248 KV tokens.
- All three measured systems used the same document first filter and join
  prompts.
- IMDB, BioDEX, and FEVER use ground truth collection
  `gt_02ffa2a5720006e8236aa993760e9e29`.
- LePaRD uses workload ground truth `gtw_fcbfa6bffb667f714069baf46f6f3810`
  on corpus `c_3bd14ed0758287cba9d88fb68de8b7b8`.
- LePaRD samples 500 known citation pairs at scale factor 0.1. It then
  deduplicates the document columns into 500 citation contexts and 433
  citation passages.
- The SoL estimate used ground truth survivor counts. It estimates the required
  model work and is separate from the production planner.

## Prediction

Deduplicating the LePaRD passage table should remove most exact duplicate
prompts. Stock vLLM should lose the earlier 96.7% prompt cache rate. Quail
should compare more favorably because all three systems must process the
distinct passage documents in the corrected join.

## Result

All 30 queries finished for all three measured systems. The run repeated only
the eight LePaRD queries. The other 22 query measurements are unchanged.

- Quail took 1,256.39 seconds in total. Stock vLLM took 3,968.27 seconds, and
  pipelined vLLM took 3,707.57 seconds.
- Quail was 3.16 times faster than stock vLLM and 2.95 times faster than
  pipelined vLLM by total query time.
- Quail had the lowest measured time on 28 of 30 queries. Pipelined vLLM had
  the lowest time on 2 queries. Stock vLLM had no query with the lowest time.
- Quail processed 244.7 documents per second across filter only queries,
  compared with 120.4 for stock vLLM and 198.3 for pipelined vLLM.
- Quail processed 3,633.3 document pairs per second across join only queries,
  compared with 864.4 for stock vLLM and 908.9 for pipelined vLLM.
- Weighted answer accuracy was 70.06% for Quail and 69.29% for both vLLM
  configurations.
- Quail was slower than stock vLLM only on IMDB-3.

The LePaRD prediction was confirmed. Across the eight corrected queries, Quail
took 341.89 seconds, stock vLLM took 455.01 seconds, and pipelined vLLM took
444.18 seconds. Quail was 1.33 times faster than stock vLLM and 1.30 times
faster than pipelined vLLM. The stock vLLM prompt cache rate fell from 96.7% on
the incorrect LEP-2 relation to 77.8% on the corrected LEP-2 relation. Across
all eight corrected queries, stock vLLM's prompt cache rate was 75.5%.

The corrected LePaRD SoL values are exactly the same as the earlier revised
LePaRD SoL values. The prior SoL calculation already used 500 citation contexts
and 433 citation passages. Its eight 4B estimates still sum to 64.44 seconds.

Pipelined vLLM was 1.65 times faster than stock vLLM on filter only throughput.
The two vLLM configurations were close on join only throughput because they use
the same join code.

The earlier LePaRD measurements are not comparable because they used a 200-row
self join with only five distinct passage values. The corrected relation has
216,500 pairs and 433 distinct passage values.
