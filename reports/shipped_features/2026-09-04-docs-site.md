# Documentation site

Quail now has a documentation site under `docs/`. It is a Fumadocs site
on Next.js, and the pages are MDX files under `docs/content/docs/`.

The site has four parts, modeled on the DataFusion documentation:

- A user guide: installation, a quickstart, the SQL reference, the
  Python builder API, data sources, configuration, results and explain,
  running on Modal, and running QUAIL-B.
- An architecture section: the query path, logical plans, physical
  plans, the Quail backend, the request backends, and the compute
  worker.
- An extending section: the extension registry, table providers,
  logical nodes and rules, physical nodes and planners, model backends,
  in-process execution, execution observers, and adding a model. The code examples come from the test suite.
- A contributing section: repository layout and checks, experiment
  rules, reports and plots, and the writing and naming rules.

The quickstart, results, SQL, and builder pages use real data: eight
reviews from the pinned `stanfordnlp/imdb` revision QUAIL-B uses and
the benchmark's own predicates. Every printed output on those pages
comes from one run of `docs/examples/imdb_queries_modal.py` on an H100 through
Modal (function calls `fc-01M1NGA090GPB4Y80XPG2P6H9G` and
`fc-01M1NGBWM5Q78NEHG251JZ58D6`, run records under `/results/runs/`).
That run also confirmed the engine layering changes on a GPU for the
one-GPU Quail path: the filter took 1.3 s after a 19.25 s cold load,
and the join reused the filter's KV for all four surviving reviews.

The home page positions Quail as a query engine for AI functions in
SQL, next to the Snowflake Cortex and BigQuery function families, and
says which operators are supported and which are planned.

Diagrams render with a small Mermaid client component. The site also
serves `llms.txt` and per page Markdown, which Fumadocs generates.

To run it:

```bash
cd docs
pnpm install
pnpm dev
```

`pnpm build` prerenders all 29 pages. The build is not part of CI.
