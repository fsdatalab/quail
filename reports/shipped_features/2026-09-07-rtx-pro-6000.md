# RTX PRO 6000 Blackwell Server Edition

Quail now accepts `EngineConfig(device="rtx-pro-6000-blackwell-server")`.
This is the GPU in Nebius's `gpu-rtx6000` platform. The device name distinguishes
it from the older RTX 6000 Ada and the Blackwell workstation variants.

The per-GPU specification uses 96 GB of GDDR7 memory and 1,597 GB/s of memory
bandwidth. The estimated dense tensor rates are 1,000 TFLOPS for FP8 and
500 TFLOPS for BF16. These divide NVIDIA's rounded FP8 and BF16 tensor rates
by two, assuming the server page lists sparse rates. That page does not
explicitly label sparsity. NVIDIA's RTX PRO Blackwell architecture paper,
Table 4, lists 1,007.6 dense FP8 and 503.8 dense BF16 TFLOPS for the
Workstation Edition, with sparse rates exactly twice those values.
This supports the conversion but does not establish exact dense rates for
the Server Edition. The code values remain approximate planning assumptions,
not directly published server dense specifications or measurements.
The planner uses them for KV capacity, admission, and computation costs.

Quail accepts 1, 2, 4, or 8 GPUs on one host, with one model copy per GPU.
The vLLM and SGLang request backends accept one GPU. Both Qwen3 FP8 models
remain available. H100 remains the default device.

The Quail executor selects FlashAttention-2 for CUDA capability 12.0 and
keeps FlashAttention-3 for H100's capability 9.0. The pinned vLLM 0.26.0
already supports DeepGEMM on capability 12.0. Its FlashAttention-2 accepts
the existing 16-token KV pages and returns the attention state in the shape
the merge kernel expects.

A normal session runs on the RTX host. The supplied Modal examples request
H100s through their function decorators.

The local smoke and IMDB demos accept `--device` and `--gpus`. The IMDB
demo defaults to Modal's rate for the selected GPU and accepts
`--gpu-usd-per-hour` for another price. It reports query cost separately from
startup cost.

CPU tests cover representative plans for both models, request backend
limits, attention dispatch, and rejecting RTX requests on the H100 Modal
provider. GPU execution and performance have not been tested on RTX hardware.
A filter and a join on the RTX host are needed to validate the kernels and
model loading together.
